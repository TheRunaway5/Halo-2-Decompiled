# Source pickup admission and live player carry limits

The live pickup adapter now retains the complete authored weapon flags at
`weap+12C` and applies original TU1.1 `152080` player inventory restrictions.
The fixed two-occupied-slot rule has been removed. The source rule excludes
items carrying flag4, discounts an equipped/requested secondary item when the
target is dual-compatible, respects flag3 on current hands, and rejects a
parented player's carry permissions. It distinguishes carrying another item
from replacing an equipped item.

This is the player restriction stage of admission. The live adapter's candidate
permissions remain native inputs. They are **not** represented as the output of
original `CEC00`. Complete live inventory/action/physics parity is unfinished.

`check_player_inventory_admission_versions.py` independently locates and
compares the complete 294-instruction player restriction at retail `1509E0`,
TU1.1 `152080` and TU1.5 `153460`. Every instruction and branch is byte-identical
after only the three actual players/object/tag global relocations. The common
normalized-body SHA256 is
`3892321340481f91abc9fb7d46b9281b46f29749a942fcac1b6549eeeb727da8`.
This establishes this live restriction across the three executable versions;
the larger retained-memory admission API remains explicitly TU1.1.

## Complete compiled source owners

`unit_pickup_runtime.cpp`, generated by
`generate_unit_pickup_runtime_1_1.py`, contains 26 complete bodies and 2,144
original instructions. These include `CEAF0`/`111490` capability, `CEC00`
four-byte admission, `152080` player restrictions, `EA660` type20 requests,
`CE510` pickup-mode dispatch, slot/sequence mutation, weapon selection, action
request/interrupt dispatch, and `1058F0` reserve/loaded ammunition transfer and
heat ordering. This retained-memory API is separate from the typed live Match.
It consumes actual caller-owned banks and full register/stack/FP state.

The executable authority is unchanged Map Pack TU1.1
`assets/multiplayer-map-pack/demos/update/Updates/default.xbe.03`, SHA256
`aaea4c9c58ac02cf5f9cc97a16d688318c59b652e92301078e2547a2a5ea5377`.
Generation decodes the authenticated source once. Production executes static
native arithmetic, calls and branches. It contains no opcode decoder, original
binary execution, captured-output table or default successful lower callback.
Missing reached owners throw with the retained ABI preserved.

## Remaining integration

The live Match still requires original graph-manager and extension ownership,
transition/saved-pose production, third-person firing/reload composition,
complete request/admission/carry/drop routing, and original physical-world
construction and scheduling. Native same-definition ammunition pickup remains
an adapter; the compiled `1058F0` owner is not yet its live state producer.

The separately recovered [Havok world graph](PHYSICS_WORLD_EVENT_ABI_RUNTIME_PORT_20261011.md)
now completes one retained original world call, but has not replaced
`Simulation::move_unit`. Full live motions,
constraints, contacts, controllers, ragdolls, dropped-item dynamics and Xbox
CPU-estimate equivalence remain open. The existing first-person/throw paths and
passing native probes do not establish matched original rendered sequences.
