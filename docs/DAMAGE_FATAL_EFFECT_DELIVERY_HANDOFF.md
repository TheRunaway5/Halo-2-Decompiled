### Source pool state

[`16D070`](../analysis/damage-shields-goal-20261011/live-fatal-cleanup/effect-research/paired/instructions/0016d070-old.asm), [`16D220`](../analysis/damage-shields-goal-20261011/live-fatal-cleanup/effect-research/paired/instructions/0016d220-old.asm) and [`16D2C0`](../analysis/damage-shields-goal-20261011/live-fatal-cleanup/effect-research/paired/instructions/0016d2c0-old.asm) establish and allocate the original records:

| Header offset | Source field |
|---|---|
| `00..1F` | Name |
| `20`, `24` | Capacity DWORD, stride DWORD |
| `28`, `29`, `2A` | Alignment BYTE, active BYTE, flags BYTE |
| `2C`, `30` | Signature `64407440`, allocator identity |
| `34`, `38`, `3C` | Search index, high-water index, live count |
| `40`, `44`, `48` | Next-salt WORD, records pointer, bitmap pointer |

Records begin at aligned storage `+4C`. Reset derives salt from the first two name bytes OR `8000`, resets counters/record salts/bitmap, and uses `BABA` fill only with flag bit3; constructor flag4 does not select it. Allocation scans the bitmap, updates counters, zeroes a whole record and assigns the real salt.

Flight records are 12 bytes: salt `+0`, completion BYTE `+2`, priority BYTE `+3`, job handle `+4`, header pointer `+8`. Pending records are 8 bytes: salt `+0`, header pointer `+4`. Flight records/bitmap are at allocation `+4C/+184C`; pending at `+4C/+B3C`; embedded physical records/bitmap at outer `+BC/+30BC`. Physical entries are 24 bytes; `13EAE0/13EFA0` use page count `+4`, first page `+8`, links `+C/+10`, and last-use clock `+14`. Pool capacity 512 is separate from the stage-selected page capacity.
