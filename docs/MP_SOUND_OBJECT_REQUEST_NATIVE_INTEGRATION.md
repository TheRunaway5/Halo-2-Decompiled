# Source sound-object request owner

The new native owner implements the complete direct **18DDE0** request builder from retained source object memory. It matches the original three authored first-person ready/reload/empty-reload requests, direct owner/marker controls, original invalid-owner rejection and actual parent-chain audibility. It does not initialize object records or derive a weapon node from player position, first-person arms, visual idle poses or an identity matrix. Submission **21F220**, scheduler admission, listeners, voice lifetime and platform playback remain separate owners. [Native interface](../include/halo2/sound_object_request.hpp), [implementation](../src/sound_object_request.cpp), [original execution](../analysis/multiplayer/integration/sound-object-request-native/measured-canonical/report.json).

## Retained input contract

`SoundObjectRequestMemory.read(address,extent)` resolves actual source32-bit address words to caller-owned stable storage. Its four roots are the source object pool, physics pool, sound system and current render BSP. No pointer, initialized flag or field is assigned by this module. The caller must retain source-owned pool/header/body allocations and run actual pose/location/physics producers before the event phase. A host bounds failure or missing provider throws; it never becomes an original AL0 or AL1. [Interface](../include/halo2/sound_object_request.hpp).

BBCB0 requires owner notNONE, low16 index below signed pool+38 high-water, nonzero signed header salt matching the signed high16 datum, and the literal body pointer. Its all-ones mask admits all header types. Other object helpers use the original12-byte low16-indexed headers at pool+44. BABD0 rejects header+2 bit10h or body+4 bit0 anywhere in the actual parent chain. BB1F0 follows parent+14 to the root and copies root+28/+2C, including historical registration fields; initial clusterFFFF rejects before any request store. [Original validity](../analysis/multiplayer/integration/sound-object-request-native/u5/instructions/000bbcb0-old.asm), [parent rejection](../analysis/multiplayer/integration/sound-object-request-native/u5/instructions/000babd0-old.asm), [location owner](../analysis/multiplayer/integration/sound-object-request-native/u5/instructions/000bb1f0-old.asm).

B9AC0 resolves **body + signextend(word+116) + signed_node×34h**. DDE0 takes the marker's unsigned first byte; FF maps to node0, other values are used directly. It does not look up the parent hand or infer a model node. The actual52-byte matrix contains scale, basis and translation. 143CE0 skips scale only when equal to original one; otherwise each point component is separately multiplied by scale. Rows use `((basisZ*z + basisY*y) + basisX*x) + translation`, with individually rounded SSE operations. Forward uses that same row order without scale or translation. [Node owner](../analysis/multiplayer/integration/sound-object-request-native/u5/instructions/000b9ac0-old.asm), [point instructions](../analysis/multiplayer/integration/sound-object-request-native/u5/instructions/00143ce0-old.asm), [DDE0 forward arithmetic](../analysis/multiplayer/integration/sound-object-request-native/u5/instructions/0018dde0-old.asm).

BB0C0 first follows the owner parent chain. PhysicalNONE, negative/out-of-range selected physical record index falls back to root+88 linear velocity. An admitted physical record uses object+C1 bit0 and physical motion+40 status for the actual immutable-vector branch; otherwise 1D43C0 copies its source motion data+40 vector. The native provider must resolve original pool+44, strideA0 physical records, record+70 motion bank, stride60 entries+40 pointers and actual data+3C pointer. No Havok result or successful motion record is supplied. [Velocity body](../analysis/multiplayer/integration/sound-object-request-native/u5/instructions/000bb0c0-old.asm), [motion copy](../analysis/multiplayer/integration/sound-object-request-native/u5/instructions/001d43c0-old.asm).

For unit/vehicle types, 11CEB0 follows signed body+12A manager offset, requires manager+68 and+0 nonNONE and word+6 nonFFFF, and tests activity+7C exactly `0E0000C2`. Only that positive branch calls the required full11D4A0/14B9D0 point query. ## Constants and numerical limits

`SoundObjectRequestConstants` field order is one, minus-one, Z scale, X/Y scale (four literal uint32 words), then12 raw vector bytes. Original addresses are465030/46503C/465298/46529C;1.5 addresses46A0D0/46A0DC/46A338/46A33C. BB0C0 dereferences46FC44→447144;1.5 dereferences474D04→44ABEC. Both vectors have identical original12 bytes, also the same target bytes as the separately proved FP position constant. OriginalData imports these fields optionally for1.1/1.5; Base has no promoted provider. [Exact scalar/vector evidence](../analysis/multiplayer/integration/sound-object-request-native/u5/providers.json).

18A800 clamps each component using the source comparison branches, subtracts the original lower bound, multiplies by its original scale, spills binary32 then FISTP. Native conversion retains the caller's explicit x87 RC bits, tie-even nearest and invalid80000000 result. The source packs `(((Z<<11)|Y)<<11)|X`.512 standalone controls include signed zero, ±1/out-of-range values, neighboring boundaries, infinities, NaNs/subnormals and declared bit patterns. The measured source control word is027F. No original object matrix is replaced by those stimuli. x87 status/exception flags and physical Xbox reciprocal seeds are not emulated here; all matrices in owning cases are actual observed original current-node banks. ## Evidence and integration limit

The suite has15 original requests,12 accepted and3 genuine invalid-owner rejections; all120 ordered stores and complete48-byte results match the native owner. Three authored ready/reload/empty-reload schedules reproduce the prior immutable original outputs. Other owner/marker controls explicitly compose existing source-owned SMG10002 or the inherited explicit biped10001 into the helper ABI; they are not newly produced FP events. Actual physical componentNONE, false unit-activity predicate and ordinary weapon header limit positive branch coverage. Class+10A rejection, valid physical velocity and positive type7 remap have source-complete implementations but are not measured positive cases here. No source object, parent, pool, node, location, physics field or readiness result is assigned to force those branches. [Oracle](../tools/oracle_sound_object_request_1_1.py), [literal fixture exporter](../tools/export_sound_object_request_fixtures.py), [native comparison](../tests/sound_object_request_tests.cpp).

Normal and Clang ASan/UBSan binaries are compiled from independently retained source/dependency snapshots. No current shared library or release is rebuilt or claimed fresh. Original repeats and complete1.5 mappings reproduce byte-identically, prior sound freeze pins are preserved, and the native reader-unavailable check retains the input packet instead of fabricating admission. [Audit](../analysis/multiplayer/integration/sound-object-request-native/audit.json), [checkpoint manifest](../analysis/multiplayer/integration/sound-object-request-native/checkpoint-manifest.json).

The next live composition needs actual retained raw carried-weapon/body/current-node/world-location producers at the local FP clock phase.
