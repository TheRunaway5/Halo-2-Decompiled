# Required-owner instruction policy

A native parent's entry cursor checks do not prove that a returned required
child leaves instruction or trace policy unchanged. A provider can replace
the callback, clear the cursor or enable tracing. Skipping the remaining pure
instruction sites would then change the source callback stream.

`SourcePhysicsContactRuntimeServices::RequiredOwnerPolicy` now binds an exact
owned callable and captured context to its executor. Its observation-only
matcher certifies that this audited body and its descendants preserve the
caller's instruction callback, cursor descriptor and trace policy on return
and exception. Unknown callbacks, wrappers, stale owner certificates and other
executors keep whole-entry source fallback. Immutable copies/moves of the same
audited body/context remain valid. A missing provider keeps its genuine
unavailable-owner behavior. Childless kernels do not need this capability.

The actual World producer uses `Impl::WorldRequiredOwner`, an immutable World
capture. Its matcher checks the actual callable target, captured World, live
main executor and both initially false trace flags. The independently audited
required-entry trace scopes restore that policy before returning or throwing;
descendants reacquire independently published immutable service tables. The
World's complete CPP passes syntax. Its exact callable/matcher executes under
both sanitizer compilers with 21 ownership/forwarding controls and three real
compiled defects. This does not qualify every numerical child outcome.

Accepted evidence:

- `native-required-owner-world-audit-20261110/report.json`: source ownership
  and trace-scope audit; corrected header hashes retain their prior diagnostic.
- `native-required-owner-policy-abi-fixture-fixed-20261110/report.json`:
  exact producer/callable wiring, owners, copies, wrappers, executors, traces,
  referenced-ABI forwarding and exceptions. All generated storage removed.
- `native-simplex-provider-policy-closure-20261110/report.json`: Boundary
  and Paired repaired; registered 3/3 plus GCC/Clang routes and omitted-guard
  defects pass. Boundary executes real mutating required children. Paired's
  actual children are local; its unknown-provider tests establish whole-entry
  fallback, with zero provider invocations.
- `native-marker-owner-required-policy-closure-20261110/report.json`:
  BACD0 repaired; registered 3/3, Clang, eleven defects and 180 genuine
  policy-mutation/reference routes pass, including original Effect ABI identity.

The effect-reference parent uses this guard; its installed component scope is
closed in `native-effect-reference-element-closure-20261110/report.json`.
The MOPP parent is unbound and also requires this capability.
Other native returning parents still need an explicit audit; this repair is
not a claim of universal child/provider closure. Original callback and ABI
behavior remains the oracle for uncertified routes.

Instruction-policy stability does not certify incidental host FP state. The
separate BACD0 handoff repair parks the caller's host environment around the
provider and then applies the actual returned source ABI. Its final installed
gate passes 3/3 plus independent Clang; all thirteen compiled defects reject
(`native-marker-owner-fp-fence-closure-20261110/report.json`).
The shared Contact `State::required` still loads returned
ABI without that fence; EffectReference and Boundary can reach it through
their existing dispatch. This is a remaining boundary audit, not a reproduced
fault in the exact World producer: the identified real particle and Scene
entrypoints own FP scopes that restore their callers. No shared State or raw
x87 scope behavior was changed for this narrow repair.
