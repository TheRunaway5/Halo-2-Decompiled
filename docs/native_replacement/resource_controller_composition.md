# Backed animation-resource controller composition

This proof composes the existing native defaults for `1264E0`, `126200`,
`1E5AF0`, and `1E5C80` through actual page/datum allocation, file submission,
computed retained-job ownership, completion, request deletion, and return.
It adds test coverage; it changes no production default or provider policy.

The fixture authenticates each complete owning body/default installer and its
actual TU1.5 dispatcher identity before copying native and canonical controls.
Mapped async reference children come from their real Arena/Shadow owners.
Imported CPU entries call their qualified ABI bridges with their normal
admission; this fixture does not execute the entire production imported-owner
shim. Unknown imports stop explicitly. Actual Effect exports are linked from
the complete production CPP, rather than replaced with allocation results.

The page-owner backing, initial page descriptor, span capacity and policy
budgets come from the authenticated existing original capture. Queue, node,
resource descriptor and nonzero byte extents are declared test inputs. The
allocators compute every page and datum. The current corpus covers each of the
four callers at byte extents 1/511/513/4095 and live x87 depths 0/1/4/8.

`SourceAsyncOwnedFiles` and the existing `SourceAsyncReadTask` algorithm read
actual scratch-owned cache bytes. The shared
`source_try_animation_cache_io_tu15` function preserves the existing World
**synchronous** policy: validate the real caller, read/write sector bytes,
retain the request, then publish its completion byte. A generated fixture
compiles the exact source-pinned World `retain_resource_read` method, row
schema and `F8000001` counter namespace. The exact animation-provider lambda,
including its `body_pose_animation=true` argument, is authenticated. The
fixture requires `body_pose_publication_active=false`; it does not qualify a
live World publication epoch, save/restore, or ordinary-provider admission.

The independent CPU comparison executes unchanged i386 instructions to the
genuine `1A3B70` entry. The actual native file/registry service computes its
state, and a second independent original CPU segment begins at `12613E` with
those actual bytes/registers. No original instruction is patched and no page,
datum or job outcome is supplied. The resumed private frame's three observer
seed words come from the actual post-service bank, preserving saved registers
and aliases. Capstone's missing read annotation for genuine `TEST r/m,reg`
operands is corrected using authenticated instruction semantics; stack
PUSH/CALL/POP/RET accesses are also observed.

The first 16-case GCC ASan/UBSan/LSan checkpoint passed complete native versus
canonical returns plus 11,184 unchanged original CPU instructions: 3,540
ordered reads, 2,504 stores, all GP/flags/XMM/MXCSR/x87 controls/status/live
80-bit values, and all final banks agree. The real owner produced 16 I/O jobs
through 184 actual file calls transferring 24,576 bytes. Native CPU bodies
emitted no literal instruction callbacks. Its immutable receipt is
`build/test-results/native-resource-composition-physical-san-r5-private-20261109/report.json`.
The expanded 64-case registered GCC ASan/UBSan/LSan and Release gates both
passed, as did independent Clang ASan/UBSan/LSan. Each compares 44,736 unchanged
original instructions, 14,160 ordered reads and 10,016 stores. One default
native corpus produces 64 actual I/O jobs through 605 file calls transferring
98,304 bytes; these counters exclude canonical controls, independent-service
snapshots and native comparison exports. The final component receipts are:

- `build/test-results/native-resource-composition-official-20261109/report.json`
  (registered CMake 2/2; sanitizer 99.12s, Release 43.47s).
- `build/test-results/native-resource-composition-clang-20261109/report.json`
  (independent compiler, full 64-case physical comparison).
- `build/test-results/native-resource-composition-closure-20261109/report.json`
  (bounded consolidation, source/dependency identities, scope and cleanup).

The compiler dependency receipts pin 247 inputs per run. Whole canonical source
snapshots are identified separately from later unrelated hierarchy prefixes;
each private fixture keeps its copied, authenticated body bytes. All generated
CPU ELF images, binaries, banks, actual cache files and build trees were removed.

Remaining boundaries are explicit:

- This is a source-backed fixture composition, not a whole live World or
  real-asset/gameplay/launcher acceptance claim.
- The World policy completes synchronously. The separately qualified real
  pending-worker/wait corpus establishes a different service/scheduling seam;
  it does not convert this provider to an asynchronous World implementation.
- Xbox kernel/import scheduling, cache eviction/device/MMIO pressure paths,
  composed exceptional prefixes and production cross-unit routing remain
  separate qualification domains.
- At this composition checkpoint, the native-named `1232C0`/`1AB330` helpers
  still contained virtual register/flag/site execution. Their later
  [typed queue DATA replacement](1AB330_async_queue_data.md) has separate
  installed CPU/source-route proofs, and this composition passes again with
  that installation. The synchronous positive cases do not qualify live
  pending-queue scheduling. Promotion was still instruction-shaped at that
  checkpoint; its later [typed promotion port](1236A0_async_promotion_data.md)
  has separate CPU, real-mutex and pending-worker regression receipts.
- Historical engine accounting and configured catalogs keep their original
  frozen hashes. This test adds no timing or observation-count improvement
  claim and retains no large generated artifacts.
