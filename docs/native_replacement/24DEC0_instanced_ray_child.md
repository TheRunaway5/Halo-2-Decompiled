# Instanced-ray child provider

Both TU1.5 production copies of `24DEC0`, in Primary live support and AI-frame,
now default to the shared typed policy in
`include/halo2/native_tu15_instanced_ray_child_kernel.hpp`. The retained ABI
view preserves lazy acquisition of the caller's key after publishing the
scenario word. It writes the count as two bytes and the remaining fields as
four bytes, preserving aliases and the original order. The public
`native_tu15_resolve_instanced_ray_child` facade shares that policy while
preserving its already captured value arguments, null/backend handling,
observer behavior and statistics. Six independent forwarding, collector and
helper bodies remain byte-identical and separately authenticated.

The exact source installer pins each complete body, selected resolver and
owning dispatcher. It also authenticates the sole qualified extra FA5D0 case
in fresh Primary generation. Installation is reversible and idempotent.
Specialized output is checked as an internally derived exact body; it does
not expand the source installer's dispatcher admission. Four binding tests
include fourteen body, resolver, dispatcher and public-owner drift controls.

The registered sanitizer and optimized Release suite passes all four tests.
Each raw/source configuration runs both GCC and Clang against 328 unchanged
i386 paths: 128 complete returns and 200 before-read, atomic-provider-write
and completed-observer boundaries. The corpus covers all thirteen sites,
all sixteen alignments, caller/collection/output aliases, exact caller 80-bit
values at depths zero/one/four/eight and all TOP positions, full GP/flags/XMM,
x87 controls/status, MXCSR, banks, ordered access/store streams and 2,082
original pre-I/O packets. Six native and four reference routes make 7,296
comparisons per compiler/configuration. Twenty-two admission refusals and
two independently compiled incorrect DATA policies are rejected.

Test-owned counters inserted after each authenticated native prefix prove
zero retained literal statements on admitted routes and actual retained
execution on every forced-reference route. Prepared reference code can use
cursor-only observations without calling the generic callback; that
optimization is explicitly distinguished from native execution. Native
admission checks the live callable, cursor, executor, three service sites,
trace controls and observation-only store witness. It initially admits only
TU1.5 dense, masked, non-MMX raw FP contexts. Other contexts retain the old
body; `HALO2_REFERENCE_INSTANCED_RAY_CHILD` selects it explicitly.

The actual public CPP passes GCC and independent Clang ASan/UBSan/LSan checks:
512 normal cases and 4,686 actual interrupted provider/observer cases out of
8,192 attempted controls. Results, full banks, ordered access/store events,
observations and statistics agree with the preserved original public body.
Both complete generators retain the exact provider default; raw and prepared
whole-unit syntax passes, including both current canonical units. Primary's
289 unrelated, pre-existing FP-lowering body differences remain recorded;
whole-unit Primary byte equality is not claimed or repaired here.

This closes the bounded TU1.5 provider/default and public DATA seam. It does
not qualify the surrounding ray controller, cast/collector children, other
images, unsupported FP contexts, device/MMIO behavior, physical page-fault
atomicity, observer-preimage failures in the raw view, or whole-engine parity
or performance. These changes are later than immutable catalog r17 and frozen
engine R14. All owned scratch, binaries, original-code copies, raw banks and
CMake trees were removed. The bounded receipt is
`build/test-results/native-instanced-ray-child-closure-20261109/report.json`.
