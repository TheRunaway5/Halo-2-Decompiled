# BF0C0 object node-matrix controller

The actual TU1.5 BF0C0 owner now has an authenticated native default in Primary
live support and AI-frame. BFB90/B8780/B87B0 use a shared typed animation
delivery/selection kernel, and the real ADCD0 prediction callback uses the
native ordered-word kernel through the actual-owner dispatcher. Wider physics,
animation sampling, root/type descendants and physical fault domains remain
separate work. The frozen r9 accounting row
executed 16,207,717 literal observations across the eight declared Coagulation
and Zanzibar workloads, ranking second after 30AA70. This is an observation
count including startup and teardown, not a timing or caller-cost measurement.

The complete matching TU1.5 bodies live in Primary live support and AI-frame.
The `bf0c0` symbol in `death_object_phases_generated.cpp` is a different MapPack
owner and must not receive a TU1.5 replacement based on that symbol alone.

## Native hierarchy stage

The private typed DATA kernel
`include/halo2/native_tu15_object_node_hierarchy_kernel.hpp` implements the
BF53C hierarchy stage: preserve physics-owned nodes, convert each remaining
model-order local orientation through actual144CF0, then compose it with its
already published parent through actual145560. The stage's initial model count
comes from the resumed model pointer. Every iteration reloads the model pointer
from the real caller frame; the loop bound reloads the model's count after both
child calls. Parent indices are signed16 and mask indices retain signed SAR5.

Its continuation contains only the semantic index, record offset, orientation,
output matrix and node record actually resumed by each real child. It does not
assume saved integer registers survived an output/caller-save alias unchanged.
The retained adapter in
`src/physics/runtime/native_tu15_object_node_hierarchy_abi.hpp` publishes the
real source ABI at memory/call boundaries and preserves the distinct BF5C0 and
BF62F epilogues. It is an explicit private stage entry, with no production
admission or environment-control change.

The existing TU1.1 `source_update_object_current_nodes_1_1` is useful algorithm
guidance, but omits BF0C0 caller-local publications and caches its hierarchy
bound. The asset-level `pose_world_object_nodes_frame` consumes parsed objects
and does not preserve retained memory/ABI ordering. Neither is silently reused
as a complete TU1.5 replacement.

## Controller invariants and remaining dependencies

The complete earlier physics/animation/root publication controller now uses the
same live-frame and semantic-child-continuation contract. Qualified
1707A0,144CF0,145560 may compose under their actual admission contracts.
Actual1DBBD0 physical delivery, E3BC0 height, BAC00 parent lookup, C15D0/C1CC0
animation tests, C1F40/C1EB0/C1F00 masks, BFB90 animation delivery, C1E50 flag
publication, B87B0/B8780 selection, B3AE0/B3B70 prediction, BFC70 root transform
and10E180 type notification must remain real native owners or explicit residual
boundaries until independently qualified. No recorded matrices or supplied
callee results may replace them.

The next retained controller must preserve these acquired values and live reads:

* The original body inBX differs from the body resolved again after physical
  delivery. The latter tests whether local orientations exist; the former
  supplies the actual local-orientation offset. Object-pool rows can change
  across that real child call.
* The tag-array pointer is cached from entry and reloaded only after the
  physical-delivery call. Definition/frame fields are reread at their actual
  source use sites, including the second biped test before the height child.
* Caller-frame slots are semantic storage with real backing. Pending argument
  pushes change subsequent operands: afterBF37A pushes the orientation pointer,
  BF37B's `[ESP+28]` reads the original frame's count at+24. It is not the parent
  matrix slot at+28. Full stack words, including partial-register upper bits,
  must come from the actual retained transport.
* Root vector copies interleave cached words and fresh reads. PositionX/Y
  stores precede the forwardX read; forwardX is stored before cached positionZ.
  The simulation-entity read precedes the final upX/Y stores. Prediction output
  copies likewise interleave fresh scratch reads and publications.
* The no-model path uses the cached object-pool pointer for its parent lookup;
  it does not insert a fresh global-pool read. A selected-animation result of0
  still reaches the genuine read at+16 and must remain a real boundary/fault.
* Child callbacks resume the actual cached body/model/manager and other values
  consumed afterward. A normal callee-saved ABI is not permission to substitute
  entry values when saved-word/output aliases changed the real continuation.

The initial hierarchy-only receipt does not establish full-parent closure, physical intermediate
flags, exceptional partial ABI, hardware page-fault atomicity, admission/control
isolation, default routing, visual parity, performance or launcher delivery.
