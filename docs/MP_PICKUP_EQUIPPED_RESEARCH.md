## Remaining explicit boundaries

- The unit/player record, object arena extents, inactive network identity, local view/controller/profile, active BSP clusters, registry pool backing arrays, HUD backing storage, hardware packets and polling intervals are declared inputs. Their complete original allocation/scheduling lifecycle is not recovered here.
- `124F30` supplies **exact descriptor-selected resident bytes** from Lockout/shared; resource I/O and scheduling are excluded. `18FCE0/18FD70` supply storage/capacity only; original object allocation, metadata construction, pose and identity logic execute.
- `FB560` carried marker/world attachment is still supplied return 0, cleanup 8. Original inventory ownership and unregistration are proven; parent/item attachment graph, weapon hand marker transforms and Havok constraints are not. Final carried items retain parent `+14=FFFFFFFF` in this bounded environment, which is an explicit attachment boundary rather than a claim of complete carried world state.
- Marker resource queries `1DC8F0/1DC940` retain supplied unavailable results. First-person notification `16A356`, effects `107B50`, and looping sound allocation `C10E0` remain named services. The actual unit graph capability/action clocks and samplers execute; those named leaves are not evidence of full presentation/effect/audio integration.
- Terrain visibility here enters only the real BSP plane/surface path. Instanced, object and Havok branches, normal item settling, full animated world-unit collision/registration, firing, replacement/drop, networking, and the full player/unit/object engine loop remain outside this frozen nine-case suite.

The native integration can use the original manager capability, exact held request, salted object carry, replicated sequence and animation-driven slot-switch contract now. Its source animation state and marker/physics service boundaries must remain explicit.
