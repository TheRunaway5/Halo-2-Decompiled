## Static search scope and reproducibility

[`tools/research_mp_combat_update_inventory.py`](../tools/research_mp_combat_update_inventory.py) uses original owned XBE bytes and fresh independently exported Ghidra entry inventories. It does not execute supplied annotation scripts, adopt annotation comments as behavioral authority, or use presumed relocation deltas as correspondence proof. XBE pins: disc 1.1 `aaea4c9c58ac02cf5f9cc97a16d688318c59b652e92301078e2547a2a5ea5377`; owned 1.5 `21b207e7efdacaf6124a0822837f8be570766a42505057f7fd2d2ba8f409c4fd`.

The explicit address scope is original 1.1 `C0000..110FFF` (unit/inventory/damage/projectile/weapon region), `11D000..11DFFF` (map-load region), and `164000..164FFF` (combat postprocess region), retaining inventory functions sized at least32 bytes. There are765 selected routines,720 with a unique16/12/8-instruction normalized entry-prefix candidate,45 without a unique prefix candidate. All720 candidates have equal normalized full instruction streams/direct internal branch topology. **Normalization is candidate correspondence evidence, not semantic equality.** It masks addresses within the loaded image, including values that might be integers rather than pointers; every changed nonbranch immediate is retained for independent interpretation. Every different paired absolute memory-byte value and unresolved/different callee is also retained separately.

The report contains 213 paired absolute-memory differences, 47 changed nonbranch immediate operands, and 169 unresolved/different direct-callee sites across198 candidate routines. Those counts include repeated reads and relocated pointers/tables. No new damage scalar, weapon constant, default/global state, or changed gameplay meaning is inferred from these differences. Switch-table payloads and callee semantics are not promoted merely because normalized surrounding instructions match. In particular, initial image zeros do not prove which globals later initialization changes.

The45 unmatched entries retain their previous/next uniquely matched anchors and all fresh original 1.5 entries between those anchors. Such intervals are search bounds only; repeated getters/callback wrappers, missing exporter entries and genuine changed routines can all appear there. The new Relic branch at `11F060` was recovered from such an interval and then verified by actual original bytes/call ownership/full execution in the separate freeze. An unmapped interval is never treated as a changed balance routine without that further evidence.

Results are in `analysis/multiplayer/title-update-1.5/combat-function-inventory/report.json`; questioned candidates retain both complete original listings in its `instructions` directory. A second full independent scan is retained in `reexecution`. Both full reports and every listing repeat identically. Reproduce into a fresh directory with `.tools/python/bin/python tools/research_mp_combat_update_inventory.py --output <new-directory>`.

## Remaining gate

This bounded search does not establish all 1.1→1.5 combat differences, unsearched network/control/session routines, initialization writers, later updates, multiplayer map activation, full weapon/sandbox logic or live native parity. The forty-five ambiguous/missing-entry intervals and retained callee/literal/table dependencies remain explicit. Existing source-kernel equality results and the identical combat postprocess must not be turned into a whole-update equivalence claim. No production file or earlier frozen suite is modified.
