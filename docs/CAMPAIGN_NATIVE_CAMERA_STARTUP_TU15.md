# Native camera storage and CRC accounting

The startup module implements complete TU1.5 input storage `1888A0`, director storage `157E10`, cinematic storage `13E9E0`, and default-angle copies `381710` / `381730` / `381750`. Constructors reserve their actual already-owned game-arena ranges through `4F2950` / `4F2954`, account each size through the genuine native CRC algorithm and publish the real source pointer. They neither manufacture a player/unit nor allocate a replacement camera bank.

Shared `native_tu15_crc32` implements full `166AE0` reflected polynomial table construction and `166A80` streaming update. The initialization flag and table remain in actual mutable source storage (`56E225`, `56E258`), already owned by `native_tu15_arena_data.cpp`. A nonpositive signed count still performs lazy initialization, reads the checksum and publishes it; positive counts read every actual input byte and then the selected current table word. No host CRC library, cached table or supplied checksum replaces that behavior. Constructor size words use a native private value interface; no guest scratch address or CPU packet is created.

Director construction preserves all 323 individual reset stores, first control allocation, checksum, control byte, fresh cursor/base reads, control-pointer publication, second reservation/checksum and director publication. Cinematic construction preserves eight zero stores, global pointer and final zero store. Aliases, declared external input changes and source faults retain their original partial publication order. Default-angle copies read their original operand addresses; no numeric defaults are baked into gameplay.

Numeric transport owns only the six ordinary void startup entries. Original startup table slots `44B1A0`, `44B3BC`, `44B644` select the three constructors through `13A766`; its continuation ignores volatile results. CRT defaults are original slots `46DA68` / `46DA6C` / `46DA70`. Only the actual RET word and SP are consumed; unrelated ABI state is preserved. Director construction's REP profile requires DF=0, and the binding rejects DF=1 before storage access. The authenticated ordinary caller's private size word is disjoint from persistent storage. Arbitrary CRC ABI/register reconstruction is not claimed.

`analysis/campaign-native-new-game-camera-20261028/startup-proof.json` pins current source and evidence. The unchanged physical i386 original executes all 141 sites across 287 cases / 989,841 instructions, including 140 semantic fault prefixes, three true unmapped source faults, signed counts, cold and noncanonical warm tables, aliases, constructor wrap and dynamic fresh/cached arena pointer tests. Both typed constructors and ordinary numeric bindings compare persistent bytes, ordered reads and original stores. Actual x87 values/control/status and MXCSR remain unchanged, including occupied original x87 stacks. Independent original repetition is byte identical. GCC and Clang ASan/UBSan pass; Clang rejects eight source mutations. A second agent independently checked original CRC and constructor read/publication order.

The required original fixture is `tests/fixtures/native_campaign_camera_startup_tu15.json.gz` (930,911 bytes). Original executables, raw banks, compiler products and build trees were removed. `cmake/CampaignNativeCameraStartup.cmake` includes guarded `NativeTu15Crc32.cmake`, retaining one production CRC definition.

Controller initialization, cinematic start, camera control, animation/director/observer updates and actual New Game progression remain separate required native work. These startup proofs do not qualify a full engine or launcher runtime.
