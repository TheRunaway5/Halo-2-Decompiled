# Original sound-cache clock, alias and drain

The new `sound_cache_lifecycle` module implements complete CPU owners `21A920`,
`13E9A0`, `21AA60` and `21A800`, including the source cache-delete callback and
pool release. It also exposes an explicitly bounded cold `127290` caller. It
does not enable audio, invent a frame clock, or admit a voice. No launcher,
runtime, renderer, shared CMake, provider or earlier frozen source is changed.

## Source-created cached state

The oracle reexecutes the immutable cache-request composition, including the
original SoundCreate raw-ABI preparation, queue constructor prefix and actual
owned `shared.map` file reads. It captures complete original memory and CPU
context after completed flags0 and before the following flags4 executes. Done
and first-use are source-produced 1; permanent pin and temporary use are
source-produced 0. Each independent control restores that whole captured
state. It never assigns a cache timestamp, pin, completion, pool count, queue
flag, availability byte or selected source handle.

The initial request remains an explicit composition of previously rejected FP
raw packets into the SoundCreate ABI. This extension does not turn that into
an admitted `128380` packet or a live local-player sound. The inherited native
file-token binding and synchronous source worker remain the previously named
platform boundaries. No original Xbox thread or file-open producer is added.

For each of ready, reload and empty reload, four independent controls run:

1. Original `21A920` followed by 255 original `21AA60` calls and one saturated
   call. The epoch advances from 1 to 2; the temporary-use byte reaches 255
   through original increments, then remains 255. All 256 returned physical
   aliases per sample match native code exactly.
2. Complete original `127290` returns with the genuinely constructed system
   `+78 == 0`, taking its actual cold tail and advancing the cache epoch.
3. Complete `13E9A0` executes as an explicitly direct ABI control on the actual
   timestamp1 state. This is not a manufactured ordinary overflow caller.
   It produces epoch257 and page timestamp0.
4. Complete `21A800` obtains one actual host tick and drains the genuinely
   completed, unpinned entry. Actual `13EFA0 -> 21AAF0 -> 16D4C0` clears the
   chunk handle to NONE, releases both entries and clears cache validity.
   No wait is needed by this real unpinned state.

The original GetTickCount thunk executes unchanged. Its existing data pointer
is backed with a measured CLOCK_BOOTTIME raw32 value only when requested.
The independent repeat replays those separately retained actual OS inputs at
that same data service boundary. The original complete reports, instruction
execution listings and fixture bytes match exactly. `clock-values.json`
explicitly distinguishes the first actual host observations from replay;
the original report does not pretend those observations occurred twice.

## Native contracts and source order

`SoundCacheLifecycleBindings` holds mutable operand **addresses**, not startup
values or presumed live defaults. `paired/providers.json` retains their exact
paired mappings. The source rereads cache roots after waits and deletion.

| Field | 1.1 operand | u5 operand |
|---|---|---|
| entry_pool_pointer | 5098DC | 50EBDC |
| page_allocator_pointer | 5098E4 | 50EBE4 |
| physical_buffer_pointer | 5098E0 | 50EBE0 |
| work_mutex_slot | 4E792C | 4ECC2C |
| work_head | 4E9EBC | 4EF1BC |
| requests_added | 4E9EC0 | 4EF1C0 |
| sound_system_pointer | 4ED950 | 4F2C50 |

`21A920` advances a source epoch, independently of wall time. At signed maximum
it calls `13E9A0`, which writes epoch257 and, for every occupied page, computes
unsigned `age = 0x7fffffff - timestamp`; age greater than256 yields0, otherwise
the timestamp becomes `256 - age`. The clock then sets eight DWORD thresholds
at allocator `+44..+60` to signed maximum. This owner does not clear cache-entry
temporary use. The near-maximum branch is a complete static translation; its
ordinary overflow condition and near-maximum positive timestamps are not
claimed to have been produced by this bounded execution.

`21AA60` resolves the actual chunk handle, literal16-byte cache entry and byte
`+5`. It increments only below255, then resolves the page through literal24-byte
addressing and returns `(page_index << (page_shift & 31)) + physical_buffer`.
It has no readiness gate. No returned alias is treated as proof of playback.

`21A800` first reads genuine host ticks. It iterates the original occupied entry
pool, retaining its initial iteration root while rereading the current cache
root after synchronization. An entry can proceed immediately only when its
pin and temporary-use bytes are zero and done is nonzero. Otherwise it requires
a real work-mutex wait, counts actual work-list nodes, genuinely releases that
mutex, stores the count, and obtains another actual tick. Unsigned elapsed time
at least5000 ends that wait loop. The actual source deletion callback clears
the chunk handle before freeing the cache entry, then unlinks and frees the
page. The cache-validity byte is cleared last. Missing memory, clock, wait,
release or an unknown nonzero callback stops instead of returning success.

The native cold `127290` helper reads the actual availability guards and rejects
the active branch. Its cache-store instruction identities are the actual tail
PCs. It neither represents the complete active body nor supplies its required
driver/listener/scheduler/effects services.

## Concurrency and remaining live gate

Raw memory spans are used only during immediate reads/writes; no span is
retained across a wait, clock or other external service. They must be accessible
only under a common full-CPU-entry execution lease. The cooperating worker
owner is implementing that separate native gate: release before a genuine
blocking wait/yield, reacquire afterward, and never turn a timeout into acquired
status. This checkpoint is serial and does not establish concurrent raw-byte
polling visibility, memory atomics or background file-write safety.

The busy drain/time-expiry branches, nonempty multi-page unlink cases, debug
poison pool and ordinary epoch-overflow condition remain unexecuted here. Their
complete static CPU translation is distinguished from this positive unpinned
evidence. Initial source cache construction and original callback identities
remain required. A static XBE value is never substituted for an active root.

The next active audio-update gate remains source startup commit `126D35`, which
owns system `+78 = 1` only after the complete mandatory platform initialization
returns through its actual success path, plus map activation owning `+7A`.
The current captured state has neither result supplied. It cannot legitimately
enter the positive active `127290` branch by assigning those flags. Actual
device/routing/stream/voice ownership and source local admission are still
required before this work can establish audible live reloads or all-map SFX.
