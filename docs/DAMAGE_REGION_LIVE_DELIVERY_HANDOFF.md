## Region bank and incoming selection

`BB6E0` resolves the object through `*[4E78D0]+44`, then its definition through `*[4EB114]`. Definition `+38` is the model datum; NONE returns. It computes `n=trunc_toward_zero(sign_extend_i16(object+118)/10)` and `base=object+sign_extend_i16(object+11A)`. The complete region allocation is `10*n` bytes: an `n`-byte active-permutation prefix, another `n`-byte prefix, then `n` eight-byte state records at `base+2*n`. This routine snapshots only the **first** prefix into its16-byte local bank. It does not copy the second prefix or replace the caller's region allocation. [Complete BB6E0 instructions](../analysis/damage-shields-goal-20261011/live-region-delivery/research/paired/instructions/000bb6e0-old.asm).

Each eight-byte state record consumed by `16F0E0` has signed permutation ordinal `+0`, signed state byte `+1`, flags byte `+2`, untouched padding `+3`, and full looping-effect datum `+4`. Object `+B1` is a **signed variant index**. The exact ten pushed arguments are `{unit, model, signed_object_B1, input_region, FFFFFFFF, 0, input_flag_bit, input_region_mask, base, base+2*n}`. Input `region` filters the ordinal of a collision region; it is not a requested damage state. The forced state argument is `FFFFFFFF`, so each existing signed state is preserved. `flag_bit` selects an x86 shift bit; the signed WORD region mask sets or clears that bit for each region before candidate selection. Thus the actual `D8070` arguments select every region and request bit2 for every region. [BB6E0 CALL construction](../analysis/damage-shields-goal-20261011/live-region-delivery/research/paired/instructions/000bb6e0-old.asm), [actual shield-depletion caller](../analysis/damage-shields-goal-20261011/vitality-delivery-boundary/pairing/instructions/000d8070-old.asm).

`16F0E0` iterates model `+70` collision-region count. A requested lower state is rejected unless the explicit allow-decrease argument is nonzero. A non-NONE variant indexes model `+54` with stride`38`, obtains the signed region map at variant `+4+region`, and selects the variant-region record through variant `+18 + map*20`. It calls `16F550` with the existing signed permutation ordinal, desired state/flags, randomize0, and capacity32. No candidate means that region's active/state bytes are unchanged. [Complete selection owner](../analysis/damage-shields-goal-20261011/live-region-delivery/research/paired/instructions/0016f0e0-old.asm).

The seven-DWORD candidate record is `{render_permutation, permutation_ordinal, state, flags, effect_datum, marker_string_id, weight_bits}`. A selected candidate writes its render-permutation byte to the active prefix, its ordinal to state`+0`, state to `+1`, and flags to `+2`. AL becomes1 whenever a candidate is found, including when those stores do not change any bytes; **AL is not a reliable byte-change indicator**. `BB6E0` ignores AL. If the selected state differs from the old state, an existing non-NONE loop is passed to `178CD0(...,1)`. A new non-NONE authored loop initializes the full96-byte request through `177960`, sets flags3, effect datum, unit owner and marker, sets request`+54/+58=030005A6`, and calls `177A10`. Only its actual return is written to state`+4`. No loop result is supplied, and NONE is not unconditionally written after stopping an old loop. [State writes and loop lifecycle, `16F23F..16F2D0`](../analysis/damage-shields-goal-20261011/live-region-delivery/research/paired/instructions/0016f0e0-old.asm).

## Selectors and actual stock authored data

`16F550` scans variant-region permutations at `+0C`, stride`20`. A permutation filter of NONE admits all ordinals. With randomize0 it uses the default permutation when both requested state and flags are zero; otherwise it searches authored state records at permutation`+10`, stride`18`, requiring exact WORD state `+6` and BYTE flags `+5`. If no candidates were produced and requested flags were nonzero, it retries once with flags zero, preserving the state. A state list with count0 does not create an effect or a missing state. Candidate capacity is enforced by the literal signed comparison. [Selector instructions](../analysis/damage-shields-goal-20261011/live-region-delivery/research/selectors/instructions/0016f550-old.asm).

`16F760` returns NONE for count0 and index0 for count1, without consuming RNG. Larger positive counts sum weights in the original SSE order, advance the mutable seed behind `4EE9D8→4F3CD8` using `seed=seed*0019660D+3C6EF35F`, use the upper16 bits through the original x87 sequence, then select by cumulative weights. The randomize branch in `16F550` uses the same real seed owner and its original strict comparison. The paired original scalar constants are separately re-read in the audit; no replacement RNG seed or normalized probability is published. [Weighted selector](../analysis/damage-shields-goal-20261011/live-region-delivery/research/selectors/instructions/0016f760-old.asm), [literal scalar reads](../analysis/damage-shields-goal-20261011/live-region-delivery/research/audit.json).

The [authored-region extraction](../analysis/damage-shields-goal-20261011/live-region-delivery/research/authored-regions.json), SHA-256 `a340552ac1f07c6e0cc002503a834ef64b6f26c4ff732ffd391bbcd37c5b5d17`, reads unchanged `assets/disc/maps/lockout.map`, SHA-256 `14c54046f259842bdac765526e7fe2d991369502041647f47db409ce845987a9`, using exactly the pointer/stride fields used above. It retains every selected descriptor/permutation/state byte, original virtual address and file offset. String names are labels, not behavioral authority.

Both use default variant string`07000001`, at index0. In the ordinary stock state0 path, bit2 produces no authored state match, so the literal flags-zero retry can choose the default permutation. This is a static path implication, not a claim that arbitrary fabricated object state is coherent. State/variant/prefix/physical-component fields for live diagnostics should come from actual object birth and preserve this relationship. The live unchanged-executable/native comparison is the parent's separate follow-up.

## Attachment and physical-region consequences

After region selection, `BB6E0` calls `17CC40` with EAX=unit, then `1C8E10` with EAX=the saved old prefix and stack `{unit}`. `17CC40` uses signed extent `object+11C` divided by8 and signed offset `+11E`. It stops at the first8-byte record whose first byte is2. A NONE/invalid effect in that first matching record returns without scanning later matches. A valid effect is checked against the current effect pool behind `4F1F0C→4F720C`, including nonzero signed salt and index limit. It then calls `179DD0` with EAX=effect, ECX=`FFFFFFFF`, stack `{effect_record[48], effect_record[58], 0, 0}`. That effect/attachment update must use the live pool. [Complete attachment refresh](../analysis/damage-shields-goal-20261011/live-region-delivery/research/paired/instructions/0017cc40-old.asm).

`1C8E10` skips a NONE `object+B4` physical-component datum, otherwise indexes the current `526248→52BE5C` physical pool with stride`A0` and requires record`+4` bit11. It compares old/new active bytes for all model collision regions, obtaining the permutation table through region`+C`, stride8, and each permutation's physical-region byte`+6`. Equal render permutation bytes skip; unequal bytes with equal physical-region mapping also skip. A changed mapped physical region calls `1C70D0(unit,0)` once and returns. NONE active bytes receive the literal NONE-mapping checks. [Complete physical-region comparison](../analysis/damage-shields-goal-20261011/live-region-delivery/research/paired/instructions/001c8e10-old.asm).

`1C70D0` records old physical flag bit5, optionally calls `1D4C50`, calls `1D3BB0`, writes the caller's full flags DWORD to component`+4`, calls `1D2B10` with the object's actual physical datum in EAX, then conditionally calls `1D4F30`. A successful physics rebuild cannot be represented by an arbitrary supplied return. [Complete rebuild dispatch](../analysis/damage-shields-goal-20261011/live-region-delivery/research/selectors/instructions/001c70d0-old.asm).

## Native ownership and remaining boundaries

The [frozen native snapshot](../analysis/damage-shields-goal-20261011/live-region-delivery/research/audit.json) records current entry groups and dispatch. During this research the parent added `BB6E0`/`16F0E0` to native construction; the snapshot was taken after those edits. `16F550`, `16F760`, `17CC40`, `1C8E10` and `1C70D0` were already exposed construction owners. `178CD0`, `177A10` and `179DD0` have startup entries. `MultiplayerObjectRuntime` actually runs original `1775D0`/`177690` effect-pool startup and original world construction, so these banks must not be replaced with new empty stand-ins. `177960` has complete paired static proof here but is not exposed in the frozen entry-group lists. Existing lower ownership and recursive ABI preservation should be reused, then verified on a reached path. [Frozen registry](../analysis/damage-shields-goal-20261011/live-region-delivery/research/native-snapshot/src/death_world_runtime_entries.hpp), [frozen actual world construction and dispatch](../analysis/damage-shields-goal-20261011/live-region-delivery/research/native-snapshot/src/multiplayer_object_runtime.cpp).

The immediate real lower boundaries are: `178CD0→178C10/179080` for effect teardown; `177A10→179B90` for actual effect allocation plus its retained admission/owner/attachment/render/update calls; `179DD0→178E10/B9C20/167DAF/17A160/17A030` for actual model-marker and effect instances; and `1C70D0→1D4C50/1D3BB0/1D2B10/1D4F30` for current physical membership and shape reconstruction. The reports preserve their exact paired CALL sites and targets; this handoff does not assert complete transitive ownership or successful delivery merely from those edges. The two call-free selectors are complete. No shield draw, fatal cleanup, all-damage-source integration or Xbox framebuffer parity is claimed by this static research.
