# Animation sampling and high-refresh presentation boundary

Research date: 2026-10-08. The existing original pose samplers accept fractional animation frames. Original pose-transition blending also exists, with saved local transforms and a simulation-tick counter. These are distinct owners. The inspected ordinary object-render consumer delivers the **current** world-node bank; this evidence does not establish an original previous/current render-snapshot interpolator or an original high-refresh rendering fraction. The user's requested higher-refresh smoothing can use an explicitly native presentation policy over completed source-clock states, leaving gameplay, action selection and events unchanged.

This is read-only research. The [focused byte audit](../tools/research_mp_animation_interpolation_u5.py) and [frozen report](../analysis/multiplayer/integration/inventory-source/animation-interpolation/frozen/report.json) compare 18 complete original bodies between owned TU1.1 and authenticated TU1.5. Every listed instruction is checked against its original XBE bytes. The independent repeat is in [frozen-reexecution](../analysis/multiplayer/integration/inventory-source/animation-interpolation/frozen-reexecution/report.json). Earlier executables, oracles, reports and production files are unchanged by this research.

## Fractional animation samples

Channel `1CA950` reads the channel's option ushort at +12, rate at +18, frame at +1C, graph/packed animation at +0/+4 and original clock frequency through `[518444]+2`. Fractional sampling is enabled by option **40**, or by an active option-bit0 channel with nonzero rate whose rate differs from1 or whose frequency differs from30. A retained fractional clock alone therefore does not mean ordinary source rendering samples its fraction. The source consumes the interpolation argument's **low byte**. [1CA950 original bytes](../analysis/multiplayer/integration/inventory-source/animation-interpolation/frozen/instructions/001ca950-old.asm), [TU1.5 equivalent](../analysis/multiplayer/integration/inventory-source/animation-interpolation/frozen/instructions/001ca950-u5.asm).

`27FB50` takes frame in XMM1, weight in XMM4 and resource input in ESI; remaining caller arguments provide animation, masks, destination and mode. In its ordinary fractional-sampling branch:

1. Truncate the frame with CVTTSS2SI, then clamp the current index to0..N−1.
2. Initialize next=current and fraction=0. With interpolation enabled and current!=N−1, select next=min(current+1,N−1), fraction=frame−float(current).
3. A fraction below original `46504C` (`38D1B717`, approximately0.0001) snaps to current. A fraction above `4650E8` (approximately0.9999) snaps to next. At the final index, disable interpolation.
4. Select the actual codec's fractional or nonfractional rotation/translation/scale functions. Masks and animation type remain source inputs.

There is **no final authored frame-to-loop-start blend** in this branch. The channel clock's epsilon-bearing wrap and the sampler's last-index clamp are separate. An interpolated presentation frame below the clock end still holds the last authored sample once it reaches indexN−1; only the clock wrap selects the beginning again. [27FB50 original bytes](../analysis/multiplayer/integration/inventory-source/animation-interpolation/frozen/instructions/0027fb50-old.asm).

The earlier base-disc sampler is `2798A0`, not TU1.1 `27FB50`. Its unchanged bounded oracle observes1.5→indices1/2/fraction0.5 when enabled,1.5→1/1/0 when disabled, and515.5/515.9998779→515/515/0 for a516-frame clip. That is existing base evidence; it must not be relabeled as a newly executed TU1.5 case. The existing actual TU1.1 Spartan live-pose report contains155 verbatim codec-dispatch snapshots, all with fraction zero. Their actual graph, frame, masks and dispatch targets are copied unchanged into the new correlation report. ## Quaternion rules depend on the owning operation

Packed codec3 `2929F0` converts both keys' signed16 lanes, computes `a*(1−fraction)+b*fraction`, then normalizes with packed RSQRTPS. Sparse codec4 `292CA0` locates adjacent authored timestamps and uses weights `next_time−sample` and `sample−current_time` before the same packed normalization. Neither complete body performs a dot-product hemisphere correction. Their quaternion normalization groups squared lanes through packed shuffle/add instructions; it must not be replaced with an assumed library SLERP under a parity claim. Original codecs retain packed integer inputs, rather than independently normalized float keys. [Codec3 instructions](../analysis/multiplayer/integration/inventory-source/animation-interpolation/frozen/instructions/002929f0-old.asm), [codec4 instructions](../analysis/multiplayer/integration/inventory-source/animation-interpolation/frozen/instructions/00292ca0-old.asm).

Object local transition `1DCE60` instead takes current locals in ECX, transition counter in EAX, node count in EBX, and stack `(mask,saved_locals)`, RET8. Each local is32bytes: quaternion0..C, translation10..18 and scale1C. It obtains weight from `1DCD60`. For admitted nodes it computes saved·current in x/y/z/w order. If dot<0 it negates the **current quaternion weight**. The blended quaternion norm accumulates `((x²+y²)+z²)+w²`, spills binary32, then executes x87 FSQRT/FDIVR and component multiply/store. Nonpositive norm yields `(0,0,0,1)`. Translation and scale use `(current−saved)*weight+saved`, with separate scalar SSE operations. This shortest-sign normalized blend belongs to a **pose transition**, not to codec-key interpolation. [Complete local transition](../analysis/multiplayer/integration/inventory-source/animation-interpolation/frozen/instructions/001dce60-old.asm).

Physical Xbox reciprocal/reciprocal-square-root seeds remain unresolved. The separate original Unicorn/native SSE comparison demonstrates that host seeds need not match Unicorn, much less Xbox hardware. High-refresh visual interpolation cannot strengthen that parity claim. [Existing approximation boundary](SPARTAN_LIVE_POSE_1_1_RESEARCH.md#reciprocal-instructionemulator-boundary).

## Saved poses, transition clocks and cuts

Object body+110 is the current local bank byte size; signed offset+112 points to current32-byte locals. Signed offset+10E points to a **saved transition local bank**. Signed offset+12A locates the manager; its+64 four-byte counter contains current, duration, curve and flags. Object+114/+116 describe current52-byte world matrices. Region/permutation blocks at+118/+11A are not previous pose banks. [BB240 ABI](../analysis/multiplayer/integration/inventory-source/animation-interpolation/frozen/instructions/000bb240-old.asm), [BEA50 order](../analysis/multiplayer/integration/inventory-source/animation-interpolation/frozen/instructions/000bea50-old.asm), [renderer](../analysis/multiplayer/integration/inventory-source/animation-interpolation/frozen/instructions/0003d4e0-old.asm).

`BB240` first requires current-local offset!=NONE and definition+38 model!=NONE. `1CEFE0` requires positive node count and duration. An existing unfinished transition rejects a shorter requested duration than its remaining time unless its completion bit2 is set. Admission clears counter bytes0/1/3, copies node_count*32 actual current-local bytes to the saved bank, then starts the counter with direction byteBL=1. `BB240` marks the object through B8250 after the request; it does not create a saved pose every render frame. `BB2C0` clears counter bytes0/1/3 and marks dirty, preserving curve byte2. [Capture/admission](../analysis/multiplayer/integration/inventory-source/animation-interpolation/frozen/instructions/001cefe0-old.asm), [clear](../analysis/multiplayer/integration/inventory-source/animation-interpolation/frozen/instructions/000bb2c0-old.asm).

`1DCC30` computes original frequency*seconds, spills to binary32, uses x87 FISTP, clamps ticks1..127 and stores duration=ticks−1. Duration<1 clears the transition. Existing active counters are rescaled when duration/direction changes. `1DCD10` advances or decrements one signed byte and marks completionbit2; `1D0ED0` updates manager counters and clears the completed local-pose counter. `1DCD60` divides current by max(duration,1), applies the stored curve, and clamps0..1. Curves1/2 invoke other original helpers; they are not substituted here. Curves3/4 execute their listed polynomial arithmetic. These fields cannot be reconstructed as a fixed render delay or a guessed fractional wall-clock weight. [Counter setup](../analysis/multiplayer/integration/inventory-source/animation-interpolation/frozen/instructions/001dcc30-old.asm), [counter update](../analysis/multiplayer/integration/inventory-source/animation-interpolation/frozen/instructions/001dcd10-old.asm), [weight](../analysis/multiplayer/integration/inventory-source/animation-interpolation/frozen/instructions/001dcd60-old.asm).

The first-person transition producer `16872A` copies its current graph-local scratch to scratch+800, using the actual hand graph-node count and only when viewflag2 is present. `168866` updates actual manager channels and transition counters, then schedules `1690FD` pose construction. That construction samples actual channels and, when manager+65 is nonzero, invokes `1CFCA0` with the saved+800 bank; the TU1.1 wrapper tail-calls `1DCE60`. Those saved scratch poses are **transition state**, not an established pair of adjacent rendered-tick poses. Secondary layers, feedback, IK and camera producers remain part of the full source first-person path. [Capture](../analysis/multiplayer/integration/inventory-source/animation-interpolation/frozen/instructions/0016872a-old.asm), [update](../analysis/multiplayer/integration/inventory-source/animation-interpolation/frozen/instructions/00168866-old.asm), [pose consumer,16984B..169876](../analysis/multiplayer/integration/inventory-source/animation-interpolation/frozen/instructions/001690fd-old.asm), [TU1.1 wrapper](../analysis/map-pack-update/functions/001cfca0.c).

## Verified integration seam and current native limits

The existing registered-SMG oracle establishes actual primary identity, delay, rate, frame, options, event masks, flags and hand fire counter after each completed bounded FP update. Its six actual cases total541ticks. Clock advancement is `(dt*rate)*30+old_frame` with separate binary32 operations, end=N−epsilon, actual flags and activity transitions; reload ammo transfer remains a distinct weapon phase. Initial allocation instant-equip must not be turned into timed-ready startup. [Clock/source fixtures](SMG_FP_CLOCK_1_1_RESEARCH.md), [native retained-clock integration](MP_FP_CLOCK_NATIVE_INTEGRATION.md).

For the user's requested higher-refresh enhancement, the bounded presentation contract is:

- Retain previous/current **completed actual bindings**, actual definition and consecutive tick identity. Keep simulation/channel/action/event updates at their existing tick stages. Rendering writes only temporary pose/vertex buffers.
- Gate same unit/weapon/graph/animation/representation/activity and require a callback-free copy of the existing source clock advanced once to equal the current represented hand state. A rejected pair snaps to current. This is a native continuity policy, not an original revision-counter producer or proof about unrepresented secondary/camera/feedback state.
- Interpolate the retained animation **frame**, then sample that same actual selected clip into shared arms/weapon locals. For a measured positive-rate loop with actual wrapflag4, use its original threshold/loop span to unwrap once. The existing native stock clock supports loop_frame0 only. Other loops, rates or missing source fields must remain outside this bounded gate.
- Preserve exact endpoint copies, final-index behavior and identity cuts. Do not dispatch sound, animation events, damage, ammo transfer or action completion from a fractional presentation sample.
- Evaluate a carried weapon against its parent's **same sampled pose** and actual attachment marker. Rebuild hierarchical matrices from local transforms rather than linearly blending already composed affine matrices. Presentation matrices must not replace retained collision/current-node state.

At inspection, `src/animation_presentation.cpp` implements the proposed copy-and-compare single-primary policy and `src/multiplayer_runtime.cpp` uses it for local registered SMG hand0. Its existing `model_pose.cpp` fractional float-key sampler is a useful visual consumer but is not a newly verified original packed-codec sampler: it uses decoded float keys, different interpolation arithmetic, and lacks the original near-endpoint snap rules. Its seconds-based path also wraps independently of retained channel flags; retained-frame entry points avoid that independent clock choice. Do not describe this enhancement as exact original quaternion/codec arithmetic. [Native presentation module](../src/animation_presentation.cpp), [sampling](../src/model_pose.cpp).

The current third-person path chooses existing idle185 and advances its presentation time; higher-refresh sampling makes that path smoother but does not close real locomotion/action/current-pose ownership. Original equipped primary/secondary channels, physical classification, local callbacks, deferred mask scheduling and current collision matrices must remain separately integrated. This research does not select new clips from velocity or invent channels. At inspection the registered first-person presentation branch was guarded `!client`; the client fallback still sampled integer tick/shot/reload time. These are runtime integration observations, not immutable claims about later parent-agent edits. [Existing equipped source evidence](SPARTAN_EQUIPPED_ANIMATION_1_1_RESEARCH.md), [owned command/pose boundary](MP_SPARTAN_OWNED_POSE_RESEARCH.md).

`3D4E0` ordinary AL=0 returns object+116's current matrix bank and the render-model node count. Its AL!=0 branch delivers separate render-object scratch. Neither complete branch supplies a previous/current tick pair or render fraction. The bounded original scheduler still has independent readiness/device/clock stops; no full admitted title/render sequence or original high-refresh tick-to-render interpolation fraction is claimed. [Original current-node delivery](../analysis/multiplayer/integration/inventory-source/animation-interpolation/frozen/instructions/0003d4e0-old.asm), [actual whole-tick stop](MP_ITEM_TICK_OWNER_RESEARCH.md).
