# Original round phases and reset dependencies

The original first-round initializer now completes against Lockout's actual
scenario and its 32 netgame equipment rows. The earlier missing-scenario stop
at TU1.5 `15D77C` is resolved by binding that real cache data and executing the
original row initializer. Native multi-round gameplay remains unbound.

The authored Elimination buffer enables parameter11, **Reset Map Every Round**.
Its unchanged next-round path needs additional world systems. A successful
control sequence with this setting disabled must not count as stock Elimination
working. The new oracle preserves both outcomes explicitly.

The original post-world owner decrements the signed32 countdown with x86 wrap.
While not game-over, lifecycle2 changes pending status to3 when the countdown
expires and the signed16 round index is below31. Entering phase3 increments that
index with signed16 wrap, emits event8 and sets the countdown to the signed16
clock rate. Expiry in phase3 requests status1. At index31 or above, phase2 expiry
begins game-over instead. Absent engines and raw mode4 skip this post-world owner.

Entering phase2 clears only the stat-bank validity byte, freezes enabled
recording outside raw mode4 and loads five times the signed16 clock rate.
At30Hz that is150 deliveries in phase2, followed by30 in phase3. The original
world frame is not executed by this oracle; clock increments between calls are
declared input deliveries.

Entering phase1 calls the complete round initializer before refilling lives.
It clears the 108-byte engine bank at+74, copies the configured signed16 time
limit, and invokes the full object/map reset when the signed round index is
positive. Outside raw mode4 it clears player respawn countdowns and corresponding
engine row flags, applies the original netgame-row reset policy and accumulates
the complete player/team score bank. It then resets player bytes1A7/1A8 and calls
the registered engine's initializer. The stat validity byte becomes1; round
start consumes the supplied clock, and the original eligible-player iterator
refills signed16 lives and sets player flag8. Raw mode4 retains its distinct
gates, including the unconditional1A7/1A8 reset. Unknown field meanings remain
unnamed.

## Live-object boundary and next work

Separate probes supply declared salted object records for an actual referenced
SMG definition and the actual referenced multiplayer Master Chief biped. Their
construction/allocation is not executed. They retain the first missing AI
context in the original destruction callback. Executing the complete original
multiplayer AI initializer (`1C79E0`/`1CB3D0`/`1CFC90`) against poisoned storage
clears exactly enable byte1, as the original game-type2 branch requires.
This advances the unchanged reset path without supplying a callback return.

The subsequent TU1.5 stops are `18A85A`, reading saved view/control context+58
for the world weapon, and `154E80`, writing player-global context+4 for the
current unit. Corresponding earlier-image stops are retained. These identify
additional required owners; declared object records do not establish a valid
constructed live world or complete teardown.

The next integration work must bind those source-owned runtime contexts and
the remaining full-map-reset services to actual constructed objects and authored
map content, then carry the phase changes through native spawn, combat, HUD and
network consumers. General weapons, objective engines, other editable rules and
session/Carnage Report return remain requirements of the all-variant goal.
This research changes no native admission gate and adds no playable variant.
