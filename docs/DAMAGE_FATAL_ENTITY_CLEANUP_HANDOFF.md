## Reached owner and exact calling convention

`A8840 → B1C90` is complete at **22 instructions**. It receives **EAX=full object datum**, takes no stack arguments, and has plain `RET`. It saves/restores EBX and ESI. It resolves the body through `*[4E78D0]+44`, twelve-byte header stride, using only the low sixteen bits for the index, while retaining the full datum in EBX. [Complete TU1.1 owner](../analysis/damage-shields-goal-20261011/live-fatal-cleanup/entity-research/paired/instructions/000a8840-old.asm), [complete pair report](../analysis/damage-shields-goal-20261011/live-fatal-cleanup/entity-research/paired/report.json).

If body DWORD`+D4 == FFFFFFFF`, the owner returns immediately. The comparison leaves EAX equal to that NONE value; there is no authored Boolean success result. Otherwise it calls **`B6810` with EAX=body[+D4]**, reloads the actual header/body address, calls **`10D010` with EBX=the full object datum**, then writes DWORD`body+D4=FFFFFFFF` and BYTE`body+D8=0`. These stores occur after the actual lower callbacks. Keeping the literal body refresh and lower ordering matters: this is not interchangeable with clearing two fields and manufacturing success. [Original CALL sites `A8866` and `A8877`](../analysis/damage-shields-goal-20261011/live-fatal-cleanup/entity-research/paired/instructions/000a8840-old.asm).

### BA980 source behavior and exact lower order

[`BA980 -> BBAC0`](../analysis/damage-shields-goal-20261011/live-fatal-cleanup/reached-ba980/paired/instructions/000ba980-old.asm), **80 instructions**, saves/restores EBP, ESI and EDI and keeps EBX as the full child datum. It resolves the child through the real `4E78D0` pool, twelve-byte header stride and low16 index, then immediately resolves **child body DWORD`+14` as the parent**. There is no NONE-parent early return. It retains the original parent body pointer, reads the signed child BYTE`+18` and signed parent WORD`+116`, and computes:

`attachment_matrix = parent_body + signedWORD(parent_body+116h) + signedBYTE(child_body+18h)*34h`.

This pointer is computed before the relationship is cleared. The real parent body, attachment index, node storage and posed matrix must exist. Filling NONE, installing an arbitrary identity matrix or treating an invalid signed index as zero would change the original precondition.

The exact calls/stores are:

1. `BAC10(EAX=parent)` walks actual parent links to the root and returns its header BYTE`+2 bit6`. Save this literal result. If true, call `BFE20(child,1,0,0,0)` before detaching.
2. `BA780(EAX=child)` removes the actual parent/list relationship. Then call `BA7D0(ESI=child, stack{saved_attachment_matrix})` to deliver the source transform.
3. If the saved root bit was true, call `B94F0(child,0)` after detaching. Independently, call `B9780(child)` unless child body BYTE`+C0 bit7` or the actual shifted header-type mask selects bit7.
4. Pass the **retained original parent** vectors to `B86C0`: ESI=child, EAX=`parent+94h`, stack `{parent+88h}`. Then `B8180(EDI=child)`, followed by `B8250(EAX=child)`.
5. Only after those actual lower calls, clear child body DWORD`+4 bit26` using mask `FBFFFFFF`. No Boolean success is authored or tested by the caller.

These original operations join attachment teardown, transforms, activation and velocity/world ownership. They cannot be reduced to clearing parent/index fields.
