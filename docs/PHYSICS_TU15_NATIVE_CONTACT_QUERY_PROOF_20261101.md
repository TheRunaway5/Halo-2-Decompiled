# TU1.5 native contact query and body eligibility

The later [native convex query composition](PHYSICS_TU15_NATIVE_CONVEX_CONTACT_QUERY_PROOF_20261101.md)
passes42 complete physical query cases per GCC/Clang across all seven protected
producer entries. Shape getters, cache initializers, geometry, centers, support
searches, encoding and `2F8630` are native; only actual `30E930` remains a service in that
qualified composition. This extends the component proof below without admitting
the full `304350` constructor lifetime or a production World binding.

`native_tu15_contact_query.cpp` contains semantic owners for actual `2E4FE0`
(256 sites) and `283380` (68 sites). The query consumes typed collision bodies,
retained result/cache data and an explicit relative-transform packet. It owns
motion detection, parent traversal, both source vector/scale paths, cache
refresh selection, temporary-setting restoration and final byte publication.
Native `2E4550` performs the relative transform. There is no guest register file,
instruction dispatch loop, supplied contact result or gameplay execution backend.

[Structured physical qualification](../analysis/physics/native-contact-query-prefixes-tu15-20261101-first/report.json)
passes 256 cases with GCC and Clang: 110 genuine cache-entry stops, 19 genuine
convex-query stops, 77 read faults, 25 rejected stores and 25 post-store observer
exceptions. It compares 11,167 ordered reads and 3,551 stores over 54,853 original
instructions. Both body-motion paths, true/false eligibility, parent chains,
class-5 cache selection, NaNs and the declared FP controls execute. All three
branch mutations are rejected. Two threshold-read prefixes retain a private
unbalanced x87 intermediate and remain explicitly excluded; they are not passes.

[Complete query/service composition](../analysis/physics/native-contact-query-ordered-tu15-20261101-native-eligibility/report.json)
passes twelve genuine-input/declared-input cases per compiler. Each compares
91,290,521 persistent bytes, the real result byte, an 80-byte contact packet,
88 retained query-data bytes, complete FP state and exact interleaved data
access/store ordering. Both compilers record 692 operand events and 2,816 original
instructions, two positive motion-vector paths, ten cache refreshes and twelve
real `2F8630` returns. Three state/restore/publication mutations are rejected.
Shape methods, cache initialization and the convex query remain genuine,
explicit dependencies in this composition.

Native `283380` independently passes
[108 physical cases](../analysis/physics/native-contact-body-eligibility-tu15-20261101-first/report.json)
under GCC and Clang: 81 full calls and 27 read-fault prefixes, 1,166 ordered reads
and 4,543 original instructions. Missing/duplicate body properties, the datum
sentinel, lower-sixteen-bit indexing, flags and parent-roster membership are
covered; all three mutations are rejected. The
[source-continuity receipt](../analysis/physics/native-contact-body-eligibility-tu15-20261101-first/source-function-continuity.json)
recovers both original compiled source hashes and verifies that the eligibility
function is byte-identical after the query began calling it directly.

The three successful validation runs removed 39,100,416, 297,111,552 and 18,866,176
allocated scratch bytes respectively. All nested builds and owner directories
are absent; no large artifacts were retained.

## Remaining integration

The complete native `304350` producer is not admitted for production yet. Its
later `303EE0` constructor reuses bytes that the original query/resolver left in
control storage. The query proof preserves explicit data and leaves those
unowned control bytes outside its contract. A source-owned constructor-data
lifetime must replace that dependency before binding the query under the full
producer. The protected raw producer failures remain red; no byte comparison
is waived and no captured postimage is installed.

Native cache initialization/convex-service closure, the two private threshold
resume prefixes, complete producer integration and visible multiplayer
acceptance remain separate open gates.
