# Original King replication packet orchestration

Research snapshot: 2026-10-12. The original caller policy separates entity decoding, aggregate application, and final network acceptance. A successful King slot15 reader is necessary for a present update, but **the aggregate does not check stream overflow/error before applying decoded blocks**. The network owner checks those conditions after its client readers return. A native implementation must preserve that ordering explicitly; neither a decoder return nor a final packet rejection is proof that nothing was applied. This is static original-instruction evidence, not an executed packet or native admission. [Aggregate instructions](../analysis/multiplayer/game-variants/king-replication-orchestration-source-20261012/complete/retail-aggregate_decode_apply-00097d80.asm), [network instructions](../analysis/multiplayer/game-variants/king-replication-orchestration-source-20261012/complete/retail-network_packet_read-00088750.asm).

## Actual tables and live wiring

The outer entity replication interface begins at **retail `450D60`**, TU1.1 `457EE8`, TU1.5 `45CA28`. The reconstructed source comment naming `450D4C` includes a preceding, separate five-entry interface. Using that address as the entity replication table displaces every method. The real interface's slots1/2/6/7 are creation decode, creation application, update decode and update application. These are distinct from the King entity-definition slots15/22/23 and the registered King game-engine slots44–46. [Literal tables and constructor operands](../analysis/multiplayer/game-variants/king-replication-orchestration-source-20261012/complete/report.json), [allocation instructions](../analysis/multiplayer/game-variants/king-replication-orchestration-source-20261012/complete/retail-distribution_allocation-00081780.asm).

The storage constructor writes aggregate vtable `450CF4` at storage+4 and handle-child vtable `450CD0` at storage+30. The aggregate's slot5 is `97D80`; the handle child's slots5/6 are `98CF0`/`98FB0`. World setup writes distribution+2098 into the peer table's owner pointer, and the view setup installs the handle child at aggregate child1, between event child0 and player-input child2. It registers that aggregate as a connection client. Thus the connection reader's virtual+14 reaches this aggregate, and the aggregate's virtual+14/+18 reaches actual child decoding/application. Corresponding literal tables and writes are checked for both updates. ## Creation decoding

Creation reads a five-bit entity type and fetches its handler. A null handler returns status3. There is no comparison against the handler-table count in this body. It queries creation-data and state sizes, allocates creation data only for a positive size, and allocates the state through the real global allocator wrapper. Allocation failure sets status2. The allocator path invokes virtual+14 allocation, virtual+28 compaction and a second virtual+14 attempt; no successful allocation is supplied by this research. [Complete creation decoder](../analysis/multiplayer/game-variants/king-replication-orchestration-source-20261012/complete/retail-entry_creation_decode-0008a6f0.asm).

With backing available, it zeroes creation data when needed, requires entity slot13 AL, then requires slot19 AL to initialize the state bank. For King, slot19 reaches registered engine slot44 through the previously recovered dispatcher. It obtains the entity's allowed update mask through slot5 and starts a local read mask at0. If the allowed mask is0, or the outer state-presence bit is false, creation decoding succeeds with read mask0 without invoking slot15. Otherwise it invokes slot15 with first argument1, requires AL=true, then rejects any returned mask outside the allowed mask. The King allowed mask is7F. [Creation decoder](../analysis/multiplayer/game-variants/king-replication-orchestration-source-20261012/complete/retail-entry_creation_decode-0008a6f0.asm), [King registration and dispatcher evidence](MP_KING_REPLICATION_SOURCE_RESEARCH.md).

Success writes type/read-mask outputs and appends two typed records, C then D, incrementing the caller's produced count by2. Decoder failure frees the private allocations and returns3; it does not restore the bitstream cursor or the decoder's attempted writes. It does not inspect stream.error or call the overflow predicate. The absent outer state-presence branch therefore differs from a present slot15 payload whose own seven presence fields are all absent: the latter returns false and this caller rejects it. [Creation decoder](../analysis/multiplayer/game-variants/king-replication-orchestration-source-20261012/complete/retail-entry_creation_decode-0008a6f0.asm), [original King reader contract](MP_KING_WIRE_SOURCE_RESEARCH.md).

## Update decoding and the private bank

Update decode first rejects id=NONE, then indexes `id&3FF` and requires the row's full identifier to equal the supplied identifier. It fetches the handler from the existing row type and allocates a new bank of exactly the existing row state size. No row+06 creation-success gate occurs here. Allocation failure returns3. [Retail update decoder](../analysis/multiplayer/game-variants/king-replication-orchestration-source-20261012/complete/retail-entry_update_decode-0008aac0.asm), [Xbox1.5 update decoder](../analysis/multiplayer/game-variants/king-replication-orchestration-source-20261012/complete/u5-entry_update_decode-0008e8f0.asm).

For stream.mode4, it zeroes the private bank and requires slot19 initialization to succeed. For other modes it copies the entire existing live state bank into the private allocation. Thus absent fields in an ordinary update preserve the prior bank bytes; absent fields in mode4 start from original initialization. It initializes a local read mask0 and calls entity slot15 with first argument0, the mask pointer, state size, private bank and stream. Slot15 AL=false frees that bank and returns3. AL=true writes the caller's read-mask output and appends one typeD record, incrementing produced count. There is no additional allowed-mask or overflow/error check in this body. The existing live bank is untouched by this decoder. [Complete decoder](../analysis/multiplayer/game-variants/king-replication-orchestration-source-20261012/complete/u5-entry_update_decode-0008e8f0.asm).

The King reader itself can write part of a private bank, replace its read-mask output and advance the cursor before returning false; the failure path frees those attempted values rather than applying them. This is the caller-owned containment boundary. It does not make the bitstream primitive transactional. [King wire reader](MP_KING_WIRE_SOURCE_RESEARCH.md), [failure/free branch](../analysis/multiplayer/game-variants/king-replication-orchestration-source-20261012/complete/retail-entry_update_decode-0008aac0.asm).

## Handle framing and aggregate application

The handle decoder reads three-bit kinds:0 terminates;1 creates one entity;2 deletes one;3 creates a group;4 deletes a group;5 updates one. Kinds≥6 return3. Group count is the next two bits+2 and must be≤4; the value producing5 is rejected. Each identifier is ten low index bits plus four salt bits shifted to28. Update kind5 requires the sender child's row to hold the same full identifier and state3 **before** calling the entity update decoder; a mismatch yields2. Creation kinds1/3 call the creation decoder. Failed nested decoding frees the current block's produced allocations and stops; prior successfully decoded blocks remain in the output count for aggregate cleanup. Maximum aggregate blocks is256. [Handle decoder and literal dispatch table](../analysis/multiplayer/game-variants/king-replication-orchestration-source-20261012/complete/retail-handle_blocks_decode-00098cf0.asm), [manifest switch bytes](../analysis/multiplayer/game-variants/king-replication-orchestration-source-20261012/complete/report.json).

Each decoded handle block is80 hex bytes: kind+00, first identifier+04, count+08, up to four identifiers+0C, four entity types+1C, four decoded masks+2C, produced typed-record count+3C, and eight typed records+40. The actual reader fills these fields; the update application path consumes the recorded mask at+2C and typeD pointer from+40. [Handle decoder](../analysis/multiplayer/game-variants/king-replication-orchestration-source-20261012/complete/retail-handle_blocks_decode-00098cf0.asm), [handle application](../analysis/multiplayer/game-variants/king-replication-orchestration-source-20261012/complete/retail-handle_block_apply-00098fb0.asm).

The aggregate iterates its three child pointers, recording each child's start/end output range. Once a child returns nonzero status, it skips subsequent child decoding. It applies **no blocks** unless the accumulated decode status is0 and stream.mode is not4. On that gate, it applies each child's complete range in child order and block order via virtual+18. Afterward it frees every remaining typed allocation in every produced block, including on decoding failure or mode4. Creation application transfers ownership by clearing its typed records; update application leaves the private allocation for aggregate cleanup. [Aggregate](../analysis/multiplayer/game-variants/king-replication-orchestration-source-20261012/complete/retail-aggregate_decode_apply-00097d80.asm), [creation application](../analysis/multiplayer/game-variants/king-replication-orchestration-source-20261012/complete/retail-entry_creation_apply-0008a920.asm), [update application](../analysis/multiplayer/game-variants/king-replication-orchestration-source-20261012/complete/retail-entry_update_apply-0008ac40.asm).

No cursor/capacity/error predicate is evaluated between successful child decoding and that application loop. The aggregate's returned status remains the child-decoder status; a void block application can decline an identity transition or store a false creation result without changing it. This is not an all-or-nothing game-state transaction. [Aggregate control flow](../analysis/multiplayer/game-variants/king-replication-orchestration-source-20261012/complete/u5-aggregate_decode_apply-000a1dc0.asm), [handle block control flow](../analysis/multiplayer/game-variants/king-replication-orchestration-source-20261012/complete/u5-handle_block_apply-000a2ff0.asm).

## Identity admission and live application

For creation kinds1/3, the handle application preflights each new identifier through the real creation identity owner. An unused child row (state0) is accepted. For an occupied row it computes `d=new_salt-old_salt+16; if(d>8) d-=16`, then accepts only `0<=d<4 || d<=-4`. This literal asymmetric branch must not be replaced with a guessed monotonic/full-datum rule. On acceptance it calls the peer owner's virtual+2C notification and releases the old entity or its actual chain through the real state transition/release owners. The peer flags decide single/head/member handling. A failed preflight prevents creation for that block; successful earlier preflights may already have performed cleanup. [Identity owner](../analysis/multiplayer/game-variants/king-replication-orchestration-source-20261012/complete/retail-creation_identity_admission-000991d0.asm), [handle application](../analysis/multiplayer/game-variants/king-replication-orchestration-source-20261012/complete/retail-handle_block_apply-00098fb0.asm), [real release owner](../analysis/multiplayer/game-variants/king-replication-orchestration-source-20261012/complete/retail-peer_release-00089660.asm).

For a single admitted creation it writes peer flags1, the incoming salt nibble and a zero peer mask, then calls the entity creation owner. The owner adopts C/D allocation pointers and sizes, clears the source typed records, initializes the row id/type/creation flag/dirty masks/context, and calls entity slot22 with the decoded mask and adopted bank. It normalizes the returned AL into row+06. The actual King slot22 first checks the selected engine's entity type, publishes the row id into MP+24, and invokes registered engine slot46 only for a nonzero decoded mask. Its engine apply AL is ignored after that type match. [Handle application](../analysis/multiplayer/game-variants/king-replication-orchestration-source-20261012/complete/retail-handle_block_apply-00098fb0.asm), [Xbox1.5 adoption stores](../analysis/multiplayer/game-variants/king-replication-orchestration-source-20261012/complete/u5-entry_creation_apply-0008e750.asm), [King creation dispatcher](../analysis/multiplayer/game-variants/king-replication-orchestration-source-20261012/complete/u5-entity_creation_dispatch-000aea90.asm).

For update kind5 the handle application calls the entity update owner directly with block id, mask, typed count and typed records. It does **not** repeat the decode-time full identifier/state3 gate. The entry owner also indexes only the low ten bits without checking full identity or row+06. It copies exactly the existing live row's state size from the typeD pointer at typed_record+4 into the live bank **before** invoking entity slot23. The decoded mask is forwarded unchanged. Slot23 AL is ignored, and there is no rollback of the bank copy if the selected engine/type dispatcher declines or engine application returns false. Earlier blocks in the same accepted aggregate run first; this research does not add an apply-time identity recheck that the source does not contain. [Handle update branch](../analysis/multiplayer/game-variants/king-replication-orchestration-source-20261012/complete/u5-handle_block_apply-000a2ff0.asm), [Xbox1.5 live bank copy/application](../analysis/multiplayer/game-variants/king-replication-orchestration-source-20261012/complete/u5-entry_update_apply-0008ea70.asm), [entity slot23 dispatcher](../analysis/multiplayer/game-variants/king-replication-orchestration-source-20261012/complete/u5-entity_apply_dispatch-000ae940.asm).

Entity slot25 and slot24 separately own match-id adoption/release: adoption writes MP+24 on the selected-engine/entity-type match, while release clears it only when the current match id equals the released row's full id. The ordinary update slot23 dispatcher selects the live engine by MP+C14 and compares its source entity type with the entity definition before invoking engine slot46; it does not additionally compare MP+24 to this row. These are distinct identity services and should not be merged into one guessed validity predicate. [Adoption](../analysis/multiplayer/game-variants/king-replication-orchestration-source-20261012/complete/u5-entity_adopt_identity-000ae9b0.asm), [release](../analysis/multiplayer/game-variants/king-replication-orchestration-source-20261012/complete/u5-entity_release_identity-000aeb20.asm), [apply dispatcher](../analysis/multiplayer/game-variants/king-replication-orchestration-source-20261012/complete/u5-entity_apply_dispatch-000ae940.asm).

## Final network acceptance comes afterward

The connection owner initializes ordinary incoming streams to mode3, cursor0 and error=false; it performs the original four-byte debug-marker probe and restores cursor0 for an ordinary marker. It then iterates connection clients and calls each client's reader at virtual+14, stopping on a nonzero integer status. The registered aggregate runs here. Only afterward does the owner parse the optional extra payload, and evaluate `cursor > 8*size_bytes || error`. Either condition forces status3. Equality of cursor and capacity is not overflow. [Network reader](../analysis/multiplayer/game-variants/king-replication-orchestration-source-20261012/complete/retail-network_packet_read-00088750.asm), [original overflow primitive](../analysis/multiplayer/game-variants/king-replication-orchestration-source-20261012/complete/retail-stream_overflowed-001946f0.asm).

Final status0 succeeds; status1 also succeeds after moving the cursor to the declared end; both set stream.mode5. Status2/3 return false. Reliable receive acknowledgement and queued message dispatch occur only on the successful ordinary-packet branch. The owner has no undo loop for aggregate game-state application that happened earlier. The late error check can therefore reject a packet after an earlier client has applied blocks; a concrete malformed-packet execution still requires actual allocator/client contexts and is not claimed by this static trace. [Final status switch and callbacks](../analysis/multiplayer/game-variants/king-replication-orchestration-source-20261012/complete/u5-network_packet_read-0008c550.asm).

## Dirty-mask production and distribution

King's world update publishes mask40 after an occupants change and mask20 after a selected hill change through the match wrapper. The wrapper requires a nonnull selected engine and MP+24!=NONE before calling the dirty publisher with that full replication id. It does not itself verify the entity row salt or type. [Actual King update](../analysis/multiplayer/game-variants/king-replication-orchestration-source-20261012/complete/u5-king_world_update-002c7490.asm), [match wrapper](../analysis/multiplayer/game-variants/king-replication-orchestration-source-20261012/complete/u5-match_dirty_publication-000b1a10.asm).

The dirty publisher reads the actual world pointer, requires world.state4 through its literal state gates, indexes id&3FF, requires `(peer.flags & 0x04)!=0`, and ORs the requested mask into entity row+0C. It does not validate the row's full id against the caller, and does not clear unsupported King mask bits here. The full-id/selected-entity context belongs to the caller and the later difference/codec owners. The publisher's relocated world pointers are retail `4CF77C`, TU1.1 `4D6D44`, TU1.5 `4DC04C`. [Retail publisher](../analysis/multiplayer/game-variants/king-replication-orchestration-source-20261012/complete/retail-dirty_mask_publication-000b58c0.asm), [TU publisher](../analysis/multiplayer/game-variants/king-replication-orchestration-source-20261012/complete/tu11-dirty_mask_publication-000b6760.asm), [Xbox1.5 publisher](../analysis/multiplayer/game-variants/king-replication-orchestration-source-20261012/complete/u5-dirty_mask_publication-000b7e50.asm).

Flush visits all1024 rows. A row must have id!=NONE and requested mask+0C!=0. If row+06 is true, it calls entity slot20 with a local copy of that requested mask and the persistent bank. For King this reaches original engine slot45, which replaces the mask with actual differences while updating the bank. On slot20 AL=true, retail publishes only that returned mask if nonzero. **TU1.1/TU1.5 instead OR the returned mask with row+10 before the nonzero test and publication.** Both updates then clear row+0C and row+10; retail clears row+0C. Clearing also happens when row+06 is false or the difference callback returns false. A secondary mask alone, with requested mask0, does not enter this flush path. [Retail flush](../analysis/multiplayer/game-variants/king-replication-orchestration-source-20261012/complete/retail-entry_flush_differences-0008a090.asm), [TU flush](../analysis/multiplayer/game-variants/king-replication-orchestration-source-20261012/complete/tu11-entry_flush_differences-0008ac40.asm), [difference dispatcher](../analysis/multiplayer/game-variants/king-replication-orchestration-source-20261012/complete/u5-entity_difference_dispatch-000ae860.asm).

The peer publication owner visits the up to15 attached sender tables and ORs the mask into each indexed sender row's pending mask+04. For state3 with no matching sender bit in the peer ownership mask and a previously zero pending mask, it also increments that sender's pending-update counter+5034. No full-id comparison is added here. This establishes actual dirty storage and distribution, not native UDP serialization or reliable delivery. [Pending-mask publication](../analysis/multiplayer/game-variants/king-replication-orchestration-source-20261012/complete/retail-peer_pending_mask_publication-00089710.asm).

The periodic caller invokes flush only when network initialization is enabled, the suppression byte is false, a world/options context exists, options+1120 is true and the same literal world-state4 gate passes. It calls flush before the subsequent network receive/pump owners in that routine. The TU1.5 caller moved to `6EDF0`; its complete normalized body still matches TU1.1 `8EAC0` and retail `8DFC0`. This caller is source sequencing evidence, not a complete native session tick. [Retail caller](../analysis/multiplayer/game-variants/king-replication-orchestration-source-20261012/complete/retail-periodic_flush_caller-0008dfc0.asm), [Xbox1.5 caller](../analysis/multiplayer/game-variants/king-replication-orchestration-source-20261012/complete/u5-periodic_flush_caller-0006edf0.asm).
