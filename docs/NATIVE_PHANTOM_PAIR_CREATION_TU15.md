# Native phantom pair creation and insertion

The native world now selects semantic `31FFC0`, `315B00`, `315300` and
`314F80` implementations for supported phantom creation. Array insertion uses
the existing native `2E3250` allocator/storage owners. Unknown added-listener
owners remain explicit refusals; component proof does not establish live
vehicle acceptance or complete destruction/audio parity.

The original is English Xbox TU1.5 `default.xbe`, SHA-256
`21b207e7efdacaf6124a0822837f8be570766a42505057f7fd2d2ba8f409c4fd`.
All original executions below use its unchanged instructions. MCC supplies
runtime content, rather than the behavior authority.

`31FFC0` checks both current collidable type words for type2. It rereads the
second pair word/type after the first callback. It passes the other payload
and an ordinary four-byte notification argument to phantom virtual1C. The
source pushes the current phantom pointer, then clears only that argument's
low byte. The native parent preserves its full value, `phantom & FFFFFF00`,
until the actual child consumes the low byte. It supplies no overlap result.

`315B00` skips an other-payload whose shape word is null; `315300` has no such
guard. With a nonzero input flag byte, both search their current overlap
array for a duplicate. Their native notification constructs the source's
phantom, other, was-present and decision fields, then visits listeners in
reverse. It retains the initial reverse index and rereads the listener backing
after each callback. Actual listeners own decision changes. After notification,
both parents reread current capacity/count and use genuine native growth when
full. The complex append stores count before the new element. The simple
append stores the element first, then rereads and increments the count.

The [parent proof](../build/test-results/vehicle-destruction-phantom-create-native-20261101/parent-observation/report.json)
passes39 physical original cases under GCC and Clang:231 ordered reads,
21 authentic `8FDB0 RET8` component callbacks, eight fault prefixes, two
unbound-owner prefixes and four callback input mutations. Four controls reject
wrong type selection, skipping the second pair, the wrong other payload and
zeroing the complete notification argument. These cases execute43 of the
parent's54 sites; the null-payload branches are not qualified by this corpus.
The callback is a declared
component service using a genuine original return leaf; it is not a claim
that an actual gameplay phantom uses that vtable slot.

The [insertion proof](../build/test-results/vehicle-destruction-phantom-create-native-20261101/overlap-observation/report.json)
passes85 cases under both compilers. It executes all55/54/33 original sites
in `315B00`/`315300`/`314F80`, all46 sites in native growth's original owner,
and the complete14-site forward copy. The allocator starts from authenticated
original initialized pool inputs and allocates/releases independently on both
sides; no returned pointer or allocator postimage is supplied to native code.
Each compiler compares458 ordered stores,919 ordered reads and264 private
event field snapshots, plus the persistent banks. There are18 fault-state
prefixes and15 declared callback input mutations. Duplicate detection, both
append orders, listener direction, decision consumption and growth controls
all reject their deliberately wrong implementation.

Two test boundaries are explicit. The notification's13 initialized event bytes
are compared at its actual `314FCF` return, while persistent state is compared
at parent completion. The original later allocator reuses that dead call-stack
space:16 raw final-bank differences per compiler remain recorded in the CTest
receipts. Padding bytes9..B are neither initialized nor supplied as an expected
value. One synthetic fault stops the original before the whole `INC [count]`
instruction, while the native memory interface fails its write after the
required count read. Its stores, persistent state and FP match, but the extra
native read is an explicitly unmatched artificial-fault trace. The strict
[failure](../build/test-results/vehicle-destruction-phantom-create-native-20261101/overlap-component-v3/compiler-0/tests.log)
is retained; it is not turned into an invented original read.

The [type proof](../build/test-results/vehicle-destruction-phantom-create-native-20261101/types-component-v4/report.json)
also verifies nine native literal getter owners, including

The helper derives all supported owner identities from the native table, then

All compiler/probe/reference banks in these component runs belonged to

## Selected native gameplay and remaining factory

The [observed gameplay cohort](../build/test-results/vehicle-destruction-phantom-live-20261101/live-summary.json)
passes the power module, Banshee, Wraith and Gauss Warthog. Including the module's
real pending cut, these cases pass80 complete-world comparisons. Gauss Warthog
executes one native phantom pair, one simple overlap notification and one append.
Spectre executes two of each before its later failure. This proves actual
selection of those native paths; complex insertion and growth retain component
proof only in this cohort. No source outcome is supplied by the counters.

Warthog, Ghost, Scorpion and Spectre remain red at factory `2F8030`. Their
original death-bit stores do not qualify their later wreck/continuation path.
The fixture remains muted and provides no audible or framebuffer acceptance.

An actual typed Warthog factory BEFORE has now been captured without changing
source memory or returning a result. The [required input receipt](../analysis/physics/native-list-contact-agent-20261101-required-before/destruction-warthog/retention.json)
retains `actual-native-before.tar.zst`,12,470,906 bytes, SHA-256
`3889dc619e0bdbae5f5e91622057624bbca5fb1b18ea7183159ea5435403804b`.
Its90,002,691 raw bank bytes and manifest were all verified after compression.
It is required for the next factory/constructor implementation, rather than
a runtime/build product or expected postimage. No original GP/SIMD ABI was
captured. Actual input has x87 depth0, CW`027F`, SW`0022`, MXCSR`1FA0`.

The [authenticated source and input inspection](../build/test-results/vehicle-destruction-phantom-live-20261101/factory-before-research.json)
establishes the next contract. Factory `2F8030` allocates40 bytes/class1A,
publishes size`28`, then reads its four cdecl inputs in order4/3/2/1 before
calling constructor `2F7D20`. The constructor stores user data at object+8,
vtable`41CCC8`, and an inline child-agent vector at+C/+10/+14 with capacity
`80000004` and backing at+18. It obtains the current first shape's child count
through virtual28; this input selects `3061F0`, whose complete source is
`MOV EAX,[ECX+10]; RET`. Its actual count is2.

For each child, the original initializes four payload words: child shape,
index, the first payload's+8 word, and the original first-payload identity.
The child filter receives a byte-result address, context, second payload,
original first payload, collection and child index. The current filter owner
is `1CBE70`; it must perform genuine filtering. The constructor caches the
dispatcher before class calls, rereads current child-array backing at its
source phases, and retains the chosen destination across real child creation.
An excluded child uses the authenticated `30BAD0` sentinel owner. These are
static source/dataflow facts, not completed native constructor behavior.

The source exception tables are also pinned. Constructor FuncInfo`46BAE0`
unwinds state1 through array cleanup`2E15C0`, then state0 through base cleanup
`2F7A10`. Factory FuncInfo`46BB70` owns storage release`2F0380`. No FS chain or
unwind outcome is invented. The [dependency listing](../build/test-results/vehicle-destruction-phantom-live-20261101/factory-dependencies-static.json)
records the complete original child-count, child-filter and array-cleanup
bodies. Full original execution and native implementation of `2F8030/2F7D20`
remain required.
