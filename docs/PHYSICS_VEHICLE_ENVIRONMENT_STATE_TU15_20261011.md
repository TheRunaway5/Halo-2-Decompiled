Recovery reads only the owned English TU1.5 executable, pinned to
`21b207e7efdacaf6124a0822837f8be570766a42505057f7fd2d2ba8f409c4fd`.
Every new instruction/store ID is an actual TU1.5 address. The three original
tables are recovered with their exact widths, counts and bytes. Generated
C++ statically lowers all bodies and dispatch targets; it executes no original
code and contains no runtime opcode decoder. The TU1.5-only API is
`source_run_physics_vehicle_environment_state_runtime`.

The bounded corpus has 16,381 original cases, including 1,240 new environment
and retirement inputs. It covers plane/portal queries, signed packed leaves,
optional outputs, category fallback, cluster chains, three dispatch tables,
pool bit iteration, clearing/poisoning, object generation/type checks, force
detachment/retirement, scalar delivery, adjacent list links/endpoints and pose
aliasing with either input. SSE paths include four rounding modes; retained
parent FP paths preserve their existing x87 C1 checks and full FP state.

The environment tree, portals, clusters, tag definitions, pools and linked
records are explicitly declared inputs. Original and native code compute
their own query results, slots, stores and matrices. Force and reference pools
are distinct. Force records have their full cleanup extent; composed callers
can retire them and update the real occupancy/list state. Parent vehicle cases
retain their authored definitions. No query, solver, activation or successful
retirement result is supplied by a fixture callback.

13,942 calls return and 2,439 stop at actual required owners. The corpus
exercises 1,226 of the 1,307 new sites. All 432 independently computed
builder-to-motion cases return; their declared component still lacks a vehicle
solver object and constraint list. These cases do not establish suspension,
solved world contacts or driving.

The diagnostic emulator discovers original memory footprints. Final parity
comparison uses unchanged original TU1.5 bytes single-stepped on the host's
Linux i386 x87/SSE backend. Test-only capture stubs preserve the reached ABI
at deeper owners and provide no return. Native comparisons check instruction

retained memory and missing-owner rejection. The validator requires repeated
recovery, generation, original diagnostic/hardware evidence and successful
