# Native TU1.5 solver composition proof

Both compositions use the authenticated English retail TU1.5 executable
`21b207e7efdacaf6124a0822837f8be570766a42505057f7fd2d2ba8f409c4fd`.
The unchanged original instructions run as a physical i386 process. Native
kernels execute separately from the same declared input banks. No ready byte,
solver return, accumulator output or committed velocity is supplied as a
dependency outcome.

The ready-zero `326A40` composition invokes the native `3268D0` initializer
and native client hash before the typed row solver. Its 103 original cases
cover 28 complete calls, 73 read-fault prefixes, two actual logger entry stops,
21 genuine clock returns and all twelve primary row families. Both GCC and
Clang pass 9,811 ordered reads, 1,388 ordered stores, retained bank bytes and
complete FP control/status comparisons. The original executed 1,734,709
instructions. Changing the native hash mixing seed or dropping FP status
across initialization fails the independent original comparison. The clock
input comes from the real host clock through the declared integer FILETIME
import; the original computes its seconds return. Private client-key text is
never printed.

The complete `326200` composition starts at the original root arguments and
banks. Its native side runs the orchestrator, actual fixed/kinematic or dynamic
accumulator setup, the complete typed `326A40` solver and all three native
motion commit owners. Its 424 cases cover 87 complete original calls and 337
read-fault prefixes on both GCC and Clang. Changing the native status-one
commit traversal to status two fails the original store comparison. These
declared cases contain zero constraint builders and zero solver iterations;
positive row math is independently covered by the 3,000-case solver proof.
This composition closes the whole call-boundary proof for those declared
inputs, without treating builder execution, positive-iteration full-root
composition or visible multiplayer as covered.

The bounded reports, exact commands, original listing hashes, source pins and
negative-control results are retained in:

- `build/test-results/native-constraint-solver-initialized-composition-tu15/`
- `build/test-results/native-constraint-full-composition-tu15/`

The 6,266,024-byte ready-zero fixture and the 165,795,810-byte full-root fixture,
reference executables, copied private banks, source overlays and both compiler
build trees were removed by their owned test lifecycles. Each report directory
contains a cleanup receipt confirming that its owner no longer exists. No
large artifacts are retained by these component proofs.

The aggregate native clock/initializer/custom-schema composition adds all
twelve primary row families with all three actual built-in custom callbacks
before and after the row block. Both compilers pass 143 original cases:
88 full roots and 55 read-fault prefixes. Four full roots consume genuine raw
FILETIME input through the new native clock arithmetic; no original seconds
output is supplied to native initialization. The current report is
`build/test-results/native-constraint-solver-native-clock-composition-tu15/`.
It retains source pins and a negative callback operand-order control. Its
fixture and all private original/compiler products were removed; see its
cleanup receipt. Actual constraint producers, world input receipt integration
and visible multiplayer remain separate evidence gates.
