# Live producers for the shared shield/transparent command bank

Research snapshot: 2026-10-11. This continues [the scheduling report](SHIELD_OVERLAY_SCHEDULING_RESEARCH.md). The required integration is one source-ordered collector bank, followed by one shared transparent allocation/suffix owner and its callback consumer. Sorting only new shield draws cannot preserve the original ordering or capacity pressure from the other live producers. No implementation was edited for this investigation.

The authority is unchanged [retail default.xbe](../assets/disc/default.xbe), SHA-256 `03215919bb7163259257d361f4c7bf802a7ab12aa85e2689436369b5c427935d`. The retained [manifest](../analysis/damage-shields-goal-20261011/overlay-pass/live-producers/source-evidence.json) identifies every instruction-body hash and the concurrent native source snapshot. The [extractor](../analysis/damage-shields-goal-20261011/overlay-pass/live-producers/extract.py) records 36 requested entries, of which two have no matching retail inventory entry: `175EA0` and `1E4C0`. Those names occur in native particle comments and other-build research; they are **not** established retail counterparts in this note. The actual retail path below is `174420→1E4E0`.

## Original assembly order and the two banks

There are two different allocations. `2CBF0` appends a **32-byte render-cache/collector record** to `4BA138`, with counter `4C0B78` and normal-view prefix `4C0B7C`; its upper bound is `0x352`. Much later, `41040` can append a **112-byte transparent callback record** through `1E2D0`, with counter `4B6280`, suffix start `4B6284`, and capacity 1024. A native service must retain the collector ordinal before it can construct the transparent callback payload. Flattened vertices or material keys do not retain this identity. [2CBF0 instructions](../analysis/damage-shields-goal-20261011/overlay-pass/live-producers/0002cbf0-retail.asm), [41040 instructions](../analysis/damage-shields-goal-20261011/overlay-pass/scheduling/00041040-retail.asm).

`2CBC0` calls, in this exact order:

1. `2CB30` resets normal render-cache counts, the override-datum bank and the 31-entry section/group bank when context `+2A78==0`. Other modes retain `4C0B7C` and start the second render-cache portion there.
2. `133390` traverses the admitted cluster list at context `+0C` in its existing ordinal order and calls `2CBF0` per accepted cluster.
3. `133520` traverses the admitted instance list at context `+18` in its existing ordinal order, computes the original coverage/alpha, and calls `2CBF0` only for positive alpha. The source also changes the input admission flags when alpha is zero.
4. `133720` prepares and traverses the admitted object list at context `+14`, invoking `133790` for each ordinal. Its special mode-1 retry remains a separate branch.

These are original instructions, not a proposed order by native scene category. [2CBC0](../analysis/damage-shields-goal-20261011/overlay-pass/live-producers/0002cbc0-retail.asm), [2CB30](../analysis/damage-shields-goal-20261011/overlay-pass/live-producers/0002cb30-retail.asm), [133390](../analysis/damage-shields-goal-20261011/overlay-pass/live-producers/00133390-retail.asm), [133520](../analysis/damage-shields-goal-20261011/overlay-pass/live-producers/00133520-retail.asm), [133720](../analysis/damage-shields-goal-20261011/overlay-pass/live-producers/00133720-retail.asm).

Before the first object collector, `133720` calls `134240`. This scans full handles, resolves `object.definition→definition+38→hlmt+4→mode`, and tests the signed dword **`mode+74 > 0`**. Each qualifying object is swapped into the next prefix position. `163D50` swaps all four parallel fields: list `+08` 16-bit flags, `+0C` full handles, `+10` dwords and `+14` 16-bit association fields. The positive prefix retains encounter order; the remainder need not retain encounter order. For example, positive positions 1 and 3 in five objects yield `[1,3,2,0,4]`. The generated decompile calls this “model has nodes,” while the native Xbox cache parser reads `mode+74` as the PRT bank count. Preserve the raw criterion; the decompile's descriptive label is not sufficient evidence to replace it with `bones.empty()`. [134240](../analysis/damage-shields-goal-20261011/overlay-pass/live-producers/00134240-retail.asm), [163D50](../analysis/damage-shields-goal-20261011/overlay-pass/live-producers/00163d50-retail.asm), [native parser](../src/source_prt.cpp).

`133790` reads each owner's cached `object+30/+3C` sphere and computes the separate geometry-distance and shader-coverage inputs. After `4B5D0` resolves its actual model/region/pose/lighting collector, `133AB0` expands that collector. This is where ordinary body collectors, shield/overshield override clones, grouped variants, and attached children enter the render-cache bank. **They are not separate entries returned by `SourceObjectAdmission`.** First-person collectors are appended by the separate first-person source owner described in the scheduling report; the ordinary object queue does not contain the FP clones. [133790](../analysis/damage-shields-goal-20261011/overlay-pass/live-producers/00133790-retail.asm), [133AB0](../analysis/damage-shields-goal-20261011/overlay-pass/live-producers/00133ab0-retail.asm).

Within `133AB0`, the tested `collector+170` branches occur in instruction order `80`, `02`, `01`, `20`, then the remaining ordinary collector, followed by children. The `01` and `20` branches copy the complete collector, OR `8000` into the copy's `+1AC` command flags and copy their respective override datum. The flags, copied group state and skip-base decision must travel with each copy. The child walk starts at the object's `+10` first-child handle and advances through each child's `+0C` sibling handle; it does not sort by model/material/weapon type. Root coverage `+1B4` survives the copy. Children with the source weapon/group exception can clear inherited group state. The prior selector evidence establishes the meaning of the shield references; this new instruction audit establishes their assembly location and order. [133AB0, `133AC0..133F58`](../analysis/damage-shields-goal-20261011/overlay-pass/live-producers/00133ab0-retail.asm).

`133F70` iterates the collector's model banks (`+166` count) in bank order, then each bank's selected region/section entries in their existing order, calling `2CBF0` per entry. `2CBF0` retains the chosen section/geometry/model fields, group ordinal/kind, coverage byte, depth-bias nibble, current pose/lighting context, and override-bank index. The source collector can contain duplicate section selections; deduplicating by `(material,section,part)` loses valid source ordinals. [133F70](../analysis/damage-shields-goal-20261011/overlay-pass/live-producers/00133f70-retail.asm), [2CBF0](../analysis/damage-shields-goal-20261011/overlay-pass/live-producers/0002cbf0-retail.asm), [native ordered collector helper](../include/halo2/source_transparent_parts.hpp).

## When ordinary model, particle and group commands are allocated

Normal `40E90` resets the transparent count/suffix start, calls `41C80` for object attachment effects, then calls **`44AC0(view0, requested_mask, group31)`** over the completed render-cache bank. This visits clusters, instances, object clones and children in the bank order above. `41C80` is not a second model collector: its `41C20` recursive object walk and `41980` attachment dispatch process lens/light-volume/trail services before `44AC0`. [40E90](../analysis/damage-shields-goal-20261011/overlay-pass/live-producers/00040e90-retail.asm), [41C80](../analysis/damage-shields-goal-20261011/overlay-pass/live-producers/00041c80-retail.asm), [41C20](../analysis/damage-shields-goal-20261011/overlay-pass/live-producers/00041c20-retail.asm), [41980](../analysis/damage-shields-goal-20261011/overlay-pass/live-producers/00041980-retail.asm).

`44AC0` first separates cache records with flag `400` into the source FP/deferred bank. For other records it requires the requested low-21-bit mask, matching sort-section ordinal, flag bit0 and positive byte `+1A`. It resolves the original resident part bank, then runs **part ordinal order** through `45CE0` geometry, `460D0` visibility and `41040` shader/regular/transparent admission. The per-record override datum is applied before `41040`; this includes the actual shield overrides. The source partial-subpart mask must participate even when the material and shader LOD are supported. [44AC0](../analysis/damage-shields-goal-20261011/overlay-pass/live-producers/00044ac0-retail.asm), [45CE0](../analysis/damage-shields-goal-20261011/overlay-pass/scheduling/00045ce0-retail.asm), [460D0](../analysis/damage-shields-goal-20261011/overlay-pass/scheduling/000460d0-retail.asm).

After the ordinary `44AC0` traversal, normal non-editor `40E90` calls `176BB0` for effect attachments, **`174220(0)` for particle systems**, `420A0` for kind-1 section groups, `42760(requested_mask)` for kind-3 section groups, then tail-calls `41640` for decals. `41640` adds regular shader commands through `40E30`; it does not itself allocate a transparent callback via `1E2D0/1E4E0`. Preserve its regular-phase position instead of appending all native decals to layer15. The editor/game-options-type3 branch substitutes `176CB0` and does not call the ordinary `174220(0)` at this point. [40E90](../analysis/damage-shields-goal-20261011/overlay-pass/live-producers/00040e90-retail.asm), [176BB0](../analysis/damage-shields-goal-20261011/overlay-pass/live-producers/00176bb0-retail.asm), [176CB0](../analysis/damage-shields-goal-20261011/overlay-pass/live-producers/00176cb0-retail.asm), [41640](../analysis/damage-shields-goal-20261011/overlay-pass/live-producers/00041640-retail.asm).

The shared bank therefore receives **ordinary accepted part commands first, admitted particle-location callbacks next, then kind-1 groups, then kind-3 groups** in this ordinary world path. Priority/depth/plane sorting happens only after this assembly. Equal-key swaps and allocation saturation make assembly order observable. The existing native `source_transparent_sort` and `source_transparent_append_groups` implement the source comparator/sorter and group builders, but this snapshot has no calls to them in gameplay runtime/renderer. [native service](../src/source_transparent_sort.cpp), [instruction-derived group report](SHIELD_OVERLAY_SCHEDULING_RESEARCH.md).

### Exact particle callback boundary

`174220` iterates the actual occupied particle-system data array `510C74` by slot, retaining each generation-bearing handle. It applies source cluster/visibility, parent/view and FP filtering before `174420`. Each accepted system's `174420` traverses its `+30` location linked list through location `+0C`; source location byte `+02` must match the FP argument. There are additional source PVS/frustum/distance/definition gates. Child particle systems at system `+40` are recursively processed and advance through sibling-system `+38`. An effects-vector or shader-name traversal does not establish this array/list order. [174220](../analysis/damage-shields-goal-20261011/overlay-pass/live-producers/00174220-retail.asm), [174420](../analysis/damage-shields-goal-20261011/overlay-pass/live-producers/00174420-retail.asm).

For each accepted location, the source starts from current location `+10/+14/+18`, or the explicit transformed-camera-local branch, then adds view-forward times signed authored system-definition `+14` times the executable constant. It uses **`1E4E0` once for the location when the actual layer mask contains `8000`**, not once per emitted sprite. At `1748B9..1748CC`, the eight copied payload bytes are `{system_pointer, location_pointer}`: local `+20` holds the system pointer before `PUSH EBX`, so the copied source is local `+24` afterward. The callback is `173C90`. Other layer bits instead enter the regular command path through `40E30`, callbacks `173CB0/173D80`. [174420, `1744D6..1744F3,1745C0..174917`](../analysis/damage-shields-goal-20261011/overlay-pass/live-producers/00174420-retail.asm).

`1E4E0` allocates in the **same 1024-record bank** used by model/shield commands, sets priority3, secondary0, clears only the low byte of `plane_present`, copies the payload, writes callback `173C90`, negative forward depth and the biased location center. It preserves unused bytes. On a full bank it returns false without incrementing count. `173C90` loads the retained system pointer into ESI and calls `174F80(location, layer15, implementation0)`; this expands the location's particle draw at callback time. A native equivalent can retain completed sprite spans, but every location must occupy one source command and one sidecar dispatch token, and retain source sprite order within that span. [1E4E0](../analysis/damage-shields-goal-20261011/overlay-pass/live-producers/0001e4e0-retail.asm), [173C90](../analysis/damage-shields-goal-20261011/overlay-pass/live-producers/00173c90-retail.asm), [174F80](../analysis/damage-shields-goal-20261011/overlay-pass/live-producers/00174f80-retail.asm).

`420A0/42760` consume the populated `4C152C` bank. That bank is written by `2CBF0` from the actual owner/group collector, including source depth, sphere center and projected rectangle (`30290` or its explicit branches). The kind-1 callback `41CC0` and kind-3 callback `423C0` perform grouped regular collection and phase execution, including layer15; they are not merely alternative vertex ranges. The pure native group builders exist, but a live collector must supply the actual section records and native grouped-phase payloads before these callbacks can be admitted. [2CBF0, `2CCAB..2CDB0`](../analysis/damage-shields-goal-20261011/overlay-pass/live-producers/0002cbf0-retail.asm), [420A0](../analysis/damage-shields-goal-20261011/overlay-pass/live-producers/000420a0-retail.asm), [42760](../analysis/damage-shields-goal-20261011/overlay-pass/live-producers/00042760-retail.asm), [41CC0](../analysis/damage-shields-goal-20261011/overlay-pass/live-producers/00041cc0-retail.asm), [423C0](../analysis/damage-shields-goal-20261011/overlay-pass/live-producers/000423c0-retail.asm).

### Native gameplay location and object admission

The source services are present: `SourceObjectLocation`, point/sphere/initial/default registration location, independent source collidable/noncollidable pools, the event-driven `SourceObjectRegistrationJournal`, and exact ordinary `source_object_admission` retaining full handles and four-field queue records. `SourceObjectAdmission` is a PVS/spatial root queue; it does not construct model/FP/shield/child clones. Its rendering sphere is deliberately separate from the registration primitive sphere. [location API](../include/halo2/source_object_location.hpp), [journal/pool API](../include/halo2/source_object_spatial_pool.hpp), [admission API](../include/halo2/source_object_admission.hpp).

Gameplay already constructs the source render camera/frustum, portal visibility and BSP admission per view. `BspAtmosphere::sample/cluster_at` supplies current camera fog/cluster. It **does not** currently call the object registration journal or object admission. `SceneObjects::Object` stores generation handle, placement, position, visibility, selected BSP and birth tick, but not the original location leaf/cluster fields, registration reference-head, independent primitive sphere or successful-registration history. Native multiplayer player/weapon/grenade snapshots provide useful full identities and poses but not that missing source registration bank. No production caller of `SourceObjectRegistrationJournal` was found in this snapshot. Recreating its order from the current scene vector would violate the journal's explicit event contract. [runtime camera/BSP path](../src/multiplayer_runtime.cpp), [scene object fields](../include/halo2/scene.hpp), [journal implementation](../src/source_object_spatial_pool.cpp).

The reusable `MainmenuBspFrameProducer` joins the title's camera/portal/fog/BSP admission, not a complete gameplay object/collector queue, and explicitly excludes partial subpart masks. Separate exact `SourceBspRangeArena/source_bsp_frustum_cull/source_bsp_part_ranges` services exist for range/mask production, but their output is not joined to this gameplay collector frame. This prevents claiming that the current BSP selection result is already a complete `44AC0/460D0` admission result. [title producer](../include/halo2/mainmenu_bsp_frame.hpp), [range services](../include/halo2/source_bsp_ranges.hpp).

## Smallest shared integration contract

The following names are proposed interfaces, **not existing APIs**. They describe the minimum owners needed to use the parent's persistent transparent bank and ordered-span consumer without making the renderer infer source state.

1. **`SourceLiveObjectRegistry` owned by simulation/lifetime services.** Resolve every currently rendered full handle to definition/type, current generic flags, cached rendering sphere, independent registration primitive, location, pool rank and parent/child/sibling identity. Drive `SourceObjectRegistrationJournal` from actual birth/register/update/unregister/free events. Preserve it in snapshot/restore where needed. A cached sphere callback alone cannot reconstruct those events.
2. **`SourceRenderCollectorFrame` owned by the runtime's source view assembly.** Build BSP admission plus object admission with the same visibility/association bank. Apply literal `134240/163D50`. Append clusters, instances, then object collectors using source order; expand each object's clones/children in `133AB0` order. Retain original render-cache ordinal, raw flags, group index/kind, override datum, coverage byte, depth nibble, actual node/context-remap bank, section ordinal and partial-subpart mask. Keep ordinary and deferred FP portions distinct.
3. **By-owner scene collector methods**, for example `collect_view(full_handle, view, visitor)`, added beside the existing append APIs. The visitor returns immutable metadata/pose/vertex/lighting references whose lifetime covers this frame. The frame assembler chooses owner order; each scene only resolves its own handle and constructs the actual selected geometry/lighting/part bank. Scenery must retain the full nodes and raw parts; the other scene geometry owners can expose their existing banks. Player/weapon/FP runtime pose caches need the same handoff. Extract before ordinary LOD filtering removes parts required by an override.
4. **An ordered BSP part visitor** joining `selected_parts` to raw metadata and admitted mask plus resident spans, with a parallel explicit original-unit record for commands not represented by ordinary accepted vertices. A material/part map remains a lookup table, never the iterator defining source order.
5. **`ParticleLocationBatch` visitors** owned by world/muzzle effect systems. Retain source system/location identity and source iteration/admission metadata; return one completed sprite span per location. Invoke the literal `1E4E0` append once per accepted location. Additional regular layer bits must enter the regular phase owner, not create duplicate layer15 callbacks.
6. **One command-index sidecar dispatch bank** owned by the runtime and consumed by the renderer. Each successful allocation stores a typed native payload at that exact source ordinal: resident/dynamic part span with independent descriptor; particle-location range; or grouped phase program. Do not encode 64-bit native pointers into original 32-bit pointer fields. Keep source callback/payload bytes for differential inspection and a checked sidecar token for native resource resolution. Failed allocation creates no sidecar draw. Use the literal source ordinal sorter over the assembled suffix.

The renderer needs an ordered callback/span consumer that can switch between BSP and dynamic buffers, independent object uniforms and particle ranges **without regrouping the ordered stream**. Existing `SourceBspResidentPlan::merge` and the ordinary renderer `group` collect by lexicographic `DrawKey`; the key lacks owner identity and merges repeated keys. The `preserve_order` grouping mode exists for the sky, but is not a shared source transparent scheduler. Existing title-only particle-depth/light-volume boundary sorting is likewise not the source 1024-record bank. Current multiplayer emits generic transparent materials and world particles in separate blocks, then foreground models and foreground particles in separate blocks. [renderer grouping and phase consumer](../src/renderer.cpp), [draw/view APIs](../include/halo2/renderer.hpp).

Keep material input preparation, local-position/pose lowering and override-part proof from the prior reports. This new queue work does not supersede those gates. In particular, passing an actual shield `SourceShieldModelShaders` binding to the ordered consumer still requires its actual model/current geometry/collector inputs and a valid callback phase.
