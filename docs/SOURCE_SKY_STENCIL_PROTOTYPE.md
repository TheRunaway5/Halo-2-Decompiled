# Retained original20 sky stencil-only prototype

This isolated producer consumes retained original20 sky geometry for events 8097, 8102 and moon 8110. It does not render sky color, regenerate authored native vertices, select live sky draws, change the Renderer, or establish complete native world appearance. Original title authority remains unchanged `assets/disc/default.xbe`; the captured raster authority is unchanged `original_capture_20.rdc`, SHA256 `d99a5c97c85916c7b07e30dc1f181d6db81b3a5246686bcbeebebbc5445642ee`.

The implementation is new `include/halo2/source_sky_stencil.hpp`, `src/source_sky_stencil.cpp`, four `source_sky_stencil*` shaders, and an isolated test/build tool. Existing weather, chronology, native migration and pipeline proofs are unchanged. The actual source caller/state chronology remains documented separately in `SOURCE_SKY_STENCIL_CHRONOLOGY_AUDIT.md` and `SOURCE_ORIGINAL20_SKY_STENCIL.md`; this prototype has no live draw predicate.

## Source admission

`source-sky-stencil-stage-reference` retains complete VS/GS/FS modules, reflection, every bound constant bank, original and remapped post-VS indices, and both VSOut and GSOut for all three actual draws. The same GS module is used for all three: SHA256 `20ac4499716ad849300a2230c91faed205ad0c609bc0779e22006ae88aa45e22`. It has no uniform banks, receives triangles, selects literal `v=(0,1,2)`, calculates the perspective triangle plane, and emits one three-vertex strip. Original strips contain 74/49/4 indices and retained VSOut 37/25/4 vertices. Remapped indices equal original index bytes exactly; primitive restart is disabled in the actual pipeline.

The pinned RenderDoc source at commit `2fc0bc04cb95499635f63986a55bc6f67849dd9f` explains the two export layouts. VSOut uses std430 member alignment and a 240-byte stride: clip position byte 0, PointSize16, D032, D148, B064, B180, Fog96, T0112, T1128, T2144, T3160, Pos0176, Pos1192, Pos2208, triMZ224. GSOut transform feedback packs the reflected components into 204 bytes: clip0, PointSize16, D020, D136, B052, B168, Fog84, T088, T1104, T2120, T3136, Pos0152, Pos1168, Pos2184, triMZ200. Its per-primitive output strips are expanded to a triangle list, 216/141/6 vertices. The fixture checks every flat position/slope lane is byte-identical among a triangle's three vertices. These are actual reflection/packing facts, not assumed semantic offsets.

Two native paths bound distinct parts of the work:

- **VSOut strip:** copy retained clip/window vertices and exact original strip indices, then run the literal captured GS calculation/order and the minimal fragment depth/region path.
- **GSOut passthrough:** copy actual retained GSOut clip position, all three flat positions and slope; a vertex shader passes these unchanged to the same fragment path. It uses the actual transform-feedback triangle-list expansion and no regenerated vertex arithmetic.

VSOut's rewritten compute shader and GSOut's graphics extraction are not byte-identical. Across the source-order triangle window controls, event 8097 differs in 130/864 components, maximum 2 float ULP ; 8102 in 118/564, maximum 128 ULP ; 8110 in 7/24, maximum 8 ULP. The source admission JSON retains those exact counts. This precision boundary remains even if their eventual stencil bytes agree. Neither path proves native authored vertex production or physical Xbox arithmetic.

Every captured fragment module has exactly one `DemoteToHelperInvocation`, controlled only by containment in eight clip regions. There is no alpha-test, alpha-kill, depth discard, sample-mask output or storage side effect. Textures/combiners write only color/alpha, separately from this gate and depth. Captured alpha-to-coverage and alpha-to-one are both false. This permits an explicitly **stencil-only** depth attachment pass with no color attachment or sky texture descriptors. The minimal shader uses `discard` at that gate: with no color, derivatives or storage side effects in this diagnostic, kill and demote suppress the same persistent depth/stencil updates. It does not enable early fragment tests.

The fragment copies the original operation order: `FragCoord.xy-0.5` region coordinates, inclusive minimum/exclusive maximum windows, `FragCoord.xy/surfaceScale` barycentric areas using the captured Kahan/FMA determinant, division by each vertex W, inverse-sum infinity handling, perspective W reconstruction, offset/slope, W<=0/NaN to FLT_MAX, then clamp to `clipRange.z/w`. Depth is exactly `uintBitsToFloat(floatBitsToUint(floor(zvalue)/16777216.0)+1)`, not a division by 16777215. Captured constants are clip range `(0,16777215,255.99998474121094,16777215)`, depth factor/offset `(0,0)`, surface scale `(1,1)`, and eight regions `(0,0,641,481)`. Original bank offsets 272/288/832/836/864 are decoded into a checked 160-byte typed uniform.

The fixed native raster state is the actual 640x480 positive-height viewport with depth range 0..1 and full scissor, fill/cullNONE, single-sample, depth clamp, no bias, late LEQUAL with no depth writes, and both stencil faces ALWAYS/KEEP-fail/KEEP-depth-fail/REPLACE-pass, reference 255, compare/write masks 255. The appended coverage export confirms rasterSamples 1, sampleMask 0xffffffff, no sample shading/custom sample locations, alpha-to-coverage/alpha-to-one false, and no conditional-rendering buffer for all three draws. Its inactive `isPassing=false` field does not suppress an unpredicated draw. Source admission has no remaining resource gap.

## Ownership and proof contract

The producer borrows an actual ordinary optimal D24_UNORM_S8_UINT image. Caller facts identify its actual device, extent, usage, single mip/layer/sample, initialized combined layout, exclusive graphics+compute queue family and enabled geometryShader/depthClamp features. Format/usage/extent/limits are checked before resource or command mutation. It creates a combined attachment view and LOAD/STORE render pass for both aspects, restores the supplied layout with explicit visibility, and owns copied upload buffers, descriptors, framebuffer and pipelines. A failed prepare retains the previous prepared resources.

One live caller-owned reset/unsignaled fence must cover successful recording and all consumers. Image, device and fence stay alive until matching completed-fence retirement. Successful recording must be submitted once. Reuse or preparation before retirement is rejected; destruction waits for an outstanding fence. This is an exclusive lifetime contract, not an attempt to reflect opaque Vulkan image metadata.

The new fixture uploads original packed D24-low24/S8-high8 data as separate native depth and stencil aspects, reads both separately, masks only the unspecified upper depth-copy padding byte, restores the attachment layout, and supplies transfer-to-HOST visibility before fence-covered mapped reads. It compares all 307200 pixels for each actual event on both native paths and the actual A→B→moon sequence under one fence, reporting every depth/stencil difference and original-only/native-only change. Original 8097 changes 462 stencil bytes 00→FF with unchanged depth ; 8102 and 8110 retain those 462 FF bytes and change no depth/stencil bytes. Later unchanged bytes do not prove stencil was disabled: all three captured states enable REPLACEFF.

Additional controls exercise empty source regions, LEQUAL failure while retaining every stencil byte value, ALWAYS/REPLACE over a patterned initial stencil, reuse and rejected geometry/image/command/fence ownership. Controls retain actual source geometry and provide no fullscreen triangles, fitted coverage, edge inflation or mask texture. Reference byte maps are comparators only.

The original pre8097image has exactly462pixels at D24=0xffffff, and those are exactly its462changed stencil pixels. Endpoint equality in this scene therefore checks the admitted far-depth pixels and preservation elsewhere; it does not independently establish every possible sky coverage edge under a different depth field. Likewise unchanged8102/8110endpoints do not establish absent fragment coverage. The two retained geometry paths keep that boundary explicit.
