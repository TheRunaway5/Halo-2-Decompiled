# Production boundary for source object registration fields

Research snapshot: 2026-10-11. The next missing owner is a **persistent source construction/body-state owner**, connected to the authoritative native reservation and mutation sites. It must retain the real construction request, header/body fields, admitted pose and service outcomes, and expose those fields to `SourceObjectRegistrationJournal`. `NativeObjectLifetimes` now supplies shared identities and native mutation order; its publication deliberately supplies only identity/type/definition. A renderer enumeration or a projection of generic flag31 cannot produce the missing complete packet. This note continues [the lifetime handoff](SHIELD_OBJECT_REGISTRY_RESEARCH.md). No implementation/test file or live collector was changed by this research.

## Query, primitive and location cannot share a guessed sphere/seed

`B8265→BD020` first invokes the actual node/pose owner `BD090`, then `BDEF0`, before the generic constructor's registration edge. Regular `BDEF0` computes query sphere `+30/+3C` from the **current world node0**, authored bounding offset/radius and object scale (`BDF90..BE07A`). Type11 with a nonNONE physical component and control `C0` bit6 first calls actual backend `1D44F0`; successful backend bounds replace the regular query. Zero/absent physics at a cold observation does not prove that later branch cannot run. [Pose/bounds order](../analysis/damage-shields-goal-20261011/overlay-pass/registration/packet-producers/000bd020-retail.asm), [bounds body](../analysis/damage-shields-goal-20261011/overlay-pass/registration/packet-producers/000bdef0-retail.asm).

`BE07F..BE117` independently produces dynamic sphere `+50/+5C` from definition radius `+20` and direct world-axis offset `+24`, or copies the query sphere. Definition `+2` bit12 selects the next registration primitive. When already registered, `BE12B..BE1B3` preserves the previous primitive until the literal squared-distance threshold `0.010000000707805157` or radius comparison requires unregister/store/reregister. Existing `source_shadow_sphere`, `Cache::load_object_shadow_definition`, `Cache::load_object_light_spatial_definition` and `source_object_light_spatial_bounds` implement the regular computations; actual node0, physical override, retained prior primitive and admitted update event are still caller-owned. There are three different source location handoffs:

1. **BSP activation pass:** `B6BB0` visits the actual header-pool iterator, admits parentNONE with generic bit7 clear, calls `BF510`, then always passes the resulting eight-byte local packet to `B8600` at `B6C16`. If absent it calls `BF510`, saves AL into `+B8`, and supplies `+BC` on success or NULL on failure. ## Narrowest implementable handoff

The proposed owner is a simulation-side `SourceObjectBodyState` bank keyed by the **existing full shared datum**, checkpointed beside `NativeObjectLifetimes` and the registration journal. This is a proposed interface, not an existing implementation. Its useful contract is:

- **Begin from actual reservation/request:** retain the source request, selected immutable type extent, genuine zeroed body/header storage, opaque source allocations and creation-identifier state. Do not reinterpret a native `Unit`, scene placement or renderer clone as the original body. Run the existing complete constructor/type owners, or separately proved bounded producers that reject every unreached service. Allocation failure/constructor failure must remain distinct events.
- **Commit producer mutations, then extract:** preserve ordered generic/header/type mutations, actual admitted world node bank and query/dynamic/primitive caches. An extraction routine copies the packet from this owner; it does not fill absent fields with defaults. Explicit constructor-stage provenance distinguishes a pre-registration packet from a completed live object.
- **Consume real phase/events:** connect exact activation supplied-packet versus later seeded/NULL branches, original interested-state results, backend physical outcomes and attachment allocation results. Retain current flags and history after each admitted event. Continue using the journal for spatial list membership, retained location, topology and link order; do not create a second independently inferred hierarchy.
- **Observe live mutation sites:** use the already integrated SceneObjects, match spawn/drop/equip, grenade prepare/release/free and ordinary projectile lifetime call sites described in the [lifetime note](SHIELD_OBJECT_REGISTRY_RESEARCH.md#actual-current-call-sites). A bounds update, attach/detach, unregister and storage free are distinct events. Checkpoint restores must restore all sidecars before consumers synchronize.

Most direct-owner code already exists: `construct_source_object` implements whole TU1.1 `B8A30`, including cleanup, with mandatory memory, type extent and invoke providers; `construct_source_object_type` implements actual callback-chain dispatch. It has no production caller in the inspected native snapshot. `OriginalData` imports the authenticated construction tables/operands only for nonBase images. Its general construction-table ranges retain record `+0..+7` and inheritance/method slots, **not type extent `+8`**; the mandatory `base_extent` provider still needs the actual selected-image field (the separate action table retains only three verified types). [Constructor contract](../include/halo2/object_construction.hpp#L47), [complete native body](../src/object_construction.cpp#L63), [type dispatch](../src/object_type_construction.cpp#L98), [immutable import](../src/original_data.cpp#L260), [table ranges](../src/original_data.cpp#L302).

Start with explicit admission of the fourteen authored power-module roots at the cold unregistered boundary, using their real cache inputs and actual initialized pose. This establishes the smallest packet producer without looping-sound outcomes, and gives an original comparison for full fields rather than a rendered-bit subset. Broader registration still needs the actual activation tail and later physical bounds owner. Add the lift/ssce branches only with real attachment allocation state; add units with biped fields and actual physics/node providers; add held/dropped weapons and grenades with admitted attachment/marker/body updates. The existing `object_physics_construction` owner requires real backend/resource providers and is not an installed live service. [Physics contract](../include/halo2/object_physics_construction.hpp).

During this snapshot the parent added explicit `attach_link`/`detach_link` journal operations. Their post-admission/post-unregister seam is compatible with the original invariant: construction initializes absent links, attachment prepends, detach splices without sorting. The current API explicitly leaves marker/local transforms, bounds, dirty/activation and subsequent callbacks caller-owned, and refuses frees with remaining links. This closes a topology interface gap, not the complete packet-production gap. [Current topology contract](../include/halo2/source_object_spatial_pool.hpp#L93), [implementation](../src/source_object_spatial_pool.cpp#L181), [original attachment evidence](MP_WEAPON_ATTACHMENT_RESEARCH.md).

now addressed by [SourceObjectBodyStorage](SOURCE_OBJECT_BODY_STORAGE.md).
