# Campaign character GPU handoff seam

2026-10-23, current canonical source inspection. The initial audit was read-only; the implementation follow-up below adds the separate selected-section producer and a focused test/module. No build, compiler, game, numerical probe or retained-asset copy was run by this subtask. Root is concurrently implementing/testing the ordinary player route. This note supplies no campaign GPU execution or pixel-parity result.

## Concrete seam

`SourceCampaignModel::vertices(lod,sections,...)` constructs a **selected-section** `RenderModel`, preserving the full bones/compound palette, copies selected vertex/binding/origin records in request order, optionally applies baked scenery lighting, then calls `skin_model_world_nodes` (`src/campaign/source_campaign_model.cpp:144–163`). It deliberately does not skin every permutation in the resident union. The ordinary `draw` overload caches that posed vector by `(section, baked-instance)` **within one call**, then runs per-main-unit shader selection/coverage and appends the accepted records (`:173–205`). Repeated sections remain repeated output, although their deformation is reused in that local map.

The narrow arithmetic substitution is `model_skin_world_pose(selected,nodes,allow_gpu)` at that existing final-kernel boundary, retaining the selected bank and every existing palette-build invocation. That function already builds the same palette and copies local vertices before numeric/host/diagnostic admission; rejection runs the original CPU kernel against that same palette (`src/rendering/models/model_pose.cpp:291–309`). Its finite-domain admission is currently under live qualification by root; this note does not assume ordinary campaign vertices satisfy it.

**Do not directly call the player full-model deferred provider on the campaign union.** It would process unselected sections and change validation/arithmetic work. Do not key an across-frame `ModelWorldPoseCache` by the temporary `selected` model's address: this stack object is rebuilt for different sections, whereas that cache's model identity is `&model` plus node bytes/mode/FP controls (`src/rendering/models/model_world_pose_cache.hpp:81–104`). Start with the existing per-call section cache. Any broader cache needs stable resource/LOD identity, ordered selection, baked-instance/light-bank identity and lifetime/invalidation proof.

## Handoff shape: one object may contain several skins

The initial inspection found a singular `ModelObjectDraw.deferred_skin`. Root has since replaced it with trailing `std::span<const ModelSkinSubmission> deferred_skins`, parallel to the view-level range interface; the renderer registers those ranges against `object.vertices`. Campaign `draw` aggregates several independently cached sections, then filters each by its own coverage. The retained genuine-MCC Cairo case below contains **four ordinary main units** for one body, so this range interface is required.

The complete narrow integration is to retain **per-output-range `ModelSkinSubmission` packets inside the same object draw**, with one immutable geometry/binding/ordinal/palette owner per selected result, and pass those ranges to the existing `FrameModelSkinPlan::add_bank`. Preserve the single object constant bank and existing grouping/draw order. The plan already maps multiple source ranges through the actual ordered append parts, disables raw-byte dedup for GPU-containing packs and checks every registered vertex was mapped (`frame_model_skin_plan.hpp`; renderer integration `:4341–4348,5449–5450`). Palette merge remains geometry-owner identity, with each bank's original extent.

Do not split one owner into arbitrary section object draws: global material grouping, draw/observer indices and transparent ordering can change. Do not rebase authored uint16 bone indices into a synthetic combined palette without a new provenance/overflow proof. A single-packet shortcut needs proof that all original section palette builds remain in place, their output banks are identical, and mixed admission/fault timing is preserved; identical local floats alone do not establish that.

`SourceDynamicModelShaders::append_selected` appends accepted contiguous part runs and rebases material slots (`src/rendering/models/source_dynamic_model_shaders.cpp:96–111`). Its `select_indexed` counterpart already preserves an ordinal array through filtering (`:114–127`); a campaign indexed append must retain the original resource ordinal and parallel skin binding while applying the same material base. Distinguish selection ordinals from LOD/resource identity. Keep selected output, shader rejection, repeated sections and empty/unresident units exact.

The canonical campaign producer now returns `SourceCampaignDrawGeometry { vertices, deferred_skins }` from `draw_deferred(owner,draws,nodes,view,current_lighting=nullptr,allow_gpu=true)`. Existing `draw` methods remain CPU APIs. `allow_gpu=false` delegates directly to the existing ordinary `draw`. The deferred path preserves the per-call section/instance cache, constructs only selected class2 geometry, invokes `model_skin_world_pose` at that cold section's original final-kernel boundary, and uses `select_indexed` once for each actual main-unit append. Each nonempty admitted append owns its original expanded ordinals, bindings and complete original palette without bone rebasing. Class1 uses the old CPU path; any class2 cache key shared with class1 also stays CPU to preserve the existing class-independent key semantics.

New focused source/module: `tests/campaign_model_skin_handoff_tests.cpp` and `cmake/CampaignModelSkinHandoff.cmake`. Root can include that module and configure `HALO2_CAMPAIGN_SKIN_HANDOFF_MCC_MAP` to the prepared Cairo map, then build `campaign_model_skin_handoff_tests` and run `native_mcc_campaign_model_skin_handoff` through its registered scratch wrapper. It creates the real native MCC Cairo actor/main units, compares old CPU output against materialized ranged output and complete SSE/x87/errno state across rounding/DAZ/FTZ/precision/diagnostic controls, checks repeats/coverage/empty/unresident/errors, joins grouped destinations and requires nonzero deferred work. This new test has not been run by this subtask. App actor handoff/fallback and weapon packet propagation remain root/caller work. Resource loading, source world, original builders, lighting query, shadow writers and simulation were unchanged.
