# Native light-portal readonly operand

The normal MCC model captures for Scorpion and Wraith stopped at actual root
`134C00`, instruction `176754`, because the native runtime lacked backing at
`46A598`. The existing compiled portal owner loads a DOUBLE there. This is a
missing immutable input, not permission to invent a lighting/admission result.

The [original-byte audit](../analysis/vehicles-tu15-goal-20261023/light-portal-original-literal-v1.json)
authenticates English TU1.5 SHA-256
`21b207e7efdacaf6124a0822837f8be570766a42505057f7fd2d2ba8f409c4fd`.
It verifies all three fixed qword loads (`1765B0`, `1765BF`, `176754`), their
instruction bytes, the original read-only `.rdata` owner and the matching native
consumer expressions. The eight bytes are `000000000000903f`, IEEE64
`0.015625`. No indexed extent, adjacent gap, writable state, instruction or
computed result is imported.

The native data fragment is generated by
`tools/export_native_tu15_light_portal_literal_data.py` and mounted through the
existing immutable-branch ownership mechanism. Existing matching owners remain
intact; a writable or mismatching owner is rejected before publication. The
runtime needs no XBE file or instruction emulator for this data.

The [red ownership regression](../analysis/vehicles-tu15-goal-20261023/light-portal-ownership-red-v1/report.json)
reproduces the missing backing after successful compilation. The
[focused native rerun](../analysis/vehicles-tu15-goal-20261023/light-portal-cairo-focused-v1/report.json)
passes exact bytes, read-only ownership, eight-byte extent, conflicting-owner
rejection and the existing installation/idempotence checks. That run also
passes the current Cairo plasma-cannon stimulus: 18 ordinary SMG shots,
12 original target damage requests, the original death-bit store, natural
full-generation retirement and 16 complete-world replay comparisons. Its
closer posed-surface aiming inputs were already present in the current source;
no weapon spread, vitality or destruction threshold was changed here.

The [scoped stage](../analysis/vehicles-tu15-goal-20261023/light-portal-native-stage-v1/refresh.json)
pins only the named native input, ownership test, generator and current
destruction fixture. Headless destruction tests own separate worlds, clocks,
scratch and reports; a four-job CTest run admits at most two of them at once.
The [full rerun](../analysis/vehicles-tu15-goal-20261023/current-native-validation-v2/report.json)
passes all364 cases. Its [freshness audit](../analysis/vehicles-tu15-goal-20261023/current-native-summary-v2.json)
verifies all327 constructor reports,24 destruction reports,nine primary target
damage reports,two secondary-input reports,actual native Ghost boost and the
strict original BV component against this run's live report bytes and times.

## Shared writable bounds binding

The [updated model captures](../analysis/vehicles-tu15-goal-20261023/current-model-captures-v3/report.json)
get past46A598, then Scorpion and Wraith reach another missing input at actual
176462: the pointer cell474D3C. The [independent original audit](../analysis/vehicles-tu15-goal-20261023/light-portal-pointer-original-v2.json)
verifies its four original bytes `5c655500`, the writable `.data` owner and
the complete consumer instructions. It aliases the existing55655C destination,
already shared with the BSP query through474D40. The original CRT row46D990
selects complete380FA0; native world startup already invokes that owner and its
six alternating min/max stores. The target's original file-zero bytes are cold
storage, not the completed bounds, and are not imported as a computed result.

Only the missing four-byte writable loader initializer is added. The
[red regression](../analysis/vehicles-tu15-goal-20261023/light-portal-pointer-red-v1/report.json)
reproduces the exact missing address. The first green attempt retained a fixture
dispatch mistake: it called the frame module for an owner registered by the draw
module. The corrected [focused run](../analysis/vehicles-tu15-goal-20261023/light-portal-pointer-focused-v2/report.json)
passes both ownership checks, including the complete native constructor's
instruction sequence, six ordered stores, caller registers/flags, cold storage,
exact four-byte alias extent and preservation of a mutated live pointer across
checkpoint restore. The existing BSP alias is unchanged. The scoped provider
copy also preserves the current separately authored spatial-loop default
operand at44EBD8; its source diff is retained in the stage receipt.

The [current full rerun](../analysis/vehicles-tu15-goal-20261023/current-native-validation-v3/report.json)
adds both native ownership tests to the364 vehicle cases and binds the result
to the exact frozen source receipts for subsequent delivery. These repairs do
not close the complete vehicle, original pixel or audio gates.
