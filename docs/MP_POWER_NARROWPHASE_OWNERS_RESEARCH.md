## Admission and wrapper ownership

Complete `2E1430` receives four cdecl arguments: output-byte pointer, manager, type A and type B. It reads `manager +18C + ((typeA <<5) +typeB)*4`. No guessed type pair or filter success is supplied.

Complete `2E14E0` receives the retained child agent in ECX and five stack arguments: output byte, collidable A, collidable B, step/context, output packet. The source aligned work frame is `((entryESP -4) & ~15) -70`.

The original loops through real collidable parent links. For a type-17 wrapper it computes the motion vector's squared magnitude with SSE order `(Y² + X²) + Z²`, spills the word, and performs the original strict ordered x87 comparison against shape `+20`. Positive capability requires the real `27F920` property owner. If admitted, the source rotates actual motion by the collidable transform, scales by actual `step+10`, stores the offset and updates the flag/refresh fields. Otherwise it writes the original zero vector. Both actual canister visits have a source-owned zero motion vector and skip `27F920`; their offsets are zero. No world velocity or chosen motion is substituted.

A flag change clears `*(step+0C)` before refreshing relative/support state. An admitted wrapper motion also refreshes support. The original type-5 branch requires `305650`; the other branch composes the already frozen `305560`. These positive refresh branches are source-listed but not executed here. After real separation completes, `2E17F4/2E1805/2E180C` store the flags, restore the original step byte and copy the lower output byte in that order. The final source `[ESP+17]` load occurs after `POP EDI`, so its owning address is **frame `+1B`**; it is not frame `+17`.

## Separation, result packet and arithmetic

Complete `2F4BD0` receives the same five argument roles. Its aligned frame is `((entryESP -4) & ~15) -1E0`. It stores actual A/B shapes at frame `+18/+1C`. Agent `+2C` owns the separation cache; agent `+20` its retained vector, and agent `+18` its contact count/state gate.

The source cache-positive branch consumes actual current/previous transform vectors and source margins, preserving SSE and x87 load, sum, reverse-subtract, store-without-pop and comparison ordering. That branch is source-listed but unexecuted in this suite: both newly allocated child caches begin `BF800000`. A profiling bank with capacity would execute original RDTSC stores; the native module explicitly stops at that unmeasured platform branch. The actual profiling bank has no capacity, so no timestamp is invented or skipped on the measured path.

The admitted source path executes complete `2E0A60` into frame `+30`, clears frame `+7C`, then calls real `30AE40` with:

`30AE40` is measured executing original instructions through actual shape retrieve/support and simplex owners. Its outputs are retained in the source report, but the new native orchestration requires this owner instead of supplying its result.

Complete `309860` consumes the actual finished workspace/result. It first stores result word `+0C` at output `+20`, then XORs the four-lane result vector with the real executable mask at `418AE0` into output `+00`. When workspace `+00=1`, it copies workspace `+20` into output `+10` and writes output `+24=3F800000`. This branch executes in both actual canister results. The workspace `+04=1` and remaining branches are represented from complete original instructions but are unexecuted here; they use actual workspace `+A0/+130` and exact weights zero/`3F000000`.

Complete `2E0C70` rotates all four lanes with `(column0*x + column1*y) + column2*z`. It reloads source vectors/matrices in source order and writes two observed eight-byte halves of the original MOVAPS. It does not add a world position or construct a contact pose.

`2F4BD0` then subtracts both actual shape `+0C` margin words from output `+20` with original x87 spill order. The latter shifts output `+10`, produces output `+30` from the original relative matrix, and writes the lower output byte one. Original `+40` vector rotation and all untouched packet bytes are retained. No approximate distance, contact point or normal is computed from native replacement geometry.
