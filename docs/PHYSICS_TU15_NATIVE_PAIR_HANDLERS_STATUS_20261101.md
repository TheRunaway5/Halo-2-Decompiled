# Native pair creation/deletion parent status

`native_tu15_pair_handlers.hpp/.cpp` are unqualified semantic prototypes for
actual `320EF0` (227 sites) and `320260` (247 sites). GCC syntax validation
passes. They have no physical numerical/store/callback qualification yet,
are not included in CMake, and must not be selected by World. They do not
close any parity checklist item. Work paused for the measured live allocator
and phantom-delete blockers, whose separate qualified modules are documented.

The prototype reuses typed activation-agent services and explicit island
activation/deferred-pair/merge services. Remaining work is strict standalone
handler comparison at actual original child entries, full-parent composition,
fault/service prefixes and source-prescribed lazy DATA reads. In particular,
`320EF0` reuses a four-byte formal pair DATA field as the current dispatch
pointer, then second-body pointer, then discrete-result byte. Its native
caller must initialize that owned field from the current pair input; it must
not copy saved registers, old control frames or opaque AFTER bytes.

The source edits remain for continued parity work. They are not a native live
replacement or proof of complete create/delete conversion.
