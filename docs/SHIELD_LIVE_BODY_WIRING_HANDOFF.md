# Live body to damaged-shield rendering seam

Research snapshot: 2026-10-12. The current live armor animation loop now reads each player's damage feedback through the authored biped function bank. The original shield pass, override part selector and sorted callback consumer are also implemented. **The current body loop cannot yet submit a source-faithful visible shield by adding one overlay draw:** its model is preview-selected geometry, while its transparent consumer requires the completed source collector and shared scene queue.

This report edits no production, CMake, test or generator file. The [fresh evidence manifest](../analysis/damage-shields-goal-20261011/live-body-wiring/source-evidence.json), SHA-256 `f9f5f49c158f9a85c9bf05bbadddf6f95915c1a7c9ca7f613c38094ed84cac0a`, freezes 16 original routine bodies and 46 native files. Each native file was unchanged across its two capture reads; this is not an atomic checkout snapshot. The [textual production inventory](../analysis/damage-shields-goal-20261011/live-body-wiring/production-symbol-inventory.json) excludes generated sources. Concurrent implementation may advance after this snapshot.

## What is connected now

At captured `multiplayer_runtime.cpp:1087..1102`, player armor material ranges map to individual player slots, and the actual biped object functions are loaded for each representation. At `2905..2909`, the live `ShaderInput` closure calls `damage_feedback_shader_input(owner.damage_feedback, owner.health, owner.shield, owner.dead, authored_functions, tables, name, shader_time)`. The result reaches `animate_player_armor_emblem`, which receives the same callback. Shader time is the current simulation tick plus the existing render fraction at `1814`. This is a real per-owner animation connection, not an unused helper. [Frozen runtime](../analysis/damage-shields-goal-20261011/live-body-wiring/native-snapshot/src/multiplayer_runtime.cpp).

`damage_feedback_shader_input` uses `evaluate_object_function` with a distinct recognized-value/activity handler. It preserves the inactive-zero result instead of treating it as a BA8C0 interpolated override. Original `BCC20` reads body vitality from `object+EC`, shield vitality from `+F0`, recent body damage from `+F8`, and recent shield damage from `+F4`; alive/dead tests `+10A` bit 2. It clamps the scalar and separately returns recognition/activity. The new armor closure currently reads the host `MultiplayerState::Player` snapshot, not these retained source-object bytes. That authority distinction matters when the source-bank damage owners are ready. ## Geometry that can be reused, and the admission that is missing

The existing body loop has the correct location for attaching an eventual admitted clone: `multiplayer_runtime.cpp:2498..2539`. It obtains current source WORLD nodes when `match.source_object_world_bound()` is true, then skins the current body model. The `posed_body` span is available **before** ordinary material selection. Its vertices retain authored section/part identity and the unposed `source_local_position`; the shield material input adapter already distinguishes that local noise coordinate from posed projection coordinates. A shield clone should consume this unfiltered span once its source collector is established. Copying the appended ordinary world vertices loses parts rejected by the ordinary shader LOD, although `41040` selects the override's LOD and then checks the original bank at that ordinal. [Body loop snapshot](../analysis/damage-shields-goal-20261011/live-body-wiring/native-snapshot/src/multiplayer_runtime.cpp), [model vertex decode, `423`, `522..528`](../analysis/damage-shields-goal-20261011/live-body-wiring/native-snapshot/src/model.cpp), [shield part binding](../analysis/damage-shields-goal-20261011/live-body-wiring/native-snapshot/src/source_shield_model_shaders.cpp), [41040, `4113A..4129D`](../analysis/damage-shields-goal-20261011/live-body-wiring/instructions/00041040-retail.asm).

However, `visual()` currently calls `cache.load_model(datum,true,variant)` without a supplied current region selection or geometry LOD. That overload uses the preview path: it falls through authored geometry LODs, collapses duplicate sections into a set, and does not preserve each collector's region ordinal. Its cached `BodyFramePose` contains only body and weapon vertices; it drops the WORLD nodes after the pose-building branch. The scalar shader collector at the draw site supplies coverage only; it is not the complete `4B5D0` collector. [Runtime `402..450`, `1989`, `2498..2526`](../analysis/damage-shields-goal-20261011/live-body-wiring/native-snapshot/src/multiplayer_runtime.cpp), [model overloads and preview path, `100..160`, `253..290`](../analysis/damage-shields-goal-20261011/live-body-wiring/native-snapshot/src/model.cpp), [coverage contract](../analysis/damage-shields-goal-20261011/live-body-wiring/native-snapshot/include/halo2/source_model_shader.hpp).

Only the reference-player fixture supplies that retained sphere directly. A successful source WORLD pose does not prove source geometry admission, current regions, or collector coverage. [Runtime `1893..1925`](../analysis/damage-shields-goal-20261011/live-body-wiring/native-snapshot/src/multiplayer_runtime.cpp), [133790 instructions](../analysis/damage-shields-goal-20261011/live-body-wiring/instructions/00133790-retail.asm).

Its `SourceModelBuildWorld` still requires the current source read/write banks, view/cache/FP owners, allocation arena and real reached resource, deferred-node, PRT, lighting and optional rebase services. Neither full model build nor model admission has a live gameplay caller in this snapshot. These are concrete inputs to wire, not values that the body preview can certify. ## Exact selector, part and callback contract

For damaged shields, `4BCC0` requires an admitted visible model/LOD, caller mode zero, positive `object+F4`, and a positive hlmt damage-info count. It selects damage-info `+80` for FP or `+88` for world, requires a non-NONE shader, sets output `+16C` bit 1, and writes shader at output `+170` plus current `object+F0` at `+180`. Overshield is a separate `F0>1` branch with different references and scalar `1-F0`. The small `select_shield_overlays` helper accepts already-resolved admission inputs; it cannot replace the admission owner by assuming those inputs. [Fresh 4BCC0 instructions, `4BF83..4C03A`](../analysis/damage-shields-goal-20261011/live-body-wiring/instructions/0004bcc0-retail.asm), [selector helper](../analysis/damage-shields-goal-20261011/live-body-wiring/native-snapshot/src/shield_overlay.cpp).

`133AB0` expands the complete collector in branch order `80`, `02`, `01`, `20`, ordinary, then children. Damaged/overshield branches copy all `0x79` DWORDs, retain accepted geometry/coverage/lighting state, add command flag `8000`, and copy the override datum and scalar. `133F70→2CBF0` assigns the actual render-cache ordinal in model/selected-region order. That ordinal is distinct from the later transparent allocation ordinal. A material-key map or a separate "all shields after bodies" loop cannot supply it. [133AB0 `133AE4..133DE2`](../analysis/damage-shields-goal-20261011/live-body-wiring/instructions/00133ab0-retail.asm), [133F70](../analysis/damage-shields-goal-20261011/live-body-wiring/instructions/00133f70-retail.asm), [2CBF0](../analysis/damage-shields-goal-20261011/live-body-wiring/instructions/0002cbf0-retail.asm).

`44AC0` visits those render-cache ordinals, requests resident geometry, calls `45CE0` for actual part geometry and `460D0` for current part admission, then calls `41040`. The latter rejects raw types 0/5 and a missing original shader, chooses the override's shader LOD, and indexes the original template bank at that same ordinal for compatibility. The implemented `SourceShieldModelShaders::binding` supplies that part result and resident per-class shield material; it owns neither collector creation nor queue order. `41020→40F60` consumes an eight-byte payload `(selected shader, actual draw token)` and dispatches shader LOD 0, layer 15, implementation 0. [44AC0 `44B00..44C6A`](../analysis/damage-shields-goal-20261011/live-body-wiring/instructions/00044ac0-retail.asm), [41040](../analysis/damage-shields-goal-20261011/live-body-wiring/instructions/00041040-retail.asm), [41020](../analysis/damage-shields-goal-20261011/live-body-wiring/instructions/00041020-retail.asm), [40F60 `40FE0..4100E`](../analysis/damage-shields-goal-20261011/live-body-wiring/instructions/00040f60-retail.asm).

Fresh untouched Lockout metadata makes the node-remap prerequisite concrete: Spartan body/hands and Elite body/hands all have model flags `0x000C`, including compact-map bit 4. `45CE0` therefore needs the actual current geometry context remap before selecting the matrix translation used as the transparent sort center. It reads the context's **48-byte matrix bank at `+44`, translation offsets `+0C/+1C/+2C`**, not directly the object's 52-byte WORLD-node matrices. The literal authored rigid-node value, resident node-map list or retained WORLD matrices alone is insufficient. The existing node producer constructs this context from the WORLD/inverse-bind, compound and selected-region palette owners. All four authored PRT counts are zero; this removes that particular request for those definitions, not resource publication or the current node-context owner. [Raw fields and section records](../analysis/damage-shields-goal-20261011/live-body-wiring/body-metadata.json), SHA-256 `9c1433f3aa74dabd058ba33f87a3a78cbff6fce1cc64ec73e6bfa7ec4c87c634`, [fresh 45CE0 instructions, `45E90..45EE6`](../analysis/damage-shields-goal-20261011/live-body-wiring/instructions/00045ce0-retail.asm), [native node-context producer](../analysis/damage-shields-goal-20261011/live-body-wiring/native-snapshot/src/source_model_node_bank.cpp), [native model geometry contract](../analysis/damage-shields-goal-20261011/live-body-wiring/native-snapshot/src/source_transparent_parts.cpp), [node-owner validation record](SOURCE_MODEL_BUILD_RESOURCE_PARITY.md).

## Shared queue and renderer constraints

There is no live producer of either `ModelView.world_transparent` or `foreground_transparent`. When one is present, the renderer suppresses ordinary layer-15 draws for that phase and the corresponding fallback particle-bank traversal. Consequently, installing a shield-only bank would omit unrelated transparent geometry and particles. The existing queue is the complete phase's queue contract, not an additive side channel. [Renderer `4509..4514`, `4936`, `5201..5207`, `5224`, `5257..5263`](../analysis/damage-shields-goal-20261011/live-body-wiring/native-snapshot/src/renderer.cpp), [inventory](../analysis/damage-shields-goal-20261011/live-body-wiring/production-symbol-inventory.json).

The original world producer resets the shared bank, submits attachment effects, traverses the render-cache bank, then submits particle and section/group/decal owners. The queue shares the 1024-record capacity and original equal-key ordering; the FP phase uses the same storage's suffix and restores the prefix count afterwards. `SourceTransparentQueue` implements this storage/sort lifecycle, but the live producer has not joined it. Unknown nonnull callback services are rejected by the renderer; group callbacks `41CC0/423C0` are not implemented there. [40E90 instructions](../analysis/damage-shields-goal-20261011/live-body-wiring/instructions/00040e90-retail.asm), [queue implementation](../analysis/damage-shields-goal-20261011/live-body-wiring/native-snapshot/src/source_transparent_queue.cpp), [draw contract](../analysis/damage-shields-goal-20261011/live-body-wiring/native-snapshot/include/halo2/source_transparent_draw.hpp), [renderer `3350..3390`](../analysis/damage-shields-goal-20261011/live-body-wiring/native-snapshot/src/renderer.cpp), [previous complete producer trace](SHIELD_LIVE_PRODUCER_RESEARCH.md).

The renderer already preserves sorted callback order and carries optional per-owner lighting through `SourceTransparentGeometryDraw`. It validates shader/draw-token identity and resident shader LOD0/layer15 passes. It does not evaluate a new per-owner `ShaderInput` in this binding, so shield materials must be prepared and animated in their existing per-owner resident ranges before the draw. Add those ranges to the material-owner mapping and active-root selection alongside their actual queue geometry. Reusing one mutable shield bank across players would lose per-owner constants. [Renderer `3350..3375`, `3533..3556`, `4196..4199`, `4990..5015`](../analysis/damage-shields-goal-20261011/live-body-wiring/native-snapshot/src/renderer.cpp), [draw API](../analysis/damage-shields-goal-20261011/live-body-wiring/native-snapshot/include/halo2/source_transparent_draw.hpp), [runtime material owners and active roots](../analysis/damage-shields-goal-20261011/live-body-wiring/native-snapshot/src/multiplayer_runtime.cpp).

## Smallest evidence-backed next implementation

The smallest immediate production change that advances the existing live path without asserting missing draw admission is a **read-only, full-handle source-object presentation accessor**, consumed at the existing body/armor callsites. It should return current `EC/F0/F4/F8` and alive state plus the retained `30/3C` owner sphere from the same bank that already supplies WORLD nodes. Validate the full salted handle using the existing `source_raw_datum_lookup` pattern in `MultiplayerObjectRuntime::world_nodes`; preserve the existing previous-unit handle for a corpse. Use it for the current armor callback and coverage producer when the source world owns those values, after the damage owner actually writes that bank. Do not manufacture source authority by copying host feedback into it. The source clock/function-state path remains a further requirement if current BAB40 interpolation or other built-in inputs are needed. [Current full-handle WORLD-node accessor](../analysis/damage-shields-goal-20261011/live-body-wiring/native-snapshot/src/multiplayer_object_runtime.cpp), [read-only memory view API](../analysis/damage-shields-goal-20261011/live-body-wiring/native-snapshot/include/halo2/source_runtime_memory.hpp), [BCC20](../analysis/damage-shields-goal-20261011/live-body-wiring/instructions/000bcc20-retail.asm).

At the same body pose-building site, retain WORLD nodes with the unfiltered vertices in `BodyFramePose`, including the split-screen reuse branch. This makes real pose data available to the node-context producer; retaining it does not itself supply that producer's 48-byte context matrices, compact remap or accepted geometry LOD. It is a necessary small ownership change, not a completed visible shield system.

The smallest **complete visible join** is then one live scene collector adapter, invoked from the existing per-view assembly, that:

1. Calls the implemented full model build/admission on current owned banks and uses its selected region bytes, geometry LOD, accepted model count, node context, retained owner sphere and lighting output. Load/pose those exact sections with the explicit `Cache::load_model(...,selection,lod)` path; preserve duplicate collector ordinals.
2. Expands the complete collector in `133AB0/133F70` order, binding each admitted shield clone with `SourceShieldModelShaders` over the same unfiltered accepted pose and separate per-owner animated resident materials.
3. Traverses the complete source-ordered render-cache and effect/particle/group producers into the existing shared queue. Builds `SourceTransparentGeometryDraw` only after actual `45CE0/460D0/41040` admission, using the actual draw token and current compact remap. Retains spans and bindings through `renderer.draw`.
4. Sets the view's transparent bank only when that phase's producer is complete; joins the FP deferred/regular owner and suffix separately. The current world-body loop hides a living local player, so attaching world-body overlays there cannot cover first-person hands/weapons.

No new shader constants, hand-chosen opacity, guessed lighting, synthetic sort center or independent shield draw order is required by this design. The remaining work is ownership and live service binding. Existing controlled shield tests establish material/input/consumer behavior only: their synthetic tokens, fixed part type, chosen center and inspection pose explicitly do not establish live collector admission or Xbox framebuffer parity. [Controlled render test snapshot](../analysis/damage-shields-goal-20261011/live-body-wiring/native-snapshot/tests/source_shield_render_tests.cpp).
