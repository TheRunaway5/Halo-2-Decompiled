## Integration recommendation

The [prepared patch](../analysis/physics/native-contact-features-handoff-full-return-tu15-20261101-qualified/recommended-world-generated.patch)
adds the helper include and wraps only canonical `30AE7D`/`30AE95`, selected
TU1.5 `30E96D`/`30E985`. It also preserves those two hooks in the maintained
generator, authenticating the selected source mapping and virtual34 operand.
No generated/World/CMake file was edited by this investigation.

Add both feature kernel and handoff `.cpp` files to the live target. In the
actual `run_actual` executor scope, alongside the existing native consumers,
construct `NativeTu15ContactFeaturesHandoffBinding` for `bank` with stack
`[0x60000000,0x60100000)`, existing read-only observer qualification, pointers
to `first_person_phase_active`/`weapon_effect_phase_active`, an instruction
callback updating `last_instruction`, and a persistent activity counter.
Expose its attempts/completed/refusals, first/second source calls and five
direct-owner counts in the existing native activity report. This needs no
scratch arena because feature outputs are actual caller-owned DATA.

The binding is limited to a void thiscall: shape ECX, feature IDs/count/output
at actual ESP+4/+8/+C and exact return at ESP. Publish native FP words and
advance ESP16 after success. There is no original register-output adapter or
feature callee frame serialization. Private control-byte differences remain
explicit under the preexisting returned-private-stack contract.

The physical adapter owner is removed after866,533,376 allocated bytes; the
model owner is removed after9,277,440 bytes. Only small reports/commands/source
and required preexisting reference inputs remain. The later04 integration above qualifies the exercised live domains;
other production paths require separate evidence.
The full-native `304350` opaque constructor lifetime remains an independent
open gate; this seam leaves its genuine original parent intact.
