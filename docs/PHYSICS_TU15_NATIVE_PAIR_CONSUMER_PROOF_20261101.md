## Inputs and physical evidence

The original captured `321510` calls in the three protected root frames have
zero change counts. Those calls alone cannot qualify the nonempty pipeline;
the initial captured-positive search remains explicitly RED. The qualified
tests stop at genuine entries with existing pair records, then declare
confirmation, deletion, cancellation, reversed, 2/4/8-record requests from
those actual current pair identities. The declared DATA is installed before
both executions. These are not captured positive events or supplied callback
results. All original filter/create/delete bodies execute normally.

Every case compares all persistent captured memory, FP words, the complete
20-byte temporary header, ordered retained reads/stores including before and
written bytes, and the exact callback owner/receiver/formal-argument sequence.
The native body and original use identical inputs; no captured AFTER data or
original callback outcome is fed into native execution. The 64-byte declared
input DATA area and header remain explicitly observable despite the existing
void-frame private-control-stack contract. FS/SEH bookkeeping is outside the
native API; its final persistent bytes still participate in the comparison.

Three mutations are rejected: incorrect 16-byte reservation stride, a wrong
last record word and suppressing the genuine create callback. The first
positive run retained zero persistent-byte differences and matching callbacks
but failed its strict read ordering. Native code was corrected to read the
first old-record word before loading the destination cursor, exactly as
`321606` precedes `321608`. The initial strict failures remain in their reports.

## Integration recommendation and open gates

`native_tu15_consume_pairs`, supplying a genuinely owned 20-byte temporary
header and the four semantic merge DATA fields. The native call receives the
current island and actual first/second spans directly; it needs no CPU call
frame, SEH packet or GP/SIMD return adapter. Retain observation-only consumers
and the existing world executor/lifetime guards.

Reuse already qualified arena allocation/release and owned-array services
only when their actual global allocator/vtable correspondence is authenticated.
The source uses arena slots `+0x24`/`+0x28` and owned slots `+0x10`/`+0x14`,
memory class `0x12`, with
byte counts derived from stride 16. Their slow/growth callbacks were not
reached in this cohort; no new ABI qualification for those owners is claimed.
Unqualified owner descriptors must remain explicit gates. `2E9A00` can use
the separate qualified native activation filter when its exact owner matches.
For create/delete, the reached original bodies require only the typed current
receiver and pair DATA; their eventual native rewrites remain separate work.

Observer/read/store-fault and service-exception prefixes, arbitrary aliases,
arena slow/growth execution, actual captured positive events and visible World
activation remain open. This module is ready for a constrained next owned
integration cohort, not a claim of complete physics parity or no remaining
original service. Required reference inputs are preserved; generated ELF,
raw banks and compiler/build outputs are automatically removed.
