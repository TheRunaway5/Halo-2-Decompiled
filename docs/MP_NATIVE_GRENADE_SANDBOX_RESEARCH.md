# Live native Q grenade bridge

The actual native Match now consumes a Q pulse, retains the original44h grenade
action record, debits the authored inventory during preparation, attaches a
genuine shared-pool projectile to the current decoded throw pose, releases it,
and applies the ordinary frag timer/material arithmetic through the native
terrain and area-damage backend. This is a named native animation/world adapter;
it is not a replacement Xbox raw Unit, a returned original whole constructor,
or a claim of full Havok/platform/effect playback parity.

The new [adapter](../src/native_grenade.cpp) consumes actual Cache metadata and
selected-image operands. [Public state/API](../include/halo2/native_grenade.hpp)
keeps full salted projectile/player/unit identities, action bytes, selected
graph/clip/activity/frame, held attachment and released position/velocity/frame.
No velocity-derived orientation, shot-counter effect, chosen fuse, chosen
damage radius or manufactured physics success is used.

## Integration and exact limits

`Controls::grenade` is a consumed pulse, including on consecutive ticks.
MultiplayerKbm retains short taps until consumption and clears dangerous pending
presses on focus loss. Native protocol23 carries a separate fourth press serial;
cached continuous inputs cannot retrigger Q. This is the native UDP protocol,
not Xbox wire parity. Match explicitly configures the retained Cache/operands;
ordinary selector/count producers remain the existing authored inventory path.

`NativeGrenadeSandbox` supplies current action/held/released model state and
actual Detonated requests. The separate64-entry monotonic-serial detonation bank
is native transport retention, not source gameplay timing or guaranteed delivery.
Clients baseline it on join and report serial gaps. Retained forward/up are the
actual projectile model frame, not a claim that all four original detonation
effect-location frames have been constructed. Runtime render/audio ownership and
real X11 Q tests are root-owned and outside this CPU checkpoint.

The admission bridge intentionally supports the ordinary detached SMG branch and
rejects reload. It does not replace all `E95E0` cancellation/seat/instant/raw Unit
owners; the complete isolated begin module still requires their genuine state.
Native triangle/prop contact and capsule/triangle area delivery are explicit host
services, not original Havok contact or raw registry enumeration. Flight does not
yet directly collide with live unit capsules. Plasma attachment, water/guidance,
stochastic responses, released angular spin and complete remaining-time contact
integration remain outside this ordinary frag bridge. Health falloff executes
without claiming acceleration/camouflage sideeffects. Original natural fuse,
bounce and detonation-effect execution are not established by the release probe.

For the root sound seam, original `100CA0` builds ordinary detonation request
flags4/parentNONE. `179B90` writes runtime effect WORD+2=0. `177A10` sets bit1 only
for request&2 and takes parent branches only for request&1; both are clear here.
For actual frag effect flags6, the optional bits3/4 branch is skipped; complete
intermediate bodies have no writer setting bit1/0200. Thus a successful ordinary
allocation reaches initial `17B2C0` with literal one. Allocation/event admission
and complete effect playback are separate owners; no successful return is inferred.
