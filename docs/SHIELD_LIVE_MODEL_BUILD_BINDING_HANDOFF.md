# Live shield model-build binding handoff

Implementation follow-up: the parent subsequently connected the isolated
`3D260/2B520` pool lifecycle and retained owner-sphere consumer. The frozen
research snapshot below records the earlier missing owners; it remains useful
for the remaining resource, view, node and lighting bindings.
[Actual implementation and validation](SHIELD_LIVE_OWNER_SPHERE.md).

The retained multiplayer source world supplies genuine object/tag/WORLD-node/BSP banks and the original game-arena allocator. It does **not yet supply a constructed model render cache or geometry-resource publication service in the frozen snapshot**. The smallest next startup join is complete TU1.1 `3D260()` followed by `2B520()` on that same bank. Model construction must then stop at its actual missing resource, view, node or lighting owner. Calling the model helper with preview residency, a private render-cache array or successful callbacks would not close those boundaries. This research changes no production code, generator, CMake or tests. Parent implementation after the snapshot is separate evidence.

## Exact image and ABI correspondence

Fresh unchanged-image matching proves **39 unique complete body pairs / 5,173 instruction rows per image**, including internal branch topology and encoded call/global operands. This is static correspondence, not runtime branch coverage or cross-image rendered parity. ## Immediate render-cache constructor and activation

The constructor itself has no BSP, rasterizer, view, geometry-resource or model input. Its real prerequisites are the already constructed `125280` allocator object, its retained arena/checksum cells and enough writable allocation backing. `125280` publishes `*51841C` and writes literal vtable `45A610`. Fresh raw bytes prove vtable+0=`125E50` (**not** register-size allocator `125490`); +4=`27E760`. `3D260` pushes `1006C` and calls that first method. Complete `125E50(size)` rounds to4, advances `4ED654`, calls checksum owner `1656A0`, returns actual `*4ED650 + old_cursor`, and `RET4`. It has no inferred allocation-success callback. [Allocator raw evidence](../analysis/damage-shields-goal-20261011/live-model-build-binding/render-startup-lowers/allocator.json), [125280](../analysis/damage-shields-goal-20261011/live-model-build-binding/render-startup-lowers/instructions/00125280-tu11.asm), [actual125E50](../analysis/damage-shields-goal-20261011/live-model-build-binding/render-startup-lowers/instructions/00125e50-tu11.asm).

`3D260()` preserves ESI/EDI and consumes no stack arguments. After actual allocation it invokes `16D070` with ESI=storage, EBX=256, EDX=256, CL=0; stack(storage, name `457A30`, allocator). `16D070` invokes `16D0D0`, retains actual record/bitmap addresses, clears occupancy and returns `RET0C`; `16D0D0` uses the existing `326970` copy owner. Records start at storage+4C, bitmap at storage+1004C. `3D260` ORs pool+2A with4, publishes `510C24`, and sets `4C90F0=NONE`. Allocation0 skips construction and still publishes0; activation dereferences the pool unconditionally, so failure cannot be treated as a usable cache. [Constructor](../analysis/damage-shields-goal-20261011/live-model-build-binding/instructions/0003d270-tu11.asm), [16D070](../analysis/damage-shields-goal-20261011/live-model-build-binding/render-startup-lowers/instructions/0016b5f0-tu11.asm), [16D0D0](../analysis/damage-shields-goal-20261011/live-model-build-binding/render-startup-lowers/instructions/0016b650-tu11.asm).

`2B520()` then loads ESI=`*510C24`, sets pool+29=1 and calls complete `16D220`. That reset's **only callee is `326970`**: it copies the first two name bytes to pool+40 and ORs8000; zeros +34/+38/+3C; conditionally fills records with BABA only for pool+2A bit3; clears each salt and the bitmap. Flag4 set by this constructor does not enable that fill. `2B520` additionally resets time4C1560, count4C1654, inline banks4C0E90/4CC538, first4C0E90=NONE and flag510BEC. Both16D220 and326970 already have retained full-ABI native bodies. [Activation](../analysis/damage-shields-goal-20261011/live-model-build-binding/instructions/0002b540-tu11.asm), [complete reset](../analysis/damage-shields-goal-20261011/live-model-build-binding/render-startup-lowers/instructions/0016b7a0-tu11.asm), [frozen entry inventory](../analysis/damage-shields-goal-20261011/live-model-build-binding/native-snapshot/src/death_world_runtime_entries.hpp).

Complete top-level renderer initialization is wider: TU `2B480` sets frame/time and view-history globals, then calls `3B890`, `3D260`, `16780`, in that order, before an additional18-byte arena allocation/publication at510C1C. The unique literal lifecycle record is retail44124C/TU44789C, words `[0,0,0,init,dispose,new-map,old-map,0,0]` with TU callbacks `2B480,2B5A0,2B520,2B580`. A bounded pool startup join does not establish those other initialization owners or the complete lifecycle dispatcher. Registration is static evidence; no dispatcher execution was run here. [Whole initializer](../analysis/damage-shields-goal-20261011/live-model-build-binding/render-lifecycle/instructions/0002b4a0-tu11.asm), [raw registered record](../analysis/damage-shields-goal-20261011/live-model-build-binding/render-lifecycle/registration.json).

## First missing geometry-resource publication owner

After actual render-cache startup, `banks.request(flags,header)` must invoke **TU1.1 `12F5E0`**, paired with retail12DE70. Ordinary selected sections reach it through `4C2A0`, mode3 for requested loading and mode0 for residency/fallback reads; admission may request PRT mode3, and `138F70` requests mode0 before reading each resident node-map bank. The header is mode section+38 (section stride5C), or PRT entry+34. [Section owner](../analysis/damage-shields-goal-20261011/live-model-build-binding/instructions/0004c2b0-tu11.asm), [node request](../analysis/damage-shields-goal-20261011/live-model-build-binding/instructions/00137800-tu11.asm).

Its required owning startup is separately authenticated:

- Retail `12D8B0 → TU12F020()` allocates/constructs real pools through allocator `*46FBF8`: requests188C andB68, constructs512 stride12 and350 stride8 records via16D070, publishes4EDA5C/4EDA60, then requests30FC and calls13E8E0 to construct the physical cache published at4EDA6C. Its allocator is a different cell from the already owned51841C; its current producer was not established here.
- Retail `12D9F0 → TU12F160(stage)`, `RET4`, admits the literal stage table, reserves700000 bytes for stages0/1/3 or680000 for stage2 through its real physical-page state at4ED9F0/4ED9FC/4EDA10 and protection call2D7A1A, publishes backing4EDA64/size4EDA68, calls13F020(page count), then sets physical-cache+2C=2. Those page-budget owners are not supplied by a successful host raw-file read.
- Retail `12DAF0 → TU12F260()` resets request policy flags/counters and activates/resets the two constructed record pools with16D220. It does not allocate or publish backing.

[Fresh complete startup bodies](../analysis/damage-shields-goal-20261011/live-model-build-binding/resource-startup/correspondence.json).

`12F5E0` first honors header+1E linked state by touching the actual physical cache's time. Otherwise it validates signed header+8/+C sizes, chooses priority from flags and cache policy, and calls `12FB10` when header+20 isNONE and loading is requested. `12FB10` uses **13EAE0 physical admission**, binds the actual12-byte in-flight record via16D390, writes header+20, clears linked+1E and submits real I/O to **19D8C0**: ECX=header+0 encoded file location; stack(sector-rounded header+4 size, actual destination, bytes-read pointer0, record+2 completion-byte address, type4, priority). EAX becomes record+4 job handle. This lower I/O body is only an actual paired call target here; its complete ownership and outcome remain unresolved.

Completion is a separate event: `12F5E0` can raise priority via122400, wait through2D84C4/1274B0, and only when the actual completion byte is set call **225D80**, EDI=resource header, stack(actual resident base), `RET4`. That complete pointer/resource-fixup body writes header-owned output pointers and retained resource structures before12F5E0 sets linked+1E=1 and returns true. These writes, clock touches, completion and failures must remain owned. [Admission/request chain](../analysis/damage-shields-goal-20261011/live-model-build-binding/instructions/0012de70-tu11.asm), [queue/I/O](../analysis/damage-shields-goal-20261011/live-model-build-binding/instructions/0012e3a0-tu11.asm), [fixups](../analysis/damage-shields-goal-20261011/live-model-build-binding/resource-startup/instructions/00223c70-tu11.asm).

The current native cache already reads actual raw model resource bytes via `Cache::load_model_resources`, including external shared-file location bits. `NativeResidency::model` retains those bytes and a decoded host model. Neither path publishes these original resource/cache/header/fixup records into `MultiplayerObjectRuntime::bank`. Its existing resource callback accepts only jmad124F30 at the exact1E121B caller; BSP delivery accepts only1244B0 at1242B1. Reuse real file reading, but deliver it at the actual new service ABI and preserve the original cache/admission/fixup owners. ## Remaining reached services and validation limits

The renderer already has actual submitted camera position/basis, source projection rectangles/program, local source player/unit identities and retained owner spheres. It must explicitly deliver geometry-distance/lighting metrics, view descriptor identity/order, caller mode and force/rebase inputs; none should be inferred from successful mesh upload. Complete134F00 (retail133790) owns the ordinary collector calculation. Source selector/admission must consume actual source-body shield damage; host shader feedback is not that join. [Frozen view inputs and body path](../analysis/damage-shields-goal-20261011/live-model-build-binding/native-snapshot/src/multiplayer_runtime.cpp), [ordinary collector](../analysis/damage-shields-goal-20261011/live-model-build-binding/instructions/00133790-tu11.asm).

The following callbacks remain mandatory whenever reached: scalar `BAB40→BBA30` (the latter is already a registered native construction owner); deferred `BD610→BE500` beyond the helper's exact local-offset/counter early returns; rebase `3D480→3D470` when its low-byte flag is set; PRT `23690→23670` when actual admission flag40 requests it; lighting `3DB00→3DAF0`, query `D1850→D2D00` and conversion `D4080→D5680`. Lighting also requires the actual default pointer `*4E58C4`, inline fallback566C18, interpolation byte46E904 and reached velocity/incident services. Current host `object_light_cache` does not manufacture this source cache's validity, cadence or query output. Existing body/hands PRT count0 evidence only suppresses that particular request for those authored models. It cannot certify other models, lighting or resource readiness.
