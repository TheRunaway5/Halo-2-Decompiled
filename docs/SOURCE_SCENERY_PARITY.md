# Original multiplayer scenery geometry and lighting

`SourceSceneryScene` retains source SCEN selection, geometry LOD and section lighting together. The constructor loads all six literal resident collectors before renderer allocation. `append_view` selects one using the shared original `4C450`/`4BCC0` arithmetic and the submitting player's prior LOD byte. An empty collector emits no geometry or lighting binding and retains prior history. The transition fraction remains the source hysteresis intermediate; the original caller discards it before draw scheduling.

## Authored selection and lighting

Automatic admission uses `D59F0`/`D5060`'s placement, Slayer game mask and BSP conditions. `SourceInitialModelSelection` must contain resolved original model-region bytes. The four Zanzibar pillars remain unresolved without actual initialization history. Default construction rejects them. The optional `OmitUnresolvedSelection` service can explicitly omit only unresolved owners, retaining their original global content indices in `unresolved_selection_owners`; it does not select a substitute region. A caller may preserve an independently labeled legacy preview for those owners. Resolved owners cannot be omitted through this seam.

`10A820`/`10A8B0` compare full authored object identity and render-model checksum, with origin BSP compared only for structure-origin objects. Tag policy2 skips baked lookup. `2D000` distinguishes valid resident pervertex implementation1 from model dynamic implementation2; invalid resource state remains unresolved implementation3. Baked objects call `Cache::apply_scenery_lighting` separately for each exact collector. Its section offset plus original source vertex index addresses the authored incident and RGB bucket. An absent offset or stream throws; it cannot choose dynamic lighting as a substitute. Incident remains in authored world coordinates, while posing transforms geometry normals/tangents/binormals.

Material slots share only within the same owner/source shader and selected shader LOD. The resident bank prepares all authored alternatives with the owner's original implementation1 for baked lighting or implementation2 for dynamic lighting. Each view selects its parts through the actual cached owner sphere, render-camera coverage and literal part scale, independently of model geometry LOD. Baked section incident/RGB attribution survives that selection. `BFD20`/`3DB00`'s direct scenery probes retain their original twenty lighting floats and packed metadata separately. Each admitted dynamic owner evaluates the original query/cache gate at every submitting view's unmodified source distance, before part shader selection. Empty collectors emit no binding but still evaluate that cache. The actual last-query-frame guard deduplicates completed queries; a later view can query when an earlier view skipped for cadence. Each view retains the bank available at its own submission. `SOURCE_SCENERY_SHADER_PARITY.md` records the original collector fixtures and independent selected-bank checks.

The initialized change-color bank is raw `BE240` output, using actual constructor position and selected variant name. `apply_object_colors` performs the single original draw-boundary pack/unpack before recursively binding base/lighting/environment/overlay passes. The new module does not quantize the raw initialized colors itself. Authored current color functions without a source input producer are rejected.

## Lifetime and caller services

`synchronize` consumes global content placement indices, full generation handles, actual creation ticks, current root transform and visibility. A new generation resets LOD history and query state. A supplied historical-selection service must return the same resolved variant, permutation and region-state bytes as the prepared resident union. A different or unresolved bank is rejected; the renderer cannot allocate unprepared geometry after construction. Owners whose initial selection depended on RNG require this service for every birth. Destroyed or hidden owners emit no geometry and perform no view/query work.

The object root enters the hierarchy before descendants, as in `BD090`; the complete WORLD bank then feeds `1376C0` inverse-bind composition. Placement is not applied a second time to skinned vertices. Cold `10A1B0` stores scenery `+138` as NONE, so `10A390` supplies no deferred root override. Later admitted overrides require their actual source state. The raw quaternion/local/hierarchy arithmetic and software reciprocal convention are documented in `source-model-pose.md`.

The optional `BirthQueryCapture` service receives the actual initial WORLDnode0 at pose0 during each new generation's synchronization, before `update_pose` samples any later controller time. It carries source content index, full handle, constructor tick, definition and scale. This captures constructor bounds without performing a lighting query and prevents a late first draw from substituting its current animated node for the source cached constructor output.

The mandatory cached-sphere service supplies the actual sphere, velocity, runtime query flags and frozen-state decision. A posed model bound or camera origin is not substituted for source cached object bounds. Multi-frame initialized clips require an explicit phase service keyed by global content index, full handle, actual birth tick and simulation tick. `AnimationFrame` additionally supplies the actual initialized clip and directly samples its retained controller frame; it takes precedence over the older seconds-based `AnimationTime` service. Fixed/no-controller objects require neither. Out-of-range retained frames are rejected instead of silently wrapped. The module does not derive a phase from rendering or visibility. Animation changes, original update scheduling/clock admission, cache refresh cadence, physics overrides and scripting remain separate source producers.

The production multiplayer runtime uses this seam for all 274 resolved automatic models. `BirthQueryCapture` records the constructor pose before advancing time, and full handles retire their cached bounds on destruction. Fixed/no-controller owners retain that strict initial cache. The 42 multi-frame clips use original `1C68C0`/`1C66A0`/`1C6560` phase arithmetic, retaining the binary32 overshoot at the authored frame-count-minus-0.0001 endpoint. Each full-handle lifetime catches up the explicit native simulation clock one tick at a time and passes the stored frame directly to `pose_model_world_frame`/`pose_model_nodes_world_frame`, without seconds conversion. Strict original metadata admission rejects alternative siblings or frame/effect/sound callbacks. The source proof covers 42,000 actual initialized updates and 8,296 independent controller-step cases; details are in `source-scenery-idle-phase.md`. The bounds service ports regular `BC820`/`BDEF0` refresh for that admitted native pose even while lighting remains frozen. Original clock admission and `B8600`/`BC470` activation scheduling remain unproved; an alive native handle is never represented as a measured original activation byte. The four known Zanzibar pillar placements 19–22 retain their separately labeled legacy preview until actual initial RNG history is supplied. An additional unresolved owner is rejected.

Original portal/PVS/frustum owner order, partial part/subpart masks, transparent queue sorting, asynchronous Xbox resource residency and dynamic-object contact queries remain separate admission services. This module does not claim final-framebuffer parity.

## Validation

`source_scenery_scene_tests` covers all 21 supplied original map caches. It admits 274 resolved automatic Slayer models: 196 baked and 78 dynamic, with four Zanzibar selections explicitly omitted. All six collectors are loaded and baked-prepared strictly; none requires a missing section offset or dynamic fallback. Two independent per-view submissions compare 548 selected LOD5/LOD0 collectors and 132,726 authored incident/RGB vertices against literal bucket offset/vertex records. The test also checks full generation/birth inputs, historical-selection rejection, hidden/destroyed admission and cache reset. Its cached-sphere service is an explicit test input, not a claim about an unimplemented live physics producer.

`source_scenery_gpu_tests` uses the actual Headlong `sign_vert_facade` SCEN (definition `E1EC0077`, placement3). It selects 444 source LOD4 and 120 source LOD0 vertices. Fresh/reused renderers match within one byte through 640×480 → 1280×720 → 640×480. Six wrong-LOD and six zero incident/RGB controls cause measured image differences only in the targeted view, with the other view's maximum error zero; restoring authored streams returns within one byte. Vulkan and synchronization validation are required and report no diagnostics. These controls prove actual GPU stream consumption, resize behavior and view isolation, not equality to an original full-map framebuffer.

Retained logs: `analysis/multiplayer-shading/source-scenery-final-all21.log`, `source-scenery-gpu.log`, and captures under `source-scenery-gpu-captures`. Original geometry collectors and LOD arithmetic are independently covered by the existing 5,550 source collector and 10,044 source chooser oracle cases; this scenery slice reuses those verified primitives.
