# Native TU1.5 phantom pair deletion

Actual live04 selected delete owner `320040`, listener `10068090`, pair
`4870A0`. This is a 41-site overlap-removal adapter, not an empty method.
The new semantic kernel and authenticated one-site `2E4D60 RET4` no-op pass
[39 physical cases with both compilers](../analysis/physics/native-phantom-pair-delete-tu15-20261101-qualified/report.json).
Actual nested live callback owners still require admission; no captured
positive phantom-delete input is claimed by this declared-model proof.

The source ignores its incoming listener receiver. It reads the first
handle/type; when type is two, it derives the two collidable payloads as
nonnull handle minus `10` hex, reads the first payload's phantom pointer at
`+20`, and calls phantom vtable `+20` with the opposite payload. After that
real callback, it rereads the second pair word and type. For a type-two
second object it rereads the current first word and dispatches symmetrically.
The second source dispatch is a tail jump with ordinary RET4 argument data.
The native function expresses the same typed service call and returns
normally; it does not serialize a return address or model a CPU stack.

`2E4D60` consists only of bytes `C2 04 00`. Its native owner reads no
receiver, argument, memory or FP state and has no effect. The production
binding may select this native no-op only for the authenticated owner. Any
other current virtual owner requires an explicit qualified implementation or
an informative refusal; the parent does not silently discard callbacks.

## Evidence and limits

The fixture executes unchanged instructions from the pinned English Xbox
TU1.5 image SHA-256
`21b207e7efdacaf6124a0822837f8be570766a42505057f7fd2d2ba8f409c4fd`.
Its pair/type/phantom/vtable DATA is explicitly declared valid model input,
with real original `2E4D60` execution as the callback. It is not represented
as a captured multiplayer pair. No callback result, GP/SIMD postimage or
expected AFTER image is supplied to the native execution.

The cases cover all combinations of types zero, one, two, three and
`FFFFFFFF`, both type-two directions, eight read-fault prefixes, and two
policy-unbound service-entry prefixes. Four independent current-DATA controls
at the first genuine callback return change the second type, second handle
or first handle; the following source rereads and callback arguments match.
These are declared observer input mutations, not claimed effects of the
source no-op. Both normal and tail paths assert actual original final
ESP equals incoming ESP plus eight, the normal RET4 contract.

All complete declared DATA banks, FP words, host FP preservation, 231 ordered
reads and 21 actual callback-entry owner/receiver/argument tuples match.
There are no persistent source stores in this owner. The tail path's formal
argument update belongs to the private original ABI; its current semantic
other-payload value is compared at the typed service boundary. Three mutants
(wrong first type, skipped second dispatch and wrong other payload) are
rejected. Thirty-eight of 42 authenticated owner/no-op sites execute; the
four zero-handle guard sites are outside the nonnull mapped-handle input
domain because the source first dereferences each handle's type.

The [local GP/XMM audit](../analysis/physics/native-phantom-pair-delete-input-context-tu15-20261101-qualified/report.json)
finds no semantic incoming GP dependency beyond ordinary formal DATA, and no
XMM use. Incoming ECX is allowed conservatively by the common audit but
unused by this body. The tail jump is an explicit service boundary. The first
conservative audit retained a false incoming-EDX dependency at authenticated
`320083 XOR EDX,EDX`; the qualified audit models this exact full-word zero
definition. The first report remains retained, with no source-byte waiver.
