# Complete retained grenade begin

The new `unit_grenade_begin` leaf ports the complete original `E95E0` direct
body and the original32-byte ordinary request constructor. Its original/native
differential passes three genuine owning cases: one admitted begin and two
actual ready-weapon rejections. It checks complete retained unit/weapon buffers,

It supplies no live throw, effect, channel, projectile, sound or world result.

## Original owning state and native bridge

The independent observer reuses the immutable
[source effect-pool begin](MP_GRENADE_EFFECT_POOL_BEGIN_RESEARCH.md). The new
original run reproduces its complete before/after state, request and returned
CPU exactly. It adds observation of every direct callee, including `E7EF0` and
`EF630`, without changing guest instructions or gameplay inputs/results. The
177 compared report/listing files and exported fixture repeat byte-for-byte.
Known NULL audio-driver boot is not rerun. Inherited platform/storage/resource,
fixed-clock/seed, physical and unavailable feedback boundaries remain declared.

The admitted allocator-owned identities remain player `EC700000`, Spartan
`E26F0000` and SMG `E2700001`. Its unit body is5750 bytes (`1676` hexadecimal).
Actual signed component offsets are:

| Unit field | Produced offset | Owning storage |
| --- | --- | --- |
| `+12A` | `1426` | retained animation manager |
| `+33E` | `14B6` | retained unit animation/control state |
| `+346` | `1632` | retained44-byte action component |

These are observed outputs, not offsets to install in a native unit. Native
`source_grenade_begin_action_storage()` follows the actual signed `+346` and
checks the complete span. Existing complete `C52C0`/`BD270` constructors own its
allocation, offsets and initialization. The bridge does not allocate an action
component, fill a unit body, set an active bit in advance, or use the old
synthetic `+704` address.

Required live inputs are actual unit object type `+AA`, parent datum `+14`, seat
`+1FC`, source flags `+134`, current hand `+212`, four full carried datums at
`+218`, current grenade type `+23C` and the retained component/managers. `+AA=0`

The caller must already own valid object storage and its full datum. Original
`E95E0` indexes low16 directly; it performs no salted object validation itself.
The source request producer clears eight DWORDs then stores type22 at offset0.
Its ordinary bytes `+4/+5` are zero. The new packet helper ports that exact
construction slice after separate input/dispatcher gates; it does not port full
`150F00` or admit Q. `E7F30`/ordinary scheduling remain separate owners.

## Complete direct body and mandatory services

The services in [unit_grenade_begin.hpp](../include/halo2/unit_grenade_begin.hpp)
provide stable mutable unit spans, complete authored `matg` grenade records,
actual parent-seat metadata and actual player records where required. Empty
grenade data denotes the original absent bank; a missing provider throws.
No source ownership, metadata, capability or readiness defaults are installed.
The explicit leaf interface carries these semantic operands:

| Original owner | Operands / output |
| --- | --- |
| `1055F0` | actual current weapon; defined AL gate |
| `112270` | unit; defined AL animation/capability gate |
| `B9C20` | parent, actual seat marker, count1, CL0; actual AX and12-byte output |
| `CF440` | unit, sign-extended current type; signed AX count |
| `EFEE0` | unit, hand0; defined AL controls channel preference |
| `E7FF0` | unit and action types22,8,18,0,10,27, in that order |
| `E7EF0` | unit, action19 |
| `115650` | unit, actual action identifier, literal blend bits `3E08B439`, CL0; AL and4-byte channel token |
| `1CA8D0` / `148160` | real channel token → XMM0 duration bits → actual duration bits → AL tick byte |
| `EF630` / `EFE30` / `C9A40` | unit; unit/feedback type26 or27; unit/scope0 |
| `1781F0` | effect, unit, EBX0, three zero stack operands, XORPS-zero XMM0 |
| `BCD80` / `A99F0` | actual definition callback datum; unit |
| `14F5D0` / `204173` | real unit→player owner (queried twice), player signed local user; EAX0/local/1/NONE notification |

These callback entries are TU1.1 semantic owner labels, not host executable
addresses. A native provider must execute its real owner or fail. In the tests,
each required leaf checks complete source before-buffers, applies its measured
whole after-buffers and returns its captured scalar/output. That closes direct
caller ordering and output parity, not the lower native implementations.

Ordinary begin rejects object type, weapon, capability/flag, seat, count and
already-active gates in original order. Cancellation occurs before channel
selection. A failed first preferred channel tries the actual alternate action;
failed channels return false. A successful channel writes phase1, counter0,
release0 and request mode; actual duration conversion writes the release byte
only when the original float comparison admits it. The literal zero comparison
word comes from the verified original-data provider. No fixed eight-tick delay
is substituted.

After scope/feedback, the actual optional begin effect and definition callback
execute, then `A99F0`, then `E993B` sets action bit22. The positive source effect
really allocates and retires its handle and returns `NONE`; that result does not
authorize a universal effect-NONE provider. The count remains2 during ordinary
begin. Later `E99B0`/`E8D60` owns preparation and debit.

The complete immediate branch instead stores phase1/counter0/mode0, invokes
real preparation and release with the request's two vectors, and returns AL0.
The missing-definition/nonpositive-count branch preserves the actual optional
local-user notification. These branches and parent-seat/alternate-channel paths
have complete instruction evidence; this suite does not dynamically exercise
them. Truncated host spans and absent services throw, rather than fabricate AL.

## Validation and live completion boundary

Registered CTest, strict GCC Release and GCC/Clang ASan/UBSan pass the same three
full-buffer cases. The packet constructor compares all32 bytes and all nine
stores per case. Callback arguments, order, complete before/after unit/weapon
buffers, defined AL and every direct action store match original outputs.
Missing-owner and truncated-component checks reject explicitly. Raw asset/body
fixtures stay ignored, not embedded in source.

Live Q needs genuinely retained constructor-owned action/managers plus these
actual lower services. The existing `unit_grenade` update/release/prepare kernels
can compose only their proved scopes. An admitted begin does not create a held
grenade or prove release, projectile ownership, attachment/marker, initial motion,
fuse, bounce, explosion, radius damage or network replication. Neither source
visual/voice/residency success nor working native grenade gameplay is claimed.
