# Native player shadows

**Status, October 28, 2026: the frozen 35-check cohort and seeded offline MCC Lockout on/off GPU cases passed.** The [acceptance receipt](../build/test-results/player-shadows-20261028/frozen-validation/acceptance.json) records exact source/runtime hashes, actual captured local-player ownership and bounded results. Original/pStencil passed at 640×480 and 960×720; Path Tracing passed at 640×480. This does not establish complete TU1.5 framebuffer parity, all-map acceptance, joining-client fixed shadows or launcher-selected runtime qualification. Earlier failed cohorts remain failed evidence; no launcher promotion was performed by this work.

| Original, ordinary offline or host native world | Original native projected-root selection, hierarchy, model/section/pose and command kernels feed fixed Generate/Apply GPU kernels and ordinary BSP receiver depth. | Requires the native world, completed camera and real target owners described below. Seeded offline 640×480 and 960×720 cases passed; live host GPU with a joined peer remains unqualified. |

The production integration is in [multiplayer_runtime.cpp](../src/gameplay/multiplayer/multiplayer_runtime.cpp), [SourceShadowScene](../src/rendering/shadows/source_shadow_scene.cpp), [source_live_shadow_selection_tu15.cpp](../src/rendering/shadows/source_live_shadow_selection_tu15.cpp), [source_live_shadow_roots_tu15.cpp](../src/rendering/shadows/source_live_shadow_roots_tu15.cpp) and [renderer.cpp](../src/rendering/renderer/renderer.cpp). Shadow pass residency is established before Renderer construction so a later graphics-mode change has its material and program resources available. Selected roots retain the actual original command masks and current source palettes; CPU root selection by itself is not evidence that either GPU phase rendered.

Authored shaders are compiled ahead of time by [compile_native_world_kernels.py](../tools/compile_native_world_kernels.py) and [compile_native_fragment_kernels.py](../tools/compile_native_fragment_kernels.py). The source-depth vertex/fragment and temporal raw-fragment variants preserve the authenticated program identities and fixed execution. Production does not interpret uploaded Xbox opcode streams. The original shader tokens remain admission and audit inputs; cleared interpreter fields in the production uniform are intentional.

Ordinary BSP receiver depth is owned by [SourceWorldDepthInput](../src/rendering/world/source_world_depth_input.cpp). The native main-camera receipt is issued only after the actual main call completes. It survives later first-person camera writes, but its consumer is valid only inside the same World's synchronous read-only render borrow. The final draw also requires the actual Renderer device/target lease and generation. Target preparation occurs before lease acquisition. Native-shadow frames submit synchronously so the borrow cannot escape to a render-overlap executor. A move-only per-frame observer scope owns its callback captures and issued main-camera frame; the World retains a weak registration. Scope exit releases captures and retires only that frame, including during exceptions and when a prepared World outlives the runtime. Conflicting registration or foreign clear is rejected rather than replacing the active owner.

The depth adapter verifies the selected ordinary BSP draw identities, actual resident/expanded geometry, original root/child pass identities, complete programs and declarations, material upload controls, texture/frame witnesses, lightmaps, camera and raster owners. Source eligibility follows an actual BSP draw key; another object using the same material slot does not acquire it. It reconstructs the original ordered W depth, near/far clipping and integer D24 encoding. It checks full immutable owners at admission, final upload and recording boundaries, while individual draw accessors retain the live capability checks. It does not repeatedly compare every texture byte for every draw.

Animated BSP stages consume the existing bitmap-frame producer. After its actual descriptor updates complete, Renderer issues an opaque bound-frame receipt containing the committed page, sampler and dimensional views. It binds the exact depth owner, material/pass identity, expanded slot, device and target generation, plus a unique borrowed upload epoch. Requested and bound frame indices must agree with the completed CPU animation selection captured by that frame's depth owner. The depth adapter compares the selected page against that exact immutable animation-bank entry and checks the prepared authored frame functions; static stages retain their literal captured frame equality. Copying a receipt cannot extend its epoch into another draw. This path preserves the existing animation result rather than selecting a replacement frame.

The current depth scope requires an ordinary full unsplit source viewport, zero requested main/offscreen AA, zero timed-boundary/near/far overrides, positive source dimensions and actual single-sample BGRA8/D24S8 attachments. It requires admitted class-0 position programs, preserved vertex inputs, authored cull `0` or `0x900` with their actual default/restored state lists, no relative/extended constant bank and no unresolved raster-changing state externs. Reverse cull `0x901` remains rejected. Animated texture pages without a completed bound-frame receipt still reject. Unknown ordinary programs or missing material/geometry owners reject the frame; they do not silently acquire approximate depth. Existing exact pStencil neutral-detail/environment adapters are admitted explicitly. Independently owned pool/infinite/edge water retains its existing later pipeline, with exact pass, source enum, selected layer, program and draw identity checks in [source_world_depth_scope.hpp](../include/halo2/source_world_depth_scope.hpp).

The fixed-shadow adapter currently submits projected roots only. The original `3D7E0` nonprojected route is keyed by creature object type `0x0C`; the adapter field named `local_light` does not establish a missing ordinary player point-light case. Roots with foreground clip-transition flag `0x800` or a per-entry fade other than `255` also remain outside the admitted draw contract. A seeded player case that never selects those states does not qualify them.

**Dynamic model receiver depth remains a bounded parity gap.** `SourceShadowScene` can produce genuine model receiver draws, but the new `SourceWorldDepthInput` contract admits ordinary BSP class 0 only. Normal model `titleDepth` uses the same source c3 W units with hardware varying interpolation. Raw shadow receivers reconstruct ordered W from snapped triangle coordinates and apply their own W clipping. Those computations can fall on opposite sides of an integer D24 boundary. [world.frag](../shaders/world.frag) already describes this boundary in its emblem W-depth path; the packed renderer also enables depth clamping specifically for `source_world_depth`, rather than every ordinary model pipeline. Shared units and valid model receiver submission therefore do not prove exact model receiver comparisons. Closing this gap requires an actual model-depth owner and class-1-through-6 raster/depth differential evidence, including D24 boundaries and clipping. No claim here covers exact depth for all receiver geometry.

The original requested-AA storage at `0x4117E0..0x4117E7` is restored as its exact eight mutable zero bytes from the authenticated TU1.5 image `21b207e7efdacaf6124a0822837f8be570766a42505057f7fd2d2ba8f409c4fd`, D3D section flags `7`. This supplies cold input storage and preserves later writes. It supplies no SDK device pointer, initialized flag or completed default-state result. Actual GPU attachment ownership remains independently mandatory. See [native_tu15_renderer_startup_data.cpp](../src/rendering/renderer/native_tu15_renderer_startup_data.cpp) and [native_tu15_world_memory_tests.cpp](../tests/native_tu15_world_memory_tests.cpp).

The position-program extension is deliberately bounded. [audit_source_world_depth_position.py](../tools/audit_source_world_depth_position.py) compares ordered scalar dependency DAGs for the original `oPos` output against eleven previously admitted complete-program seeds. It retains multiply/add order, signs, masks, paired old-operand reads, reciprocal distinctions and the `r12`/`oPos` alias; it discards only dead computations and register names. The current catalog contains 54 distinct candidate programs, of which 49 have a seed-equivalent position DAG. Production receives those complete exact byte arrays in [source_world_depth_position_contract.hpp](../include/halo2/source_world_depth_position_contract.hpp); five different position paths remain unadmitted. This is not permission to accept an arbitrary unknown program.

[test_source_world_depth_position.py](../tests/test_source_world_depth_position.py) additionally executes all 49 admitted programs and their seeds through the existing **test-only C++ token arithmetic reference**, with 128 deterministic states per program: 6,272 exact four-word position comparisons. These comparisons support the position contract. They are not unchanged Xbox CPU execution, physical GPU measurements, new pixel-program parity or whole-frame parity. The reproducible proof is [depth-position-dag-proof.json](../build/test-results/player-shadows-20261028/depth-position-dag-proof.json); [depth-material-inventory.json](../build/test-results/player-shadows-20261028/depth-material-inventory.json) is a material/pass inventory, not live all-map acceptance.

Temporal input scaling maps the raw Apply source viewport, clip regions and scissor to the physical target. Apply and ordinary receiver depth share the same actual viewport jitter; the fragment reconstruction subtracts that explicit offset before evaluating W depth. Generate remains on its authored 128×128 target without camera jitter. Zero-offset raw draws keep the original menu layout. The GPU test uses an actual original Regret resource/program/material with explicit diagnostic inputs. Its retained [temporal report](../build/test-results/player-shadows-20261028/frozen-validation/cohort-v5-x11/evidence/shadow-temporal-raster/report.json) passed with zero integer-translation errors, zero fractional native-viewport depth differences and zero Vulkan validation errors; omitting the offset produced 72 different depth samples. This validates that fixture's temporal raster transport, not the complete live shadow frame or every upscaler/resolution combination.

Path Tracing keeps primary first-person body visibility separate from secondary ray geometry. Offline/host secondary geometry is copied from the completed native WORLD collector, including its actual model/LOD, selected sections and current palette, before reusable source storage changes. Joining-client secondary geometry requires accepted full-model region/permutation and pose ownership and uses the explicit secondary LOD4 policy; it does not claim a camera-dependent native collector selected that LOD. Corresponding primary-body material ranges are replaced in ray geometry to avoid duplicate occluders. See [source_world_pose.hpp](../include/halo2/source_world_pose.hpp), [geometry.cpp](../src/rendering/path_tracing/geometry.cpp) and [geometry_tests.cpp](../tests/path_tracing/geometry_tests.cpp). The live receipt now counts body triangles after final BVH filtering, separately from held weapons. Each body count matches the designated current native root, definition/model, LOD, selected sections and exact ordered posed positions against the complete native body bank. Its positive final count must equal the full eligible bank; a weapon-only scene or exact same-material torso subset cannot satisfy that requirement. The component controls cover those negative cases, duplicates, BVH reordering, fade, degeneracy and foreign ownership. The visibility fragment declares the complete shared vertex interface, and both component and live tests reject Vulkan warning/error diagnostics.

Joining-client fixed shadows require more than removing the `source_model_world` guard. Ordinary joining worlds do not own the native render state needed for current camera, visibility, selection/history, model collection, receiver queries and command generation. A background authority replay candidate cannot be borrowed across executor or snapshot boundaries as a foreground presentation world. The required recipient owner, authenticated state channel, lifecycle merge and stale-cut controls are recorded in [client-owner-audit.json](../build/test-results/player-shadows-20261028/client-owner-audit.json). No such complete owner is implemented by this change.

The supporting same-host continuation checks now use `H2HOST05` to retain accepted pending/consumed inputs and motion-adoption history alongside completed cameras and full native model metadata. Their strict packet/world comparisons are described in [HOST_CONTINUATION_INPUT_STATE.md](HOST_CONTINUATION_INPUT_STATE.md). That bounded continuation proof does not supply a joining client's fixed-shadow render owner or complete a remote-to-local controller role transition.

The runtime wrapper requires a completed captured-tick receipt with the actual living local-player identity. Fixed modes require that same root in both Generate and Apply submissions; Path Tracing requires the captured living local player's current full-body owner and a positive final body-triangle count equal to its complete eligible bank; aggregate body-plus-weapon counts cannot pass. The visible control keeps native selection and ordinary depth, omits only the shadow GPU packets/additional ray occluders through `HALO2_REFERENCE_DISABLE_PLAYER_SHADOW_GPU`, verifies zero omitted submissions and unchanged player/root identities, then requires a pixel difference. It also rejects Vulkan validation diagnostics. The successful reports establish their bounded seeded map/camera/mode cases, not all maps, networking paths, framebuffer parity or launcher delivery. The body tests and wrapper explicitly select X11 only when using their owned xvfb server; direct game callers retain normal backend selection. A probe confirmed SDL otherwise selected the user's Wayland compositor even while xvfb supplied another DISPLAY, exposing those fixtures to uncontrolled desktop focus/input changes. Input assertions were preserved; no event filtering or control replacement was added.
