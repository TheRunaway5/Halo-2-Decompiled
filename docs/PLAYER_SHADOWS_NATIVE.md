The production integration is in [multiplayer_runtime.cpp](../src/gameplay/multiplayer/multiplayer_runtime.cpp), [SourceShadowScene](../src/rendering/shadows/source_shadow_scene.cpp), [source_live_shadow_selection_tu15.cpp](../src/rendering/shadows/source_live_shadow_selection_tu15.cpp), [source_live_shadow_roots_tu15.cpp](../src/rendering/shadows/source_live_shadow_roots_tu15.cpp) and [renderer.cpp](../src/rendering/renderer/renderer.cpp). Shadow pass residency is established before Renderer construction so a later graphics-mode change has its material and program resources available. Selected roots retain the actual original command masks and current source palettes; CPU root selection by itself is not evidence that either GPU phase rendered.

Authored shaders are compiled ahead of time by [compile_native_world_kernels.py](../tools/compile_native_world_kernels.py) and [compile_native_fragment_kernels.py](../tools/compile_native_fragment_kernels.py). The source-depth vertex/fragment and temporal raw-fragment variants preserve the authenticated program identities and fixed execution. Production does not interpret uploaded Xbox opcode streams. The original shader tokens remain admission and audit inputs; cleared interpreter fields in the production uniform are intentional.

Ordinary BSP receiver depth is owned by [SourceWorldDepthInput](../src/rendering/world/source_world_depth_input.cpp). The native main-camera receipt is issued only after the actual main call completes. It survives later first-person camera writes, but its consumer is valid only inside the same World's synchronous read-only render borrow. The final draw also requires the actual Renderer device/target lease and generation. Target preparation occurs before lease acquisition. Native-shadow frames submit synchronously so the borrow cannot escape to a render-overlap executor. A move-only per-frame observer scope owns its callback captures and issued main-camera frame; the World retains a weak registration. Scope exit releases captures and retires only that frame, including during exceptions and when a prepared World outlives the runtime. Conflicting registration or foreign clear is rejected rather than replacing the active owner.

The depth adapter verifies the selected ordinary BSP draw identities, actual resident/expanded geometry, original root/child pass identities, complete programs and declarations, material upload controls, texture/frame witnesses, lightmaps, camera and raster owners. Source eligibility follows an actual BSP draw key; another object using the same material slot does not acquire it. It reconstructs the original ordered W depth, near/far clipping and integer D24 encoding. It checks full immutable owners at admission, final upload and recording boundaries, while individual draw accessors retain the live capability checks. It does not repeatedly compare every texture byte for every draw.

Animated BSP stages consume the existing bitmap-frame producer. After its actual descriptor updates complete, Renderer issues an opaque bound-frame receipt containing the committed page, sampler and dimensional views. It binds the exact depth owner, material/pass identity, expanded slot, device and target generation, plus a unique borrowed upload epoch. Requested and bound frame indices must agree with the completed CPU animation selection captured by that frame's depth owner. The depth adapter compares the selected page against that exact immutable animation-bank entry and checks the prepared authored frame functions; static stages retain their literal captured frame equality. Copying a receipt cannot extend its epoch into another draw. This path preserves the existing animation result rather than selecting a replacement frame.

The current depth scope requires an ordinary full unsplit source viewport, zero requested main/offscreen AA, zero timed-boundary/near/far overrides, positive source dimensions and actual single-sample BGRA8/D24S8 attachments. It requires admitted class-0 position programs, preserved vertex inputs, authored cull `0` or `0x900` with their actual default/restored state lists, no relative/extended constant bank and no unresolved raster-changing state externs. Reverse cull `0x901` remains rejected. Animated texture pages without a completed bound-frame receipt still reject. Unknown ordinary programs or missing material/geometry owners reject the frame; they do not silently acquire approximate depth. Existing exact pStencil neutral-detail/environment adapters are admitted explicitly. Independently owned pool/infinite/edge water retains its existing later pipeline, with exact pass, source enum, selected layer, program and draw identity checks in [source_world_depth_scope.hpp](../include/halo2/source_world_depth_scope.hpp).

The fixed-shadow adapter submits projected roots. The original `3D7E0` nonprojected route is keyed by creature type `0x0C`; its adapter field `local_light` does not establish an ordinary player point-light gap. Per-entry fade and foreground clip-transition flag `0x800` now carry an owned entry contract: the actual completed projection, authenticated `44A8A0` operand, ordered constants and native minimum-W transport are retained. Their current source and regression fixtures require final cohort acceptance; a seeded case that never selects these states supplies no coverage of them.

Model receiver depth is implemented in [SourceModelDepthInput](../src/rendering/world/source_model_depth_input.cpp). It joins actual native object/definition/model/LOD/section, complete original primitive ordinals, declared vertex class, palette and material owners to the final submitted primary geometry. Fixed native CPU position prefixes for admitted classes 1 through 6 compose with exact admitted ordinary position programs; original vertex order is retained for snapped triangle W reconstruction, clipping and integer D24 encoding. Native main MACH/SCEN submissions retain their actual selected geometry and PRT ownership before secondary collection. Missing or foreign owners, reverse winding, changed programs or unsupported classes reject; sharing c3 units alone grants no depth proof. The [bounded implementation/component receipt](../build/test-results/player-shadows-finish-20261028/depth-source.json) records the arithmetic/owner controls. Current coherent linked and live GPU acceptance is pending, and unknown programs or all-map framebuffer parity remain outside that receipt.

The original requested-AA storage at `0x4117E0..0x4117E7` is restored as its exact eight mutable zero bytes from the authenticated TU1.5 image `21b207e7efdacaf6124a0822837f8be570766a42505057f7fd2d2ba8f409c4fd`, D3D section flags `7`. This supplies cold input storage and preserves later writes. It supplies no SDK device pointer, initialized flag or completed default-state result. The position-program extension is deliberately bounded. [audit_source_world_depth_position.py](../tools/audit_source_world_depth_position.py) compares ordered scalar dependency DAGs for the original `oPos` output against eleven previously admitted complete-program seeds. It retains multiply/add order, signs, masks, paired old-operand reads, reciprocal distinctions and the `r12`/`oPos` alias; it discards only dead computations and register names. The current catalog contains 54 distinct candidate programs, of which 49 have a seed-equivalent position DAG. Production receives those complete exact byte arrays in [source_world_depth_position_contract.hpp](../include/halo2/source_world_depth_position_contract.hpp); five different position paths remain unadmitted. This is not permission to accept an arbitrary unknown program.

[test_source_world_depth_position.py](../tests/test_source_world_depth_position.py) additionally executes all 49 admitted programs and their seeds through the existing **test-only C++ token arithmetic reference**, with 128 deterministic states per program: 6,272 exact four-word position comparisons. These comparisons support the position contract. They are not unchanged Xbox CPU execution, physical GPU measurements, new pixel-program parity or whole-frame parity. The reproducible proof is [depth-position-dag-proof.json](../build/test-results/player-shadows-20261028/depth-position-dag-proof.json); [depth-material-inventory.json](../build/test-results/player-shadows-20261028/depth-material-inventory.json) is a material/pass inventory, not live all-map acceptance.

Temporal input scaling maps the raw Apply source viewport, clip regions and scissor to the physical target. Apply and ordinary receiver depth share the same actual viewport jitter; the fragment reconstruction subtracts that explicit offset before evaluating W depth. Generate remains on its authored 128×128 target without camera jitter. Zero-offset raw draws keep the original menu layout. The GPU test uses an actual original Regret resource/program/material with explicit diagnostic inputs. Its retained [temporal report](../build/test-results/player-shadows-20261028/frozen-validation/cohort-v5-x11/evidence/shadow-temporal-raster/report.json) passed with zero integer-translation errors, zero fractional native-viewport depth differences and zero Vulkan validation errors; omitting the offset produced 72 different depth samples. This validates that fixture's temporal raster transport, not the complete live shadow frame or every upscaler/resolution combination.

Path Tracing keeps primary first-person visibility separate from secondary rays. When a native render frame exists, both host and joined secondary geometry come from its completed native WORLD collector with actual model/LOD, sections and palette copied before reusable source storage changes. A joined replica fallback requires its accepted full-model permutations/pose and explicit secondary LOD4 policy; that fallback never claims native camera selection. Corresponding primary material ranges are replaced to avoid duplicate ray occluders. Final BVH receipts count the designated full body separately from guns and require its positive count to equal the complete eligible bank. Weapon-only, partial same-material torso, duplicate, foreign-pose, fade and degenerate controls remain mandatory. See [geometry.cpp](../src/rendering/path_tracing/geometry.cpp) and [geometry_tests.cpp](../tests/path_tracing/geometry_tests.cpp). The complete shared shader interface and strict Vulkan warning/error checks remain enabled.

The [native shadow transport](../src/runtime/source_shadow_transport.cpp) carries a complete named-field checkpoint or exact-base delta plus the real encoded gameplay body selected at the same closed native boundary. Its roster/native admissions are independent of the checkpoint's claimed player metadata. Raw LAN, retained System Link and ONLINE use the same lane; dedicated producers have zero genuine producer views, while each recipient still requires one to four admitted local views. This presentation admission does not grant migration or recovery authority. Generic recovery budgets remain unchanged. The separate shadow policy is 32 MiB encoded, 192 MiB raw, 160 MiB native materialization, 1,024 MiB parser and 1,536 MiB weighted staging, with bounded retained images and delta workspace. The final production-cap census is pending; the earlier larger diagnostic run is sizing evidence only.

[SourceShadowPresentationOwner](../src/rendering/shadows/source_shadow_presentation_owner.cpp) decodes the owning immutable image, performs full native preparation and real local-view rebind, preserves eligible full-salt render/history state, rechecks the connection, then commits. Only successful adoption can issue the cut's native ACK. Imported banks retain their real backing-owner token and revision: cold storage uses actual activation, partial storage still rejects, and reusable C++ addresses cannot authorize another bank. `H2HOST05` continuation proofs remain separate; see [HOST_CONTINUATION_INPUT_STATE.md](HOST_CONTINUATION_INPUT_STATE.md).

[SourceNativeRenderTimeline](../src/rendering/shadows/source_native_render_timeline.cpp) owns the two exact historical body receipts. Native WORLD geometry, regions, attachments, depth, light/material inputs, decals, contrails and visual effect clocks use that same closed state. Ordinary gameplay, collision/input, audio, HUD and first-person packets keep advancing. The latest local camera/FP pairing requires matching full-salt player, unit, weapons, configuration, seat, death and teleport identities; a mismatch suspends native rendering. Explicit private cut continuity admits only progressing same-world/generation cuts within 120 actual ticks. Default ordinary gap-1 interpolation is unchanged. Native state ahead of or more than 120 ticks behind the ordinary/client front also suspends, preserving the ordinary replica fallback. Receipts report both clocks, cut serial, lag and suspension; they do not claim native WORLD updates at 30 Hz. Decode/import remains synchronous and can stall one foreground interval; its timing must remain visible.

Latest gameplay effects and historical graphics own independent preloaded SCEN/MACH/BLOC adapters and effect/RNG/journal state. Forks share resident material identities without writing each other's render banks; ordinary rewind guards remain strict. World-lifetime changes retire stale graphics state. The current independent latest45/native32 and material/PRT identity regression is awaiting linked acceptance with the rest of the matrix.
