# Frontend post-process raster extension

The native aspect extension preserves the centered 640x480 camera image. Its bloom targets are originally 160x120 and its patchy haze target is originally 320x240. Enlarging these targets with a plain integer ceiling and mapping the whole target onto the drawable changes the original center's sampling density.

For a 1280x720 drawable, the original centered image is 960x720. A plain 214x120 bloom target maps 160.5 texels onto that center, and one horizontal tap spans 1280/214 = 5.981308 physical pixels instead of the original 960/160 = 6. The resulting horizontal bloom is about 0.31 percent narrower. A plain 427x240 haze target maps 320.25 texels onto the center. The haze's continuous coordinates are correct when its rows scale by the drawable ratio, but the intermediate sample grid changes. These are post-process sampling changes, not world geometry stretching.

`frontend_post_raster()` pads each original target by whole pairs of texels. Both the original base dimensions and the padded dimensions are even, so the center starts at an integer texel offset. It retains the rational active width and height separately from the allocated image size. The `crop` rectangle maps the full drawable into the padded target; `source` is its inverse and maps the threshold pass's padded target back into the drawable. `scale` expands completed original haze rows by padded/base, and the direct haze quad uses the crop rectangle for its target coordinates.

At 1280x720, bloom remains 214x120 and haze becomes 428x240. The active widths are 213⅓ and 426⅔ texels respectively. At 2560x720, bloom is 428x120 with an active width of 426⅔; haze is 854x240 with an active width of 853⅓. The extra fractional outer coverage is cropped on composition. The original center retains its texel spacing and phase. At 4:3 all dimensions and mappings are exact identities.

The tests exercise centered texel locations, threshold tap spacing, composite lookup coordinates, haze noise coordinates, and phase at 4:3, 16:9, 16:10, 21:9, 32:9, 5:4, 1000x600, and an odd 1919x1081 drawable. The helper changes native presentation mappings only; it does not change the original effect programs, taps, weights, haze state, or noise-generation algorithm. Float upload rounding remains bounded by the tests and is not a claim of full-frame retail pixel parity.
