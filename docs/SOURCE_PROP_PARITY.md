# Source type11 prop submission

`SourcePropScene` submits the authored BLOC objects that were absent from the multiplayer world. Its resident materials are allocated before the renderer is created. It uses actual source model-region selections and preserves the region collector's section order, original source vertex identities, per-section PRT streams, object colors and independent lighting state. It does not emulate Havok motion.

## Original creation and material selection

The initial persistent phase is `18F000 → D5560(0)`. The `D5990` damageable mask `0x199F` includes type11, so eligible BLOC placements enter that phase independently of whether they have names. `D5060` rejects NeverPlaced objects; the SCEN game mask branch remains type6 only. Native scene lifetime synchronization uses the global content placement index, actual full generation handle, visibility, root transform and creation tick.

Type11's constructor is `11BBF0`, from descriptor `468180 + 2C`. It initializes the type-specific field at object `+12C` and requires `20A9A0` to resolve a nonempty `phmo +38` body bank. It sets prop bit1 when definition `+BC` bit0 is set or all body types are 1/2. Those type-specific flags are distinct from generic object flags used by `D1850` lighting queries. The decoder reproduces these conditions without changing generic runtime flags.

All 415 admitted supplied multiplayer BLOC placements have render models and positive physics body counts. Five have animation graphs, but all generic initial controller selections are NONE; the SCEN named-idle override is not applied to props. Every initial model-region selection resolves deterministically. Ordinary model shaders select source lighting implementation2 through `2D000`'s model branch. PRT materials select authored layer5 implementation0, with no substitution of ordinary lighting.

The constructor prepares 807 ordinary dynamic shader-table entries and three PRT entries. The legacy LOD5 diagnostic geometry uses 784 ordinary slots and all three PRT slots across 415 objects, producing 215,511 triangle-expanded vertices. Its remaining 23 prepared entries are unused. The resident LOD0..5 union uses 793 ordinary slots and 18 distinct PRT slots; 14 prepared ordinary entries remain unused by that union. Materials remain distinct between owners. PRT passes receive a separate source coefficient bank for each LOD and selected section; the base and unrelated overlays do not receive that bank.

Initial change colors use the complete original `BE240` producer, including its constructor-position/channel hashes, actual selected variant name, weighted permutations and HSV interpolation. This producer consumes no primary random values. Seventy-nine supplied props have authored color channels; none of the 415 has a later `BE8E0` color function. The scene therefore retains the source initial bank without substituting a lower-bound preview color or inventing runtime color functions.

## Zanzibar crane source identity

The original final capture20 events7621/7651 are `main_crane`, not flywheel. They match the authored section0 raw position, UV, normal basis, PRT SHORT1/SNORM16 stream and complete part indices. Event7651 uses `zanzibar_crane_prt` (E93407BF); event7621 uses `grating_prt` (E93E07C9). The source placement is type11 ordinal24, definition E93107BC, render model E93307BE, at (-5.211551666, -1.593515754, 6.710000038), with unit scale and identity root orientation.

The source collector orders crane sections `[0,1,2]`. Section0 uses node map `[1]`. The actual source WORLD node1 multiplied by its authored inverse bind matches all 12 captured palette words exactly. The `SourcePropScene` section0 banks match all 157 consumed source c68..109 words for both captured materials. Unwritten padding and literal datum bits in unused components are excluded from the equality claim. Authored crane final pixel constant C16 is white and agrees with the original. The flywheel's authored gray constant is preserved.

Production poses apply the actual object root before descendants (`BD090`) and skin the complete WORLD bank with literal inverse binds (`1376C0`). Query bounds, PCA projection and rendered geometry consume the same rooted hierarchy. A post-skin placement transform is not used. The local arithmetic retains raw bind quaternions; the reciprocal seed follows the explicit software-reference convention in `source-model-pose.md`, with physical CPU precision still open.

Source evidence is retained in `original20-main-crane-identity.json`, `original20-main-crane-bank-proof.json` and `zanzibar20-main-crane-pixel-bank-proof.json` under `analysis/multiplayer-shading/original-xemu/prt-output-audit`. The scene regression consumes the literal source bank fixture `tests/fixtures/retail_main_crane_bank.tsv`.

## Lighting query state and physics bounds

`BDEF0` first attempts the type11 physics override when object `+B4` is valid and `+C0` bit6 is set. `1D44F0` additionally requires positive physics group count, physics flags bits5/11 and definition `+1C` bit1 clear. Each group returns its cached quantized broadphase AABB through `2E1090 → 2E0020`; authored geometric shape bounds are not interchangeable with those bounds. The routine expands each box by its maximum authored body margin, aggregates the boxes, and computes center and half-diagonal radius plus the source 0.001 scalar.

The retained actual crane satisfies every override gate. Its current backend result differs from its cached object sphere. The cached sphere equals regular authored initialization in this captured state, but this does not authorize replacing later physics updates with a regular node0 sphere. The renderer uses the caller's actual cached query state through `SourcePropScene::lighting_query_state`, including velocity and generic runtime flags. The legacy diagnostic `update` and the production admitted `append_view` require that producer; missing inputs raise an admission error. `source_prop_physics_sphere` implements the recovered aggregation arithmetic over explicit original backend AABBs; the cold insertion, quantization and update cadence remain the physics producer's responsibilities.

The bounded PRT-only material admission rejects every generic object-lighting extern. Captured crane section0 submits its complete independently proven PCA bank independently of generic lighting state. The complete selected crane model also has an ordinary material consumer, which requires the callback. Owner-cache advancement precedes selected shader binding in `4B5D0`; PRT-only selections and empty resident collectors still evaluate the admitted owner cache. Only ordinary selected passes receive its uniform binding. Every admitted scene owner requires the actual query-state callback, independently of the part shader mask. The existing map-light sampler keeps unresolved dynamic contact ownership explicit. Scene submission, metadata inventory and shader bank equality do not establish moving prop physics, object-contact lighting, dynamic shadows, network lifetime replication or framebuffer parity.

- 415 untouched `11BBF0/20A9A0` constructor executions and 1,245 matching native decoder words.
- 800 untouched `1D44F0` aggregation fixtures, with 3,644 exact success/center/radius components. Backend AABBs are explicit inputs in this arithmetic oracle.
- All 21 map scene constructors, 415 separate object material ranges and ordinary-lighting bindings, and the literal 157-word crane section0 source bank.
- Complete untouched `BE240` over 4,096 synthetic fixtures/24,570 RGB words, plus all 79 colored prop constructors/264 authored RGB words, match the independent native color helper bit for bit.
- Independent original capture identity, PRT input, coefficient and pixel-combiner evidence described above.
- `source_prop_gpu_lighting` retains 4,356 real Headlong `bus_chassis` LOD5 vertices and submits its authored LOD3/LOD0 streams (1,674/819 vertices) with the original constructor-query state. Controlled source distance inputs choose these streams; this is not a live camera or original framebuffer claim. Fresh/reused renderers agree within one byte through 640×480 → 1280×720 → 640×480. Six wrong-geometry controls and six zero-light controls visibly change only the selected viewport. The other viewport stays byte-identical, and restoring its geometry/bank restores the frame. Vulkan synchronization validation reports no diagnostics. This demonstrates ordinary geometry/bank consumption, updates and isolation.

The reproducible scripts are `prop-constructor-original.py` and `prop-physics-sphere-original.py` under `analysis/multiplayer-shading`. The GPU captures/log are `source-prop-lod-gpu-captures` and `source-prop-lod-gpu.log` in the same directory. Production initial-query integration is validated separately from later moving-body physics.

## Geometry detail and view admission

`133790` computes separate source coverage and camera-distance metrics from the cached sphere. `4BCC0` calls `4C450` with the distance metric, the render model's cutoffs and the submitting player's previous LOD. PRT objects are capped at LOD4 unless actual object flag19 forces LOD5. The retained original wheel, flywheel, blades and crane records all have flag19 clear. The source resident collector orders model regions and preserves repeated sections; a residency miss may fall back to the prior LOD through `4C190`.

The metadata audit `object-geometry-lods.json` proves that all 415 admitted rendered props and 48 admitted rendered machines select identical ordered section arrays at LOD4 and LOD5. Lower levels differ: LOD0/1/2 change the selected arrays of 224 props and eight machines; LOD3 changes 213 props and eight machines. `SourceObjectGeometry` preloads every exact selected LOD0..5 collector through the explicit five-argument cache loader. Empty collectors stay empty; source section order and duplicates remain ordered. Ordinary slots share only within one owner/source shader; PRT slots are keyed by owner, LOD, section and source shader. Each slot binds that LOD's actual stream and coefficient bank, so two source views do not replace one shared material bank.

Production `update_pose` advances and poses the resident geometry and coefficient banks. `append_view` accepts the source player index/count, actual `133790` distance producer, actual object flag19/control bit2, and source `4BA019` modifier. It applies original `4C450` hysteresis and the `4BCC0` cap using independent retained signed bytes for each owner/view. Each admitted view evaluates the owner cache using its unmodified original distance. `3DFE0` deduplicates actual query frames: a later view may query when an earlier view skipped for cadence. Empty resident collectors emit no geometry or binding but still evaluate the owner cache; hidden owners remain unsubmitted. Cold type11 query state retains `object+C1` bit0 from the proven `D5560 → BF0F0 → D5060 → B7B40` request path. Initial invalid frozen caches still query; later valid frozen caches retain their state. Later physics and frozen-bit transitions remain separate required inputs. A new full generation handle resets the view bytes. Legacy `append` remains an explicit LOD5 diagnostic.

All 464 automatic MACH/BLOC cold prefixes have flag19 clear and control `+10A` zero. The supplied scenario/camera producer owns source `4BA019`; later HS/control mutations require their actual state. Native resources are decoded and resident before renderer allocation. This does not simulate the original Xbox asynchronous cache queue/residency fallback, faded visibility, model-part visibility mask or transparent sort-section queue. Those inputs cannot be inferred solely from a model's shader table or a diagnostic camera.
