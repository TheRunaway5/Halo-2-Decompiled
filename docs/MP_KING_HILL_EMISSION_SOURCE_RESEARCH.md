# Original King hill CPU emission corridor

Research snapshot: 2026-10-12. The unchanged retail hill helper now supplies executed CPU packet evidence for the source geometry loop: 22 declared post-preparation cases emitted 1,452 vertices, 726 RGBA point-pairs and 61,160 command bytes. Every case stops before `19FC12`, without closing/submitting the strip or returning from the whole helper. This adds emitted geometry evidence to the earlier [visual-consumer research](MP_KING_VISUAL_CONSUMERS_SOURCE_RESEARCH.md); it does not establish successful hill material preparation, GPU acceptance, pixels, normal King admission or completion of the all39 goal. [Original-only tool](../tools/research_king_hill_emission.py), [frozen raw report](../analysis/multiplayer/game-variants/king-hill-emission-source-20261012/complete/report.json).

**Executed ranges and frame correspondence.** Each case creates a fresh emulator over the same captured memory. The code hook compares every observed original instruction with unchanged retail XBE bytes; only fresh caller storage, declared camera/tick inputs and the explicit register assignments below are supplied. No instruction is patched, and no original function return, bitmap/I/O result, SDK success or readiness byte is supplied. The bounded composition is:

1. Execute whole `D4BC0(shader=F2C81143,0,0,15,0,NONE,record*)`. All22 calls return `AL=1` and the original record bytes `a5a5a5a50000ffff0000a5a5ffffffff64224e8000000000`. Untouched A5 bytes remain declared caller storage, not initialized state invented by the harness.
2. Enter original `19F680` with its actual custom ABI and the real filler output. Execute its distance/attenuation prefix and stop before the original call instruction at `19F73C`. This produces the actual inner/outer locals and leaves the original callee-saved shader/LOD/layer/implementation values available.
3. Explicitly resume at `19F75F`, after the unexecuted material-preparation call. Execute the unchanged metadata walk through `19F840` and stop before `19F844`. This resolves UV register1 from real shader/template/pass/vertex metadata; the harness does not supply a resolver result.
4. Preserve the observed stack and FPU/control state. Assign ESI from actual captured `[407488]` and EAX from that device's captured current command pointer, the literal loads performed at original `19F88C` and `19F897`. Explicitly resume at `19F8AD`, run the arithmetic/emission loop, and stop before `19FC12`.

Ranges `19F73C..19F75E` and `19F844..19F8AC` remain unexecuted. They include the material/declaration/program/texture preparation, cull-state handling and dirty flush. Their success is not implied by the entry frame. The actual post-preparation GPU/program state of a successful original King draw is therefore still unknown. [Complete helper listing](../analysis/multiplayer/game-variants/king-hill-emission-source-20261012/complete/whole-19f680.asm), [observed original instructions](../analysis/multiplayer/game-variants/king-hill-emission-source-20261012/complete/observed-original.asm), [per-phase register/frame states](../analysis/multiplayer/game-variants/king-hill-emission-source-20261012/complete/report.json).

**Finite corpus and emitted values.** Sixteen baseline cases combine four camera offsets from the actual hill center—`(0,0)`, `(R,0)`, `(2R,0)`, `(1.4R,0.8R)`—with ticks10117/0/59/60. Camera inputs are stored as explicit binary32 words. Tick10117, signed16 rate30 and the other clock bytes come from captured clock `82D498E8`; only clock+8 is changed for the declared timeline cases. Baseline FPCW is captured `023F`, MXCSR is captured `1FA0`. Four additional center cases use FPCW `063F`, `0A3F`, `0E3F`, `027F`; two more use the other measured view RGB and neutral RGB. No camera, geometry, time or color value is inferred from final rendered pixels. [Full case inputs](../analysis/multiplayer/game-variants/king-hill-emission-source-20261012/complete/report.json).

Every case writes exactly 2,780 bytes into the captured buffer range `83F9EC64..83F9F740`, below captured limit `83FA0FB0` (9,036 available bytes initially). There are166 normal method packets: begin `(000417FC,6)`, then33 groups containing one four-float `1AB0` color, two two-float `1888` UVs and two four-float `1A00` positions. No capacity-wait owner is entered. All original non-caller writes are verified to stay within that command span or the first12 device bytes; original resource headers/readiness/backing data are not rewritten. [Raw commands, packets and all862 writes per case](../analysis/multiplayer/game-variants/king-hill-emission-source-20261012/complete/report.json).

The observed source loop produces point indices0..31,0. Each point supplies `(x,y,center.z,1)` with UV `(u,1)`, then `(x,y,center.z+0.8,1)` with UV `(u,0)`. Both positions use the same original RGB and source-computed per-point alpha. Closing positions equal the first pair while their u values continue accumulating. The report's `cases[].vertices` is decoded directly from these emitted packets as `position0_bits[4]`, `uv1_bits[2]`, `rgba11_bits[4]`; it is not a host recomputation of the source formula. `cases[].pairs` records loop index, selected point, local RGBA/UV/position words and actual FP state immediately before the color command. [Emitted vertex and pair records](../analysis/multiplayer/game-variants/king-hill-emission-source-20261012/complete/report.json).

For baseline center/tick10117, the first lower/upper positions are raw words `(C05200CE,BF8641BB,C1070000,3F800000)` and `(C05200CE,BF8641BB,C0F46666,3F800000)`. Initial u is `3F1DDDDE`; first RGB is the measured view literal and alpha is `3F800000`. These are original emitted values. Actual begin value6 and method-to-attribute naming (RGBA11/UV1/position0) use the locally pinned xemu interpretation already cited by the earlier visual note; this CPU run does not execute its GPU backend. [Raw first packets](../analysis/multiplayer/game-variants/king-hill-emission-source-20261012/complete/report.json), [prior literal-method evidence](MP_KING_VISUAL_CONSUMERS_SOURCE_RESEARCH.md).

The two actual FISTPs at `19F8F0` and `19F906` each load binary32 input bits `41C2E2A4`. Both produce12 under FPCW `023F`, `063F`, `0E3F` and `027F`; both produce13 under `0A3F`. Requested controls remain observed before and after each conversion; no call helper resets the word between phases. UV-edge accumulation subsequently uses x87 arithmetic and differs between rounding controls even when the converted repeat count agrees. Initial u instead comes from the unchanged SSE signed remainder/conversion/division path: tick10117 yields `3F1DDDDE`, tick59 gives `3F7BBBBC`, ticks0/60 give0 and identical complete command streams. [All44 actual FISTP observations and14 distinct streams](../analysis/multiplayer/game-variants/king-hill-emission-source-20261012/complete/report.json).

**Binding scope.** This supplies a small independent original CPU comparison corpus for native geometry generation, including camera-dependent alpha, original UV accumulation, actual time/rounding controls and the source register identities. The existing native geometry layout has no equivalent per-vertex RGBA11 alpha seam; a material tint alone cannot carry this output.
