# Original King hill and objective visual consumers

Research snapshot: 2026-10-12. King has separate registered world-boundary, objective-marker and text consumers. The unchanged Xbox owners determine the boundary shape, view-dependent opacity, colors and marker records; authored `mulg`, `shad`, `stem`, `spas`, `vrtx`, `hudg` and `bitm` data determine their resources. This note supplies complete CPU color results, original marker/draw prefixes, real shader-record filling, complete far-view draw returns and static emission contracts. It does not establish a rendered hill, original GPU submission/completion, framebuffer parity, normal King admission or completion of the all39 goal. [Original-only tool](../tools/research_king_visual_consumers.py), [frozen report](../analysis/multiplayer/game-variants/king-visual-consumers-source-20261012/complete/report.json).

The earlier [King engine research](MP_KING_ENGINE_SOURCE_RESEARCH.md) owns the scenario-marker/spline and registered-engine contracts; [callback research](MP_KING_NATIVE_CALLBACK_RESEARCH.md) owns the gameplay callback dependencies. This slice begins at their actual visual callbacks and retains original instructions rather than treating decompiler prototypes as ABI evidence.

**Authority and reproduction.** These are the three actual executable inputs. The tool runs their real registrations before reading the King table and checks every executed instruction against its original image, including the reached SDK instructions. The positive probes load the complete, pinned retail Lockout cache and its literal tag index into each executable's isolated context. Supplying those same cache bytes to all three images is a declared input composition, not proof of every title-update cache or a naturally booted renderer. **Draw ABI and boundary geometry.** The complete hill draw callback consumes seven stack arguments `a0..a6`, returns with `RET1C`, and ignores a1/a5. After its count gate it computes color for the current render view's local player. It calls the boundary helper with `EDX=a0`, `ECX=a2`, `EAX=a4` and nine stack arguments `(a3,a6,state+64,32,state+164,radius,perimeter,RGB*,0.8)`. Thus actual dispatch supplies shader datum, LOD ordinal and implementation ordinal in those registers; the stack supplies layer15, the real 24-byte record, all 32 spline points, center, radius and perimeter. The submitted 32-point count does not change when the source control-marker count differs. The helper returns with `RET24`. [Complete callback](../analysis/multiplayer/game-variants/king-visual-consumers-source-20261012/complete/instructions/retail-002be5d0.asm), [complete helper](../analysis/multiplayer/game-variants/king-visual-consumers-source-20261012/complete/instructions/retail-0019f680.asm).

Before graphics, the helper uses camera XY and the original center/radius. For positive finite radius R, it calculates x87 XY distance minus R, stores the difference as binary32 and tests the still-live x87 result against0. The nonnegative branch loads the stored value and clamps it to `1.5R`; the negative branch selects0. It computes `f=1-d/(1.5R)` in the listed SSE order. If `f<=0`, the complete helper returns. Otherwise `inner=(f*R)*2`, `outer=inner+(R-epsilon)` with epsilon bits `38D1B717`; the later binary32 denominator is `outer-inner`. The corpus covers camera distance multiples `0,1,2,2.5,3,10` using real Lockout geometry. All three images return completely for the latter three distances. Near cases preserve the actual registers, stack and XMM bits at the first graphics-state owner. These ABI-only probes use explicit arguments `a0..a6=100..106` and stop before the filled-record read; the separate real-filled-record composition supplies actual shader/record inputs. [Helper `19F680..19F741`](../analysis/multiplayer/game-variants/king-visual-consumers-source-20261012/complete/instructions/retail-0019f680.asm), [measured draw prefixes/returns](../analysis/multiplayer/game-variants/king-visual-consumers-source-20261012/complete/report.json).

The remaining loop is **static recovery**, beyond the measured SDK boundary. No boundary vertex or UV command was actually emitted by this corpus. Its precise source contract is nevertheless retained in the complete 408-instruction helper:

1. Begin literal command words `(000417FC,6)` and eventually close `(000417FC,0)`.
2. Iterate j=0..32 inclusive, selecting `i=j` except j=32 selects point0. At each point compute alpha as the clamped x87 expression `(outer-distanceXY(point[i],camera))/(outer-inner)`, with the listed binary32 stores and comparisons.
3. Emit command `00101AB0` followed by source RGB and that alpha. The same color applies to both vertices of the pair.
4. If semantic3 was found, emit `00081880+8*register` followed by `(u,1)`. Emit `00101A00` followed by `(point.x,point.y,center.z,1)`.
5. If semantic3 was found, emit its UV command with `(u,0)`. Emit the second position with `(point.x,point.y,center.z+0.8,1)`.
6. After each pair, decrement u by the x87 edge length from previous point to current point times the stored scale. For i=0 the previous index is31, otherwise it is j-1. The first decrement therefore uses edge31→0, and the closing iteration uses that same edge. Preserve this ordering.

The UV repeat count is `max(2,FISTP(perimeter/(height*1.2)))`, where the multiplier's literal binary32 bits are `3F99999A`; FISTP observes the active x87 rounding control. The source actually performs its second FISTP on the admitted `>=2` branch. UV scale is converted repeat/perimeter. Initial u uses signed `clock.tick % (2*sign_extend16(clock.rate))`, converted and divided by that denominator. This slice does not execute these FISTPs or establish a numeric UV corpus, alternative rounding controls, invalid radius/perimeter/rate behavior or raster-center equivalence. [Helper `19F8AD..19FC6B`](../analysis/multiplayer/game-variants/king-visual-consumers-source-20261012/complete/instructions/retail-0019f680.asm), [literal constant bytes](../analysis/multiplayer/game-variants/king-visual-consumers-source-20261012/complete/report.json).

For naming only, the locally pinned xemu register header identifies begin value6 as TRIANGLE_STRIP; its method consumers map `1A00` to attribute0, `1AB0` to attribute11 and `1888` to attribute1. This is backend interpretation of the literal original command words, not a physical NV2A or framebuffer claim. [xemu register definitions](../tools/reference/xemu-0.8.136/hw/xbox/nv2a/nv2a_regs.h), [2F/4F consumers](../tools/reference/xemu-0.8.136/hw/xbox/nv2a/pgraph/pgraph.c), [pinned file hashes](../analysis/multiplayer/game-variants/king-visual-consumers-source-20261012/native-seam-inspection.json).

The read-only native snapshot identifies bounded integration opportunities, not completed bindings:

- The existing `SourceKingState` already preserves the real 32 points, center, radius, perimeter and occupants; the whole color owner and marker-record producer have independently captured original outputs suitable for native CPU comparison. Preserve the distinct active-player/ordinary-player iterators and real imported palettes.
- The hill needs the exact settings-selected shader, LOD0/layer15/implementation and its animation/resources. Existing world material preparation's layer15 branch does not admit this actual `transparent_simple_world`/self-illumination pass. Its existing transparent draw bank requires a completed geometry service, not an invented successful collector callback.
- The source geometry loop varies alpha per polygon sample. Native `Vertex` currently has RGB but no corresponding alpha field, and the ordinary vertex adapter keeps v11 in the material bank. A per-draw tint alone cannot carry the source's RGBA11 input for every pair. Exact strip positions/UV/color should receive original emission comparison before renderer admission.
- Generic score HUD already has a source-type/round-mode interface. Live snapshots must supply source4, actual round selector and real scores/wins instead of relying on type2 defaults. Marker projection, directional arrows, occlusion/state/bitmap delivery, other-player markers and the slot28 outer text caller remain additional source-consumer work.
