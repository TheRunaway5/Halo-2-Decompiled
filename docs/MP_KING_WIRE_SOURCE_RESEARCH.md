# Original King wire codec and optional-field builder contracts

Research snapshot: 2026-10-12. King encoding is an ordered sequence of seven optional fields, with per-field checkpoint rollback and capacity reservation. Decoder validity, field presence, stream overflow, and application are separate results. A writer can succeed with no fields retained; a decoder can reject after modifying its bank. These contracts come from unchanged original instructions, not a proposed native packet format. [Complete original-byte report](../analysis/multiplayer/game-variants/king-wire-source-20261012/complete/report.json), [replication bank/application research](MP_KING_REPLICATION_SOURCE_RESEARCH.md).

The [static inspection tool](../tools/inspect_king_wire_contracts.py) starts with the immutable three-image replication report, derives helper addresses from genuine direct-call instruction positions, and checks complete original owners in retail, TU 1.1 and TU 1.5. It saves 42 listings and 28 complete static pairs for 14 owners. There are **zero codec executions** in this tool, no native imports, no instruction patches and no supplied returns. Root's independently owned wire oracle and native module are separate. [Manifest, mappings and comparisons](../analysis/multiplayer/game-variants/king-wire-source-20261012/complete/report.json).

## Stream and builder storage

The stream fields consumed here are `+00` backing pointer, `+04` signed byte capacity, `+0C` mode, `+10` signed cursor in bits, `+14` error byte, `+18` checkpoint count, `+1C..2B` four checkpoint words, `+2C` discarded bit-span, and `+30` discard counter. These owners do not allocate the backing or establish its initial contents. [Bitstream layout reconstruction](../tools/reference/halo2-decompiled/include/bitstream.h), [whole checkpoint owner](../analysis/multiplayer/game-variants/king-wire-source-20261012/complete/retail-checkpoint_pop-00194710.asm).

The builder is `0x34` bytes: stream pointer `+00`, first index `+04`, count `+08`, requested mask `+0C`, started `+10`, written `+14`, discarded `+18`, truncated `+1C`, initial-space byte `+20`, current index `+24`, name pointer `+28`, supplied reservation `+2C`, and current reservation `+30`. Initialization is expanded in the real shared/King writers. It clears the masks, sets current index to `NONE`, name to zero, computes `reserve = supplied_reservation + field_count`, and sets initial space according to `remaining_bits >= reserve`. The begin/end helpers do not independently revalidate that initial-space flag or enforce index bounds; King uses indices `0..6` in ordered begin/end pairs. [Expanded shared initializer](../analysis/multiplayer/game-variants/king-wire-source-20261012/complete/retail-shared_write-000a4ab0.asm), [expanded King initializer](../analysis/multiplayer/game-variants/king-wire-source-20261012/complete/retail-king_wire_write-0009a3a0.asm), [builder layout reconstruction](../tools/reference/halo2-decompiled/include/flags_writer.h).

### Begin, commit, discard, and truncation

Field begin records its index/name, ORs the started bit, pushes the current stream cursor into the actual checkpoint array and increments checkpoint count. If its requested bit is set, it ORs a true presence bit into backing when at least one declared bit remains, increments the cursor regardless, marks written, and returns true so the caller emits the payload. An unrequested field returns false without advancing the cursor at begin. It still has a checkpoint. [Whole begin](../analysis/multiplayer/game-variants/king-wire-source-20261012/complete/retail-field_begin-000b56e0.asm).

Field end considers rollback only for a written field. A discarded bit forces rollback. Otherwise it compares remaining declared bits with the **current reservation before decrementing it**; insufficient space marks the field truncated and forces rollback. On rollback it clears that written bit and calls real checkpoint discard with true. On commit, or an unrequested field, it merely decrements checkpoint count. If the final written bit is clear it advances one bit for a false presence marker. Finally it decrements current reservation and resets current index/name. This leaves earlier committed fields intact. [Whole end](../analysis/multiplayer/game-variants/king-wire-source-20261012/complete/retail-field_end-000b5760.asm).

Checkpoint discard pops a saved cursor. With discard true it restores that cursor. In writing mode 1, when the current cursor is later than the saved one, it also records attempted span in stream `+2C`, increments `+30`, preserves only bits below the saved offset in the checkpoint byte, and zeroes **all later bytes through the declared end of the buffer**. It does not limit clearing to the attempted payload. In another mode it still restores the cursor but skips this backing cleanup. With discard false it only pops the checkpoint. The error byte is not restored or set by this owner. [Complete unchanged checkpoint owner](../analysis/multiplayer/game-variants/king-wire-source-20261012/complete/retail-checkpoint_pop-00194710.asm).

An unrequested field only advances over its false marker; it does not clear a preexisting backing bit. Integer writes likewise OR the first word. Therefore initial backing is an actual input, and the codec is not a complete-buffer serializer into arbitrary dirty bytes. Buffer zeroing, if required by a particular caller, belongs to its actual setup owner and is not invented here. [Begin/end instructions](../analysis/multiplayer/game-variants/king-wire-source-20261012/complete/retail-field_end-000b5760.asm), [integer write instructions](../analysis/multiplayer/game-variants/king-wire-source-20261012/complete/retail-write_bits-00195720.asm).

## Capacity and ordered fields

Let `R` be the King's supplied reservation and `remaining = (capacity_bytes << 3) - cursor`, evaluated by the source's signed 32-bit instructions. The shared writer receives `R+2` and initializes its five-field builder with current reservation `R+7`. If the initial test fails it returns false without emitting those fields or changing the caller's written mask. Otherwise it visits every shared field in order and ORs its retained written mask into the caller mask, then returns true even if that mask is zero. King then tests the remaining bits against `R+2`, initializes its two-field builder with that reservation, visits fields 5/6, ORs its retained bits, and returns true. If this second gate fails, it returns false without undoing prior shared output. [Whole shared writer](../analysis/multiplayer/game-variants/king-wire-source-20261012/complete/retail-shared_write-000a4ab0.asm), [whole King writer](../analysis/multiplayer/game-variants/king-wire-source-20261012/complete/retail-king_wire_write-0009a3a0.asm).

The current reservation checked at end is `R+7-index` for shared indices `0..4`, then `R+2` for hill and `R+1` for occupants. Since the current field's presence/payload have already advanced the cursor, this is one bit more conservative than counting only later presence markers. For a bounded zeroed stream with `R=0`, hill-only payload occupies 11 bits but retaining it requires 12 available starting bits; occupant-only occupies 23 but retaining it requires 24. These are direct arithmetic consequences of the complete owners, to be independently exercised by the separate oracle. [End comparison before decrement](../analysis/multiplayer/game-variants/king-wire-source-20261012/complete/retail-field_end-000b5760.asm), [two expanded reservation initializers](../analysis/multiplayer/game-variants/king-wire-source-20261012/complete/retail-king_wire_write-0009a3a0.asm).

| Index / mask | Presence and payload |
| --- | --- |
| 0 / `01` | Team mapping exists; five unsigned words at bank `00,02,04,06,08` with widths `8,9,8,8,8`, then nine ordered designators at `0A..1A`, four bits each when the bank `+02` bit selects them. |
| 1 / `02` | Phase exists; bank `+1C` unsigned byte, two bits. |
| 2 / `04` | Finished exists; bank `+1D != 0`, one bit. |
| 3 / `08` | Round exists; signed bank `+1E`, five bits. |
| 4 / `10` | Timer exists; sign-extended bank `+20` plus 1, 16 bits. |
| 5 / `20` | Hill exists; sign-extended bank `+24` plus 1, four bits. |
| 6 / `40` | Occupants exist; unsigned bank `+26`, 16 bits. |

The writer is driven by requested bits, not by comparing with a previous bank. The returned written mask preserves the caller's preexisting bits through OR; decoder flags have different replacement semantics below. [Shared payload sequence](../analysis/multiplayer/game-variants/king-wire-source-20261012/complete/retail-shared_write-000a4ab0.asm), [King payload sequence](../analysis/multiplayer/game-variants/king-wire-source-20261012/complete/retail-king_wire_write-0009a3a0.asm).

Checked values outside the encoded width reach the real formatting diagnostic and then still reach the primitive bit write. The diagnostic formats `%u exceeds max value of %u` via original `_vsnprintf`, terminates the destination at byte `FF`, and returns; it neither aborts nor marks stream error. The primitive masks to available width. Thus selected designators `8..15` fit the writer's four-bit check but are invalid to the reader; hill 15 diagnoses `16`, then encodes low four bits zero, which reads as hill `NONE`. These are boundary contracts, not normal authored hill admissions. Original formatting/CRT execution must not be replaced with a fabricated successful service return to claim whole-owner coverage. [Diagnostic owner](../analysis/multiplayer/game-variants/king-wire-source-20261012/complete/retail-checked_value_diagnostic-000b66f0.asm), [checked hill branch](../analysis/multiplayer/game-variants/king-wire-source-20261012/complete/retail-king_wire_write-0009a3a0.asm), [checked shared values](../analysis/multiplayer/game-variants/king-wire-source-20261012/complete/retail-shared_write-000a4ab0.asm).

The shared size owner selects the minimum applicable value from `01→4A`, `02→07`, `04→06`, `08→0A`, `10→15`, or zero when none applies. King adds two and clamps with `min(result,0B)` for bit `20`, then `min(result,17)` for bit `40`. This method is not the total encoded size: no requested fields gives size 2, while successful zero-request writing still visits seven presence fields. Do not convert it to a maximum or a sum. [Whole shared size](../analysis/multiplayer/game-variants/king-wire-source-20261012/complete/retail-shared_size-000a4950.asm), [whole King size](../analysis/multiplayer/game-variants/king-wire-source-20261012/complete/retail-king_wire_size-0009a2c0.asm).

## Primitive bits, backing, and overflow

Integer write/read compute `n = min(requested_width, remaining_bits)`. When `n > 0`, they handle one or two little-endian 32-bit words, taking low-order bits first. Write ORs the first word; on a word crossing it **assigns the entire second word**. Read combines the words and masks to `n`. Both advance cursor by the full requested width even when only part is available; integer read returns zero when `n <= 0`. Neither sets the stream error byte. [Whole write](../analysis/multiplayer/game-variants/king-wire-source-20261012/complete/retail-write_bits-00195720.asm), [whole read](../analysis/multiplayer/game-variants/king-wire-source-20261012/complete/retail-read_bits-001959c0.asm).

Those primitives load/store full words, so the supplied physical backing must cover the rounded word span, including padding beyond a non-word-aligned declared capacity. One-bit read additionally uses an inclusive cursor test: **at cursor exactly equal to declared bit capacity, it reads the next backing byte**. Only cursor greater than capacity produces false without a read. It always increments cursor. Guard-byte and word-padding contents therefore need explicit recording in a boundary fixture; a host replacement must not silently substitute zero and claim original equivalence. Negative sizes/cursors, malformed checkpoint counts, and signed arithmetic wrap are not admitted normal packet contexts by this static note. [Whole one-bit read](../analysis/multiplayer/game-variants/king-wire-source-20261012/complete/retail-read_bit-001957d0.asm), [whole integer read](../analysis/multiplayer/game-variants/king-wire-source-20261012/complete/retail-read_bits-001959c0.asm).

The separate overflow query returns `cursor > capacity_bytes*8 || error_byte != 0`. Neither the King nor shared reader invokes it. A returned true from the King reader consequently does not prove that the declared packet span was sufficient, or that the stream error byte was initially clear. Whether a particular outer packet owner subsequently rejects overflow remains a distinct caller contract, not a reason to change this decoder's return or erase its partial output. [Whole overflow query](../analysis/multiplayer/game-variants/king-wire-source-20261012/complete/retail-stream_overflowed-001946f0.asm), [whole King reader](../analysis/multiplayer/game-variants/king-wire-source-20261012/complete/retail-king_wire_read-0009a530.asm), [whole shared reader](../analysis/multiplayer/game-variants/king-wire-source-20261012/complete/retail-shared_read-000a4e20.asm).

## Reader validation and partial output

Shared read starts structural-valid true and an observed mask zero. A present mapping immediately stores all five words, then checks `bank04 ⊆ bank00`, `bank08 ⊆ bank04`, `bank06 ⊆ bank08`. Invalid subset relations skip the designator loop entirely. Otherwise it visits nine entries: unselected entries become `FFFF`; selected entries are read/stored and must be signed nonnegative and less than eight. The first invalid selected entry remains stored, stops the loop, and leaves later entries unchanged. [Complete mapping validation](../analysis/multiplayer/game-variants/king-wire-source-20261012/complete/retail-shared_read-000a4e20.asm).

After invalid mapping data the reader still attempts phase/finished/round/timer presence and payload reads from its **current cursor**, including unread designator bits that may now be interpreted as later presence flags. It ORs observed shared bits into the supplied read-mask pointer and returns structural validity only. There is no bank, cursor, or mask rollback on invalid data. Shared read with no fields observed returns true and contributes zero flags. [Complete shared reader including unconditional later fields](../analysis/multiplayer/game-variants/king-wire-source-20261012/complete/retail-shared_read-000a4e20.asm).

King read initializes its local mask to zero and retains shared validity. It then always attempts hill and occupant presence reads, even after shared-invalid. Present hill is `read4 - 1` stored as i16; present occupants are `read16` stored as u16. It **replaces** the caller output mask with the observed shared/King bits on both success and failure. The final result is `shared_valid && observed_mask != 0`. Field presence is sufficient; values equal to the existing bank still count as observed. No observed fields returns false. Truncation can still produce stored payloads/flags and true when a presence bit was read and shared structural data remains valid; the separate overflow query is not folded into this boolean. [Complete King reader](../analysis/multiplayer/game-variants/king-wire-source-20261012/complete/retail-king_wire_read-0009a530.asm).

There is no decoder check that the hill is an authored group, the occupant bits correspond to currently occupied player slots, or selected team-designator values are unique. The nine-bit assignment mask is not validated against an additional mask; the explicitly listed subset/index checks are the shared structural checks. Stronger semantic admission, if needed by an actual caller, must come from that caller's original contract. [Whole King reader](../analysis/multiplayer/game-variants/king-wire-source-20261012/complete/retail-king_wire_read-0009a530.asm), [whole shared reader](../analysis/multiplayer/game-variants/king-wire-source-20261012/complete/retail-shared_read-000a4e20.asm).

This yields intentionally different outcomes that a native binding must preserve: a capacity-qualified empty writer can succeed with zero written fields; its all-zero presence packet decodes to false, and structurally invalid input can leave partial bank/output changes despite false. Reader failure does not authorize applying those changes to live gameplay. That application decision belongs to the actual caller, and no external caller success has been supplied here. [Writer returns and OR](../analysis/multiplayer/game-variants/king-wire-source-20261012/complete/retail-king_wire_write-0009a3a0.asm), [reader returns and replacement](../analysis/multiplayer/game-variants/king-wire-source-20261012/complete/retail-king_wire_read-0009a530.asm), [separate original application owners](MP_KING_REPLICATION_SOURCE_RESEARCH.md).
