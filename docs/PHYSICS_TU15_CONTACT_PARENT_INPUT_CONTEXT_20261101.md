# TU1.5 contact-parent input context

Native `325810` and `08FDB0` remove motion CPU-state postimages from the contact
advance path. The next original contact parent must therefore be checked for
consumption of those caller-volatile values before its own definitions.

The [physical entry audit](../analysis/physics/native-contact-parent-input-context-tu15-20261101-first/report.json)
reaches actual `2F7A50` by executing unchanged original `3205B0` and its genuine
motion owners from the explicitly retained Warthog BEFORE input. It then runs
the unchanged complete contact parent from the same actual current banks under
twenty declared incoming contexts in each of eleven actual/declared time and
velocity cases: 220 complete original parent executions. The variants replace
all XMM registers with zero, ones, finite, quiet/signaling NaN, and denormal
patterns; poison each XMM register separately; and vary EAX/EDX together across
zero, `FFFFFFFF`, and `DEADBEEF`.

Every variant matches all 89,734,533 persistent bytes and complete FP state.
The audit does not consume captured AFTER data or supply a callback result,
guest register postimage, or original outcome to native gameplay. The original
actual-entry banks are independent inputs for this offline liveness experiment.
All owned reference/compiler products are removed: 299,872,256 allocated bytes,
with no large retained artifacts.

An independent [local source audit](../analysis/physics/native-contact-parent-xmm-tu15-20261101-final/report.json)
checks all reachable local paths of `2F7A50` (40 sites), `304350` (534), `2F36F0`
(575), and `2E4FE0` (256). It finds no incoming XMM lane read before a local
definition. Control-flow merges intersect definite lane masks. Calls remain
explicit interprocedural boundaries and supply no assumed register definition.
The local audit alone does not establish transitive callee liveness.

This is bounded input-context evidence for the retained contact-parent cohort.
Other parents, unexercised branches, incoming callee-saved GP changes, returned
control-stack bytes, and caller-volatile GP/SIMD postimages remain outside this
comparison. Native world binding and visible multiplayer acceptance are
separate gates.

## Full producer's remaining raw comparison

The native `304350` parent remains unqualified for production. A
[before-copy diagnostic](../analysis/physics/native-contact-producer-constructor-diagnostic-tu15-20261101/constructor-difference-summary.json)
reproduces the representative 100-byte raw failure and shows that its original
`303EE0` constructor inputs already differ before the verified record copy.
Hardware write watchpoints identify the first three words of that temporary:
the previous `2E4FE0` query's `PUSH EBX` at `2E4FEC`, `PUSH ESI` at `2E4FFD`,
and `PUSH EDI` at `2E4FFE` leave their saved values in storage later reused by
the partially initialized record constructor. The current offline bridge
passes genuine receiver/arguments but retains older preserved GP values.

At this query phase, original `304350` itself has defined EBX as the current
child, ESI as the resolved component, and EDI as the current twelve-byte
candidate-entry cursor. Other differing temporary fields include earlier
inverse-transform output and service/control spills; they require explicit
source-owned lifetime work. No expected bytes are installed, no raw bytes are
waived, and no zero-filled constructor packet substitutes for the original
data. The diagnostic does not by itself show that `325810` postimages are
consumed; the physical entry-context audit above tests that separate boundary.
