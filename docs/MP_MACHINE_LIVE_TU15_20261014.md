# TU1.5 live machinery ownership audit

This audit uses only the English TU1.5 executable, SHA256
`21b207e7efdacaf6124a0822837f8be570766a42505057f7fd2d2ba8f409c4fd`.
It includes a visible activated Zanzibar gate check. Moving-platform/support
parity and the remaining device/script scope are still open.

The actual object update path is B8F40 -> BE4A0 ->10DD10. The complete10DD10
dispatcher reads the type table474B90 and inherited descriptors at+84, then
calls their+40 callbacks at10DD5B. The actual DEVI and MACH descriptors bind
10B840 and1179C0 there. Their394/472 complete instructions already belong to
the registered scene-device module; `scene_device_tu15_entries.json` pins their
original sites/callees. No new missing-owner claim is made for these bodies.

Original10C790 constructs the actual device group bindings. Global4ECBF8
owns the original group pool, with12-byte records. It writes private group
current/initial values at+4/+8 and flags at+2, then stores full power/position
group identities at device+130/+13C and current values at+134/+140. These
fields come from the whole original constructor, not an inferred layout.
Read-only original listings and raw descriptor windows are retained under
`analysis/multiplayer/physics-live-tu15-20261012/machine-live-owner-audit-v311`.
The initial10B730 candidate was inspected and is the49-instruction group
retirement callback; it is not labeled as the device motion update.

Before the v319 integration, native `Simulation::step_impl` also called
`step_devices`; that path advanced
`SourceDeviceWorld`'s separate motion/group bank before the completed original
source object/world pass. Source scene roots/WORLD nodes are subsequently
published from the actual source bank. The device snapshot still reads the
native device owner. This is an observed ownership boundary that requires a
paired live-state/control audit; it is not yet a demonstrated state divergence.
The resulting integration gate was to compare actual TU1.5 device/group state and
control effects against the native snapshot, establish the correct authority
and readback paths, and visibly exercise moving machinery and supported riders
over UDP. Do not replace these gates with the completed gravity-lift sweep.
