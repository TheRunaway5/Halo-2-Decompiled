# Typed vertex input and post-skin residency review

This is a read-only review of the production declaration and post-skin input
adapter after the bounded Elite reflection correction. It found no further
submitted-material input mismatch in the supplied ordinary BSP/model corpus.
It does not establish complete rendering parity or authorize unknown local
compiled classes.

## Original class and pass propagation

Original `1CAA0`/`1CB20` select the compiled class from section classification,
part type and the corresponding opaque/transparent influence count. The native
`VertexOrigin::vertex_class` retains that choice per expanded source part.
`SourceDynamicModelShaders` prepares each highest/lower shader record with the
same actual part class; a class-dependent operation creates a separate resident
slot. Pass selection remains based on the literal original shader LOD bank.

The adapter admits the extra normal operation only for the exact original
reflection payload identities documented in `SOURCE_CPU_SKIN_INPUTS.md`.
Environment and before/after overlay children are copied before their own
modifier is assigned. The literal authored declaration and program bytes are
retained. The supplied reflection references occur only in layer7 or layer15:
the dynamic-role corpus contains21 Elite FP glow layer7 links and21 Elite body
`soc_eyes` layer15 links. No affected reflection pass occurs in a bloom or
planar child. Those child families are not silently covered by the limited
recursive adapter.

The independent all21 placed-model review in
`analysis/multiplayer-shading/cpu-skin-scene-admission-review.json` executes
136 original part/class selector cases and checks1,296 authored reflection
pass/collector references. All are rigid classes1/2 (1,070/226 respectively).
The current SCEN/MACH/BLOC preparation paths therefore do not omit a required
reflection skin-normal operation. This is an authored six-LOD inventory with
the report's explicit initial-selection inputs, including the unresolved
Zanzibar pillar fixture boundary; it is not a runtime visibility census.

## Packed selector admission

The typed world adapter admits class0 and only literal semantics
`{0,3,4,5,6,8,9,14,19,20}`. Registers omitted by the original list retain their
constant attributes. Empty/unknown/local or skinned raw semantic banks are
rejected rather than interpreted as world inputs.

Bit7 of the first packed selector marks an authored mapping. Bit6 modifies
only the Normal selector4, producing68 for the proved post-skin operation.
The unused-register sentinel is255. These values do not overlap any admitted
literal semantic. A missing declaration accepts only the existing explicit
legacy/procedural Preserve path; requesting normalization without an authored
Normal register fails. The UBO remains3,712 bytes with the four-selector bank
at offset3,696. PRT semantic19/20 admission requires the explicit PRT input
bank. Source reflection class6 remains a rejected adapter request; other
already validated class6 program families keep their existing behavior.

## Mutation and ordinary update review

`shader_animation.cpp` derives `forward_transforms`, `forward_diffuse` and
`forward_specular` from the final `program_constants` bank. The ordinary color
binder changes the matching attribute as well as its derived diffuse field.
Object lighting changes the program/constant bank. The source pass/vertex
program/declaration assignments found in material, world, environment,
atmosphere and surface preparation are preparation-time assignments; no
current runtime producer replaces these resident instructions after allocation.

The controlled all21 authored-parameter probe is
`analysis/multiplayer-shading/typed-input-field-update-review.cpp` and its log.
It examines resident tables, including unused entries:5,193 BSP pass records
over31,158 producer events have805 derived-field changes and zero changes
independent of program/constants. The210 dynamic role model banks contribute
4,074 pass records and24,444 events, with210 derived-field changes. Its clocks,
curve inputs, colors and light state are explicit controlled inputs, not claims
about original runtime producers.

The42 initially apparent model exceptions are the two `elite_honor_armor`
table slots per cache. The separate literal-role geometry probe
`typed-input-unused-honor-review.cpp` and `.ndjson` verifies all42 have zero
selected vertices across21 caches. A detailed Cyclotron probe records an
initial derived diffuse value differing from the already default-bound v10
attribute. Animating repairs that unused duplicate without changing the bank.
Applying the actual owner-color binder before animation removes the discrepancy.
Production binds owner colors before `SourceDynamicModelShaders` and Renderer
allocation. These observations do not justify broadening the updater's
early-return comparison for the currently submitted BSP/model passes.

There is a latent ordinary residency guard omission: the updater checks its
packed declaration/modifier for interpreted slots, but does not compare raw
`vertex_program` or selected pass identity against the allocated instructions.
A caller changing those fields could retain old GPU instructions. No current
runtime writer was found, so this review does not call it a visible source
mismatch. Any tightening should first include a deliberate stale-program
mutation control and preserve normal animated constants/frame updates.

## Shadow admission and validation limits

The shadow plan and resident slot comparison both require the authored
Preserve input policy and literal phase declaration/program. A resident Apply
normal cannot accidentally receive the reflection normalization operation.
Generation keeps source UV semantics while Apply keeps source Normal semantics;
their preferred typed-loader GPU controls are separate from the reference-input
fixture route.

The original local/boned payload, compute input/output, world-class0 and neutral
authored Renderer checks remain documented in `SOURCE_CPU_SKIN_INPUTS.md` and
`SOURCE_VERTEX_DECLARATION_PARITY.md`. This review ran only CPU/read-only probes
during the parent's immutable gameplay capture window. It made no production,
header, GLSL, runtime, shared-build or GPU-state change.
