# BSP per-view shader selection

`tests/source_bsp_shader_scene_tests.cpp` composes the recovered source
camera, portal traversal, BSP admission, projected coverage and shader LOD
services with the production `SourceBspShaderScene`. It tests all 21 supplied
original Xbox maps. The inputs and expectations retain the original map banks;
no expected selection is generated by the scene under test.

## Independent inputs and comparisons

The frozen `retail_source_transparent_parts_assets.tsv` retains literal BSP
cluster bounds, instance definition IDs, authored world spheres, original part
words and shader identities. `retail_source_shader_lod_assets.tsv` retains raw
shader bias and projected-height threshold words. Their independent cache
exporters and the individual untouched-executable differential tests establish
the input and pure helper contracts.

The test checks the native loader against every supplied cluster bound and
instance sphere. It obtains source part coverage from the frozen banks, then
composes the separately verified source `1BEB0` view multipliers, `2C490` player
multiplier, cluster/instance projection, byte quantization, `1BF50` shader
selection and instance alpha/stipple helpers. The selected part commands must
match owner, section, ordinal, material, shader LOD, coverage byte and alpha.
Alpha-zero commands must disappear. Every retained vertex preserves original
order and all fields except the expected material index and stipple level;
every omitted vertex must have a corresponding rejected source command.

Every root's alternative shader slots are independently prepared from its
literal shader datum, explicit selected LOD and actual baked/per-vertex policy.
The test compares full program words and fragment offsets, vertex bytecode,
128 constant float words, sampler/raster/blend state, bitmap bytes/mips and
ordered environment/overlay/bloom children. It checks those banks again after
all views. Each original vertex's actual lightmap ID must be resident for every
alternative root slot: **14,158 distinct material/lightmap pairs**. This catches
the missing lower-LOD descriptors found by the production renderer captures.

## Camera and view cases

Each map has seven explicit source camera cases covering one, two and four
local views. Camera positions start from authored player locations with an
explicit .35 vertical fixture offset and must resolve to an actual source
cluster. The original grid, angle, projection and `441B0` frustum producers
feed `173130` portal traversal, `16E210` containing-fog results and `134390`
BSP/instance admission. Safe rectangles equal outer rectangles, feature
adjustments are off, and the portal mask is the explicit all-open cold mask.
For Gemini this is a cold-mask test; it does not establish live door state.

Four additional consumer cases use an explicit complete authored command
bank: near, far, repeated near after another view, and a camera giving a real
authored instance partial alpha. The far camera is outside the map. These
cases test the selector consumer without claiming that the original portal
producer would admit an outside-map gameplay camera. Repeating the near view
must reproduce every output word after the other view, and prior view storage
must remain unchanged.

The 231 cases select **10,753 lower-LOD parts**, of which **1,980** come through
the complete source camera/portal/BSP producer. They omit **3,955 alpha-zero
instance submissions / 952,014 vertices**, with **164 alpha-zero submissions**
through that producer, and retain **525 partial-alpha part submissions**.

## Verification boundary

This gate proves production-linked CPU preparation and per-view shader
selection from source-backed inputs. The regular and ASAN/UBSAN CTest runs use
`retail_source_bsp_shader_scene`; sanitizer checks enable leak detection. Run
provenance, cache/fixture/source/binary hashes and per-map counts are retained
in `analysis/multiplayer-shading/bsp-shader-scene-proof.json`.

The test does not establish GPU descriptor submission, stipple raster
orientation, live player camera state, door-mask history, model shader LOD,
partial-part sorting/culling, or framebuffer equality. Those remain separate
source services and renderer gates. Infinite water retains its independently
recovered explicit shader LOD0 service; ordinary BSP pool/edge materials have
no lower authored record in these maps.
