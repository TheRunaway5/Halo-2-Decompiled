# Original item interaction-point producer

The separate [oracle](../tools/oracle_mp_item_point_1_1.py) executes untouched `FBFA0` and its actual helpers on **208 literal original current item snapshots** from the frozen visibility/retreat fixtures. Every emitted point and full EAX return matches the prior original execution: **205 root fallbacks and three SMG ground-marker/ordinary-plane projections**. The projection cases also match the prior defined marker and plane output bytes. The source current object/header/node/region bytes, real Lockout metadata and relocated collision BSP are supplied inputs; this replay adds no pose, contact, collision, Havok or marker service. [Report](../analysis/multiplayer/integration/inventory-source/pickup-item-point/report.json), [original visibility](MP_PICKUP_VISIBILITY_RESEARCH.md), [retreat](MP_PICKUP_RETREAT_RESEARCH.md).

Prior tools, reports, exports and production remain unchanged. A separate process reproduces this new report and its original instruction listings byte for byte. The [independent audit](../tools/oracle_mp_item_point_audit_1_1.py) checks literal current inputs, original byte listings/cache operands, all earlier point/return results, 207 consumer-ID correlations and the original quaternion/composition/projection rounding against captured output. Exported expectations are captured fields, never calculated audit values. [Manifest](../analysis/multiplayer/integration/inventory-source/pickup-item-point/manifest.json), [audit](../analysis/multiplayer/integration/inventory-source/pickup-item-point/audit.json).

## Entry, identity and return ownership

`FBFA0` receives the full item datum in **ECX** and writable point pointer in **EAX**. It resolves `4E78D0 → pool+44 → headers[(datum & FFFF)*0C]+8`. Item `+12C` is read as a **byte**, and bit 5 selects marker/contact processing. Bit5 clear calls `BACC0` with item datum in EAX and output in ESI. Missing marker AX0 also takes this fallback. The item-point routine writes all three point words and returns full **EAX=0 for fallback, EAX=1 for projection**, because its epilogue clears EAX before `SETE AL`. A root fallback is a valid defined point; `C57A0` consumes it without testing this return as an admission gate. [FBFA0 byte reads/branches at FBFC4–FBFF2 and returns FC19A–FC1D3](../analysis/multiplayer/integration/inventory-source/pickup-item-point/instructions/000fbfa0.asm), [consumer](../analysis/multiplayer/integration/inventory-source/pickup-visibility/instructions/000c57a0.asm).

The three projections are repeated calls using one observed row12 SMG node/contact state after the original conditional item postpass; they are not additional settling states. The replay preserves complete original body/header bytes and their full datums, definition and originating row identity. Every current item is header type 2 and parent NONE. `BACC0` reads parent `+14`; its executed unparented branch copies root **`+64/+68/+6C`** exactly. It does not use bound center `+30` or apply scale `+A0` to that root. The listed parented branch uses the retained parent datum/node and parent current matrix bank, but is unexecuted here. [BACC0 branch](../analysis/multiplayer/integration/inventory-source/pickup-item-point/instructions/000bacc0.asm), [separate attachment/parent evidence](MP_WEAPON_ATTACHMENT_RESEARCH.md).

## Exact current fields and resident inputs

| Current input | Owning read and meaning |
|---|---|
| Item `+12C` byte | Bit5 decides root versus ground marker; no host grounding flag may substitute. |
| Item `+14` full datum | `BACC0` parent test; `B9B90` marker-object resolution. All executed values are NONE. |
| Item `+4` flags dword | `B9B90` tests bit 0 of its low byte; the executed value is clear. `B9C20` reads the dword and extracts bit 10 as mirror. |
| Item `+0` definition | Definition resident tag → definition `+38` model → model `+4` render model. |
| Item signed i16 `+114/+116` | Current matrix-bank byte length and body-relative byte offset. Here length `D0`, offset `264`: four matrices at stride `34`. |
| Item signed i16 `+11A` | Region-state byte-bank offset. Here `334`, with ten current bytes retained in the complete snapshot. Selected marker region FF bypasses this bank's permutation read. |
| Item i16 `+132/+134` | Contact instance and surface. Instance FFFF takes ordinary current-bank handling; surface is sign-extended to index the stride8 surface table. |
| Globals `4EB114`, `4E7910`, `4E7918` | Exact resident tag-bank/current collision-bank/current BSP-root bindings, imported using the original fixture's real cache allocation mapping. |
| Original constants | One `465030`, two `46507C`, threshold `46504C`, projection offset `46508C`; untouched XBE bytes, recorded as external operand reads. |

Every external read is classified and retained with original instruction, address, width and bytes. Cache/BSP reads have actual file offsets; object reads have actual body offsets. No unknown external operand is admitted. Contact BSP `+130` is retained provenance but is **not read to choose the ordinary plane bank**: source `FC005` reads global `4E7910`. Contact material and ownership fields are likewise not substitute plane inputs. The item type/owner-redirection branches inside `B9B90` are listed, but their preceding bit 0 gate is clear in these cases. [Read set](../analysis/multiplayer/integration/inventory-source/pickup-item-point/report.json), [object resolver](../analysis/multiplayer/integration/inventory-source/pickup-item-point/instructions/000b9b90.asm), [marker inputs](../analysis/multiplayer/integration/inventory-source/pickup-item-point/instructions/000b9c20.asm).

The pool/header/resident-address binding is explicit backing storage for these source instructions. Imported current nodes/contact fields are literal prior source outputs; this replay does not recover their live scheduling/production by copying them. The prior source pose reciprocal boundary and explicitly configured FPCW027F/MXCSR1F80 remain stated fixture limits. Initial/unused register values and output padding are raw provenance only. ## Marker selection and transform arithmetic

When bit 5 is set, original `FBFE3` clears CL and calls **`B9C20(item, 0C0000C1 ground_point, 1)`**, output in EBX. CL0 invokes `B9B90` rather than selecting an arbitrary direct object. Its executed unparented/bit 0-clear branch retains the same item datum. `B9C20` resolves the actual definition/model/render links, current node bank, region-state pointer and mirror bit, then `1DC8F0` scans marker groups in stored order for the first matching string ID. [Actual resolver/query order](../analysis/multiplayer/integration/inventory-source/pickup-item-point/instructions/000b9c20.asm), [group lookup](../analysis/multiplayer/integration/inventory-source/pickup-item-point/instructions/001dc8f0.asm).

Actual SMG links are `E57B0406 → E57C0407 → E57D0408`; its ground-point group is **1**, one entry at node **0**. BR links are `E192001D → E193001E → E194001F`; its authored ground-point group is **0**, also node 0. BR metadata is exported from actual cache records; no BR contact-marker execution is claimed. Render-model group count/pointer is `+58/+5C`, stride `0C`; group ID/count/pointer is `+0/+4/+8`. Entries have stride `24`: region/permutation/node bytes `+0/+1/+2`, translation `+4`, quaternion `+10`, scalar `+20`. [Literal metadata](../analysis/multiplayer/integration/inventory-source/pickup-item-point/metadata.json), [prior authored marker inventory](MP_WEAPON_ATTACHMENT_RESEARCH.md).

`1DC940` receives mode in ECX, group in EAX and six stack arguments: region bytes, optional node map, current matrices, mirror, output, maximum. Actual calls use region FF, no node map, mirror 0 and maximum 1. A positive record defines signed i16 node at `+0`, local matrix at `+4`, world matrix at `+38` and scalar at `+6C`, stride `70`; **`+2` padding is undefined**. Each matrix has scale `+0`, basis vectors `+4/+10/+1C`, translation `+28`. [Marker evaluator](../analysis/multiplayer/integration/inventory-source/pickup-item-point/instructions/001dc940.asm).

Original `143580` forms separately rounded `((x²+y²)+z²)+w²`; its exercised non-small branch computes `2/norm²` with DIVSS, then the quaternion basis products/additions/subtractions in source order. `1DC940` sets local scale 1 and copies exact authored translation before original `1441D0` composition. This path uses no Xbox reciprocal instruction. `1441D0` computes world scale `node.scale*local.scale`; basis components group **`x*i + (y*j + z*k)`**; translation groups **`node.scale*((tx*i + ty*j) + tz*k) + node.translation`**, with each scalar/packed operation rounded separately. Generic reassociation, fused multiply-add or a differently normalized quaternion would change the captured words. The independently emitted quaternion and matrix fixtures take literal original operands and outputs. [Quaternion instructions](../analysis/multiplayer/integration/inventory-source/pickup-item-point/instructions/00143580.asm), [composition instructions](../analysis/multiplayer/integration/inventory-source/pickup-item-point/instructions/001441d0.asm), [captured original local/current/world matrices](../analysis/multiplayer/integration/inventory-source/pickup-item-point/report.json).

Missing-marker root fallback, mirror, region filtering and node remapping are source-defined branches but unexecuted by the three ground-point cases. An unavailable model/current-node producer is not evidence for a successful marker query or permission to import the zero-marker attachment fallback. [Existing failure/zero-marker distinction](MP_PICKUP_NATIVE_CONTRACT.md#exact-capsule-and-item-point-producers).

## Ordinary ground plane and emitted point

For contact instance FFFF, `FC005–FC01D` takes current collision bank **`800AB3C8`**, surface `0B9F`, stride8, reads that surface's signed plane token **`04FF`**, then calls `14BA50`. Plane descriptor count/pointer is collision `+8/+0C`, stride10. The helper masks token with 7FFF and copies the four plane words; its high-bit branch performs separate `0−component` operations, but these three tokens have that bit clear. The returned plane words are **`3433B653 B4D96C60 3F800000 C1433339`**. [Ordinary selection at FC005–FC034](../analysis/multiplayer/integration/inventory-source/pickup-item-point/instructions/000fbfa0.asm), [plane helper](../analysis/multiplayer/integration/inventory-source/pickup-item-point/instructions/0014ba50.asm), [actual surface/plane operand reads](../analysis/multiplayer/integration/inventory-source/pickup-item-point/report.json).

The actual marker world point is **`BFC0B87E 412A5C91 C1433334`**. Source signed distance is computed in this exact order: `((Pz*nz + Py*ny) + nx*Px) − d`; shift is `46508C − distance`, and each result component is `Pcomponent + ncomponent*shift`. Every multiply/add/subtract is a separate SSE operation. The emitted point is **`BFC0B87E 412A5C91 C1426667`**, while the current root is different. Owning observations retain the actual plane/marker buffers at `FC022/FC12E`, actual signed distance at `FC167`, actual shift at `FC173`, and completed xyz registers at `FC19C`. Only these defined values are exported as stage expectations. [Source arithmetic/stores FC12E–FC1A5](../analysis/multiplayer/integration/inventory-source/pickup-item-point/instructions/000fbfa0.asm), [literal stage fixtures](../analysis/multiplayer/integration/inventory-source/pickup-item-point/fixtures.tsv).

The source instanced branch is listed: current BSP `+144` instance table stride58; instance `+34` selects strideC8 definition table at BSP `+13C`, collision subrecord `+70`; it transforms the returned local plane by that instance matrix. It remains unexecuted and is not represented by ordinary-bank fixtures. Negative plane tokens are also unexecuted here. [Instanced FC03F–FC12A branch](../analysis/multiplayer/integration/inventory-source/pickup-item-point/instructions/000fbfa0.asm).

## Fixture schema and smallest live gate

The ignored [fixtures.tsv](../analysis/multiplayer/integration/inventory-source/pickup-item-point/fixtures.tsv) and [schema](../analysis/multiplayer/integration/inventory-source/pickup-item-point/schema.json) contain literal source inputs/results:

| Tag | Contract |
|---|---|
| P | 208 item identity/current flags/parent/contact/root/output/full-return records. `consumer_global_id` retains the prior 207 consumer IDs; the extra direct FBFA0 observation uses −1.|
| N | All four actual current node matrices per item; no generated pose.|
| Q/C/M | Actual quaternion→basis, current/local→world composition, and defined marker output records.|
| L/S | Actual selected plane and defined distance/shift/point-owning stages.|
| R | Every imported external operand read, retaining original byte width/order and cache/body provenance.|

For the verified ordinary live item-point scope, the caller needs a stable full item identity, source-owned current root/parent/flag state, and—when bit 5 is set—the actual current node/region bank plus actual source contact instance/surface and active collision bank. This new gate can compare/port **FBFA0 on supplied original state**; it does not authorize setting those fields from a host solver. `F9B10→F9EA0` owns normal physical/contact updates, and the first contact observations remain conditional on unavailable `246A50` Havok shape/world production. Source graph/resource/node evaluation owns current matrices; source `BDF10/BEDE0` bounds and registry updates own the live enumeration center/location. [World producer/order](MP_ITEM_WORLD_RESEARCH.md), [actual spatial producer and enumeration](MP_PICKUP_SPATIAL_RESEARCH.md), [native producer contract](MP_PICKUP_NATIVE_CONTRACT.md).

The remaining live composition is allocated item/unit identity → source pose/bounds/contact/registry state → ordinary enumeration and capsule/item point → proven terrain/posed visibility consumer → actual equipped animation capability/input hold/action → `CE510/CFED0` transfer and `FB560` attachment. Allocation, bounded visibility, held233-ms admission, retained datum/slots/row, and attach/detach each have separate source evidence; joining them requires their real producer states in source stage order. Current-node availability, Havok settling/general object phase and full world registration/scheduling remain live boundaries. Successful carry must retain the allocated target datum/ammo/heat/row reference, then apply the proven ownership, slot, unregister and attachment stores. A definition-only replacement cannot satisfy that contract. [Input/action/carry](MP_PICKUP_EQUIPPED_RESEARCH.md), [parent lifecycle/markers](MP_WEAPON_ATTACHMENT_RESEARCH.md), [source admission/control](MP_PICKUP_CONTROLS_RESEARCH.md).
