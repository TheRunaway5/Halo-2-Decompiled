# Checked translated execution: selective LTO/PGO eligibility

2026-10-22. Read-only source, Ninja/CMake metadata and `nm` audit. No compiler, linker, build, profiler or game was run; no production/CMake files were changed. The4K120 single-player and4K60 four-player goal remains unmet.

**A three-translation-unit external-object LTO trial is justified as an experiment, with no established performance gain.** It can reuse the current owned build's ordinary objects/archives without enabling IPO across the project. LTO is primarily an opportunity to expose translated-caller→checked-memory calls and live-owner→generated-entry calls. It does not newly expose the memory owner's internal lookup/validation/write-policy implementation: those are already one translation unit.

## Closure and semantic obstacles

`SourceRuntimeMemory` is final, but generated runners accept the open `SourcePhysicsContactMemory&` interface. Its scalar read/write are virtual; its default vector operation performs four ordered scalar calls, including32-bit wrap: [physics_contact_record.hpp:15](/home/eric/Developer/Halo-2-Decompiled/include/halo2/physics_contact_record.hpp:15). Real alternative adapters include [lens QueryMemory](/home/eric/Developer/Halo-2-Decompiled/src/runtime/source_execution_lens.cpp:33), [NativeVistaWidgetMemory](/home/eric/Developer/Halo-2-Decompiled/include/halo2/native_vista_widget_memory.hpp:11), [SourceContrailSnapshotMemory](/home/eric/Developer/Halo-2-Decompiled/include/halo2/source_contrail_snapshot.hpp:23), and the [PIO action interface](/home/eric/Developer/Halo-2-Decompiled/include/halo2/source_sound_pio_storage_tu15.hpp:7). Tests also supply custom faulting adapters. The live required-owner checks `&m==&bank` at [physics_live_world_tu15.cpp:1177](/home/eric/Developer/Halo-2-Decompiled/src/physics/physics_live_world_tu15.cpp:1177); whether LTO propagates that identity into useful clones is unmeasured.

Ordinary IPO that proves a concrete target, or keeps a guarded virtual fallback, is eligible. An unconditional assumption that every base reference is a `SourceRuntimeMemory` is unsupported. No hot-path memory-ABI plugin loader was found in the inspected runtime/world/app files; that is not a whole-application closed-class proof. The build also creates shared kernel libraries and bundles external SDKs. Do not globally hide this public class hierarchy, force whole-program vtables, suppress RTTI, or assume foreign/native linkage units cannot contain users. Clang documents public/hidden LTO visibility, including the mixed native/bitcode class-definition constraint, in [LTO Visibility](https://clang.llvm.org/docs/LTOVisibility.html). Its guarded devirtualization and hidden-class whole-program options are distinct in the [Clang manual](https://clang.llvm.org/docs/UsersManual.html#cmdoption-fwhole-program-vtables).

Callbacks remain substantive barriers. The checked scalar helper calls `m.read` at [physics_step_internal.hpp:12](/home/eric/Developer/Halo-2-Decompiled/src/physics/runtime/physics_step_internal.hpp:12); writes retain guards/observers, alias staging and exception prefixes. Required-owner calls copy/save/load ABI on both success and exception at [physics_contact_runtime_internal.hpp:201](/home/eric/Developer/Halo-2-Decompiled/src/physics/runtime/physics_contact_runtime_internal.hpp:201). The public shadow runner publishes intermediate state when it catches a fault at [source_shadow_frame_tu15_generated.cpp:19838](/home/eric/Developer/Halo-2-Decompiled/src/rendering/shadows/source_shadow_frame_tu15_generated.cpp:19838). LTO must retain those effects and cannot reuse source loads across legitimate memory/owner mutations merely because training rarely changes them.

The fast instruction cursor is already explicitly admitted by callback type/executor/service sites and checks changing trace flags each instruction. The generic fallback is `noipa` on GCC and `noinline` on Clang at [physics_contact_runtime_internal.hpp:115](/home/eric/Developer/Halo-2-Decompiled/src/physics/runtime/physics_contact_runtime_internal.hpp:115). GCC's [attribute contract](https://gcc.gnu.org/onlinedocs/gcc/Common-Attributes.html#index-noipa-function-attribute) intentionally makes that body opaque to caller IPA; do not remove it to make an LTO trial look faster. Clang's existing annotation is weaker; a Clang trial needs its own evidence.

Strict FP is also part of eligibility, not a tuning variable. Preserve the source control-word/MXCSR setup, x87 exception/status publication, volatile source spills, inline-assembly clobbers, SSE ordering and all original error boundaries. The world target uses `-fno-fast-math -ffp-contract=off -frounding-math`; copy those options into every hot LTO input and the LTO link, while preserving the original ABI/target/exception options. No `pure`, `const`, `noexcept`, `restrict`, fast-math or skipped-check annotations are proposed.

## Exact external-object overlay route

The route suggested by the parent is viable in principle: compile the **complete original three TUs** into private object paths, link them as external objects ahead of the unchanged archives, and require the old archive members to remain unextracted. It is not enough to compile only the hot functions.

`nm -g --defined-only` on the frozen objects found67 strong definitions in memory,144 in live-world, and2 in shadow. The memory member supplies all backing/memory methods, both `source_runtime_validate_write` overloads, every write/topology register/unregister/validation API and all PolicyHold/PolicyChange constructors/destructors. Shadow supplies its runner and `owns_entry`. Ninja places memory/live-world only in `libhalo2_systems.a`, and shadow only in `libhalo2_physics_world_runtime.a`. Checked strong memory/policy/runner entries have no second definition across the systems/world/cache/renderer archives.

The registry singleton, its guard variable and thread-local `Dispatch` are local to the memory member. Supplying its complete public symbol set from one replacement TU should leave one registry and TLS owner. Compiling the `.inc` separately, leaving an old public setter unresolved, forcing old members with `--whole-archive`, or hiding duplicate-symbol diagnostics could instead create a duplicate/mixed owner or a link error. Header inline/COMDAT helpers may still come from other ordinary members; keep identical definitions, layouts, macros, exceptions and RTTI. An actual link map and symbol comparison remain necessary before declaring this replacement closed. [GNU ld archive extraction rules](https://sourceware.org/binutils/docs/ld/Options.html#index-_002dl-namespec) support the route; they do not replace that check.

A minimal official CMake-worker trial can therefore:

1. Work only inside the existing owned frozen context after other timing runs finish. Record the baseline binary hash, exact three input paths/hashes, original compiler commands, normal object/archive hashes and initial Ninja commands. Use the build-produced specialized shadow source, not an unspecialized canonical replacement.
2. Add custom compile commands with new object and dependency paths under an owned `lto-trial/` directory. Copy every original compiler/include/system-include/definition/dialect/thread/ABI/FP option; redirect `-o`, `-MF`, `-MT` and other output paths. Add GCC LTO to those commands only. Do not set global IPO or compile options on either large library. The policy `.inc` is already included by the memory source and must not be an additional TU.
3. Add these generated files to `halo2_native` as external objects, leaving all ordinary libraries/objects intact. CMake's [EXTERNAL_OBJECT](https://cmake.org/cmake/help/latest/prop_sf/EXTERNAL_OBJECT.html) property links rather than recompiles them. Add strict LTO **link** options only; inspect generated Ninja metadata to confirm the three overlays precede archives and normal compile/archive commands are unchanged.
4. Preserve the ordinary executable by giving this trial a distinct output path/target. Changing only objects still relinks and overwrites the normal executable unless its output is redirected. [RUNTIME_OUTPUT_DIRECTORY](https://cmake.org/cmake/help/latest/prop_tgt/RUNTIME_OUTPUT_DIRECTORY.html) can isolate the candidate while retaining ordinary object paths. Account for [post-build tag staging](/home/eric/Developer/Halo-2-Decompiled/cmake/RuntimeTagData.cmake:9), SDK staging and runtime working-directory requirements. An official trial target/worker is preferable to modifying archives and later trying to restore them manually.
5. First require successful linking, identical required public symbol coverage, no unexpected ODR/type/ABI diagnostics, and a map showing none of the three old members was extracted. Check the sole memory/policy-state owner. Then inspect whether the hot checked scalar/vector virtual calls were actually specialized/inlined and whether callback/fault boundaries remain. No changed hot call path is a falsifiable no-gain result; stop before expanding the closure.
6. If code generation changes usefully, run the existing semantic cohorts against the LTO-built closure, then alternate hash-pinned ordinary/candidate runtimes with identical source inputs and view counts. Compare exact outputs/state, ordered faults/callbacks and FP results as well as unsampled CPU/FPS. Keep all temporary objects, LTO cache/map and executable under the same owner, retain only bounded reports, verify ordinary hashes unchanged and clean the trial on completion.

GCC supports mixed native/bytecode links, requires LTO information from compile time, and versions that bytecode strictly. Native-only existing objects cannot gain cross-TU analysis by adding `-flto` solely at the final link. Its documented option merging also makes repeating strict FP link settings prudent. These are described in [GCC Optimize Options](https://gcc.gnu.org/onlinedocs/gcc/Optimize-Options.html#index-flto). A bounded trial needs only these selected recompilations plus LTO code generation/relink, not a full source rebuild; compile time/memory cost of the large generated shadow TU and live-world TU is still unmeasured. Cap jobs rather than using unrestricted auto parallelism. Fat LTO objects can optionally provide both native and LTO link controls from one compile; do not overwrite the normal objects with them.

Clang [ThinLTO](https://clang.llvm.org/docs/ThinLTO.html) offers incremental caches, but the frozen build is GCC. A compiler switch would be a separate experiment with its own baseline, not a way to reuse GCC IR or attribute a change solely to LTO.

## PGO and validation limits

PGO is a later hypothesis. Existing sampled stack JSON is not GCC/Clang compiler profile input. GCC instrumentation needs selected-source compile/link instrumentation, representative training, then recompilation with matching feedback; see [Instrumentation Options](https://gcc.gnu.org/onlinedocs/gcc/Instrumentation-Options.html#index-fprofile-generate). Clang uses its own raw/indexed profiles and `llvm-profdata`; its manual explicitly distinguishes its profile format from GCC's. This costs at least a generation build/link, training run and use build/link for the selected TUs. Missing/mismatched feedback should be reported, not silently papered over. Train more than an idle camera; retain generic behavior for less frequent adapters, traces, faults and observer-policy changes. Instrumented training FPS cannot certify an ordinary optimized runtime.

Existing useful semantic cohorts include [source_runtime_write_dispatch_tests.cpp:17](/home/eric/Developer/Halo-2-Decompiled/tests/source_runtime_write_dispatch_tests.cpp:17) for callback order/throws, policy replacement, recursion, oversized banks and concurrent retirement; [source_runtime_transfer_tests.cpp:41](/home/eric/Developer/Halo-2-Decompiled/tests/source_runtime_transfer_tests.cpp:41) for staging/aliases/full rejection; [source_runtime_memory_tests.cpp](/home/eric/Developer/Halo-2-Decompiled/tests/source_runtime_memory_tests.cpp) for ownership/topology; and [test_native_instruction_cursor.py:109](/home/eric/Developer/Halo-2-Decompiled/tests/test_native_instruction_cursor.py:109) for trace/service/exception/replaced-callback/foreign-executor behavior. Their current separate ordinary builds do not automatically exercise the proposed LTO closure. In particular the cursor helper hardcodes an ordinary `-O2` compile at line160. Run/adapt the trial's validation so it actually links the replacement objects and tests the relevant hot public paths. No existing test was executed during this audit.
