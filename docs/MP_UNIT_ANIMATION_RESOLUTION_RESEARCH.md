## Native contract

[unit_animation_resolution.hpp](../include/halo2/unit_animation_resolution.hpp)
and [unit_animation_resolution.cpp](../src/unit_animation_resolution.cpp) expose
the complete direct bodies. The manager input is at least `90` bytes. Requested
and resolved identifier outputs are16 bytes each; packed output is4 bytes.
Outputs retain their exact prior bytes and source store order. The manager is
read-only. Unsupported host aliasing, truncated backing and cyclic resource
links fail explicitly.

`SourceAnimationGraphMemory` resolves original graph identities and original VA
tokens into bounded literal backing. `UnitAnimationMetadataStore::graph_memory()`
supplies the actual58 Cache-owned packets and retains their lifetime. Missing or
escaped graph memory is unavailable; a missing inherited graph is not silently
skipped. Mutable descriptor state is a separate owner, even when the authored
descriptor bytes initially occur inside a literal graph packet.

`SourceAnimationResourceServices::state()` must return the actual two runtime
gate bytes. Its `request()` must deliver the complete resource demand owner when
the actual descriptor byte `+10` admits it. There is no enabled, resident or idle
default. `SourceAnimationDemandServices` requires bounded mutable storage and
explicit image/runtime bindings. Its queue allocator supplies actual `16D2C0`
EAX full datum and EDX pool address; its scheduler supplies complete `125120`
ownership. Exhaustion requires the original clock provider only on that branch.

The differential supplies observed original allocator/scheduler calls, checks
the complete caller state before each service and applies the actual full
before/after buffers. These are explicit lower-service fixtures, not a native
port of cache allocation/retirement/IO. The raw queued lookup itself is native
and compared against all51 original `124DD0` returns.

## Preserved selection and demand rules

* Packed high and low halves are signed16-bit animation/inheritance indices.
  High `FFFF` is invalid; low `FFFF` denotes the current graph. The original
  signed index/address arithmetic is retained and host spans are checked.
* `1CFCE0` normalization preserves every identifier substitution and ordered
  output store, including the unconditional weapon-class map store at `1CFDA7`.
* Class `NONE` in `1DEB60` writes only packed `NONE`; incoming optional output
  values remain intact. Non-null optional output pointers become explicit spans.
* Flag2 tries the actual idle action identifier. Flag4 can admit a weapon bank
  while packed animation remains `NONE`. Defined `AL=true` alone does not prove
  a valid clip or resource residency.
* `1E13C0` demands the originally selected animation first. Its separate base
  link selects the start of the subsequent variant-chain walk; it does not
  replace the first selected-animation demand. Repeated selected demands are
  retained when the actual link chain encounters that animation again.
* The five weapon resource banks are `(m,c,w)`, `(m,c,D)`, `(m,D,w)`, `(m,D,D)`
  and `(D,D,D)`, in that order, even when tuples are equal. Each sweep visits the
  root then every inherited graph. `1DEB60` sweeps requested and resolved banks;
  admitted `1CFDE0` sweeps resolved banks again. Repeated requests are observable.
* `124E40` CLnonzero selects priority1; CLzero selects priority2. Its queued
  lookup visits the actual occupied bitmap in ascending index order and returns
  the stored salt plus index. Existing queued requests return without a new
  allocation. New allocation writes priority at `slot+4` (`124E8B`) then
  descriptor at `slot+8` (`124E8F`) before scheduling.
* Allocation failure reads the clock, then the warning deadline. Only unsigned
  `now>deadline` calls the clock again and stores wrapping `later+30000` at
  `124EB0`. The resident branch compares signed wrapped age against the actual
  priority threshold and writes `counter-threshold` at `124EE9` when required.
  These complete branches are ported from instructions; resident, exhaustion,
  warning-clock and priority2 branches have no owning dynamic case in this suite.
