# Original entry update decoding

The native generic entry decoder now matches **13,350 whole original calls** across retail, TU1.1 and Xbox TU1.5. These calls execute the original concrete allocator and King codec, with no replaced instructions or supplied allocation returns. This adds packet preparation beneath the shared engine/entity interface; native session delivery and normal King admission remain unfinished. [Original execution](../analysis/multiplayer/game-variants/engine-entry-decode-20261012/complete/report.json), [native owner](../src/source_engine_entry_decode.cpp), [declarations](../include/halo2/source_engine_entry_decode.hpp).

The original update decoder is retail `8AAC0`, TU1.1 `8B690`, TU1.5 `8E8F0`, reached through slot6 of each actual entity-owner vtable. The original complete listings establish the changed32/36-byte row layout, signed sizes, allocation/cleanup order and the separately ordered application owner. [Complete owner research](MP_KING_REPLICATION_ORCHESTRATION_SOURCE_RESEARCH.md), [retail decoder](../analysis/multiplayer/game-variants/king-replication-orchestration-source-20261012/complete/retail-entry_update_decode-0008aac0.asm), [live application binding](MP_ENGINE_ENTRY_NATIVE_BINDING.md).

The original oracle invokes the reusable real allocator setup over declared arena/context backing. Its bounded boot suffix constructs the concrete allocator and publishes the wrapper global; complete physical memory boot remains outside this boundary. Every decoded bank pointer comes from the original allocator instructions. The decoder itself increments/decrements the wrapper counter. [Allocator evidence and exact ABI](MP_REPLICATION_ALLOCATOR_SOURCE_RESEARCH.md), [whole decoder oracle](../tools/oracle_engine_entry_decode.py).

The native API takes an allocator provider which supplies actual host storage and source-address metadata. It ports the decoder's ownership/order policy, not the Xbox arena implementation. Differential tests pass the original allocator's observed outputs at that explicit provider boundary, then compare the native bank, typed output, complete stream, counters, status and callback prestates. The original executable oracle does not consume those outputs as inputs. [Native tests](../tests/engine_entry_decode_tests.cpp), [fixture](../tests/fixtures/engine_entry_decode_original.json).

The reproduced contract is:

- Reject `NONE` or a mismatched full entity ID before definition lookup, allocation or stream changes. The caller indexes its row by `handle & 3FF`.
- Allocate the signed entry state size. On failure call real compaction with0 and retry once; a second failure returns3. The negative-size controls execute both allocation attempts and the real compactor.
- Increment the live allocation counter on success. Mode4 zeroes the private bank and requires definition19 initialization; other modes copy the prior live bank. Matching uses actual engine39/definition0 identifiers, independently queried in every executable.
- Initialize a local mask to0 and require definition15's reader result. On failure inspect and release the private bank before decrementing the counter. Neither the caller's mask nor output count changes.
- On success store the mask and append one literal8-byte block with signed16 size, type13 and the real private-bank address; increment the output count and return0. The capacity argument is unused in this owner. Explicit host backing remains necessary.

All4,450 inputs per image include the previous codec's2,066 writer outputs and1,024 random streams, all128 low masks under mode4 for all10 registered selectors,64 full-ID/NONE controls and16 negative allocation-size controls. All three images produce identical results after normalizing only the documented update-row extension. **6,291 decodes succeed,9,654 reader calls execute,3,840 initialization gates execute,6,819 rejections release banks, and48 compactions execute.** The live bank, source entry, packet bytes and adjacent guards stay unchanged. Callback prestates preserve zero/copy-before-reader and inspect-before-release ordering. [Execution counts and instruction hashes](../analysis/multiplayer/game-variants/engine-entry-decode-20261012/complete/report.json), [full outputs](../tests/fixtures/engine_entry_decode_original.json).

**4,275 successful decodes have an overflowed stream.** This is observed original behavior: the entry owner does not query overflow/error. The aggregate may apply decoded children before the enclosing network reader performs its later stream check, with no rollback. A successful decode is therefore not a claim of packet acceptance. [Original ordering research](MP_KING_REPLICATION_ORCHESTRATION_SOURCE_RESEARCH.md), [codec boundary](MP_KING_WIRE_NATIVE_BINDING.md).

The verifier freezes the prior compatible source snapshot, overlays this module and its exact CMake additions, independently reruns original execution, and builds the seven focused root targets. It also runs the complete decoder corpus under ASan/UBSan with leak checks.
