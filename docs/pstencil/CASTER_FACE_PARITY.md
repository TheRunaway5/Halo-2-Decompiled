# 2003 caster faces and the TU1.5 adaptation

The demonstrated 2003 casting categories are **type 1, opaque shadow-only**, and **type 2, visible opaque shadow-casting**. Type 3 is opaque without shadow casting; type 4 is transparent. Preserve the actual part type through the current pose and collect casting geometry independently of color-pass admission. A shader's retail layer-10 availability does not establish either the part's casting category or the 2003 ISQ face set.

This is a source audit, not a framebuffer comparison. The 2003 game image is SHA-256 `5a9edb4c874a782594c86020db49b0086f44ae38f53ff2276b3192a2c2383d18`; the current reference is the original Xbox **TU1.5** image, SHA-256 `21b207e7efdacaf6124a0822837f8be570766a42505057f7fd2d2ba8f409c4fd`. [The verification manifest](../../analysis/pstencil/caster-parity/build.json) identifies these files, the 2003 tool image and matching symbol maps, and verifies every exported function's bytes against its primary image. [The verifier](../../analysis/pstencil/caster-parity/verify_exports.py) executes no original code.

## Part categories: proved facts and the crosswalk limit

The named 2003 XBE predicate `geometry_part_type_is_shadow_casting` at **001CB000** returns true for 1/2 and false for 3/4. The adjacent named predicates establish opacity for 1/2/3, shadow-only for 1, and transparency for 4. The compiler-side primary evidence is independent: `render_geometry::get_part_type_from_connected_material_flags`, **0044DDD0** in the matching 2003 `tool.exe`, returns 1 for casting without visibility, 2 for casting with visibility, 3 for visible noncasting geometry, and 4 for transparent geometry. Its embedded assertions name the render, visible, and transparent flags; this is stronger than borrowing a later enum declaration. [XBE casting predicate](../../analysis/pstencil/2003-shadow-lighting/functions/001cb000.c), [opacity predicate](../../analysis/pstencil/2003-shadow-lighting/functions/001caf90.c), [shadow-only predicate](../../analysis/pstencil/2003-shadow-lighting/functions/001cb070.c), [transparent predicate](../../analysis/pstencil/2003-shadow-lighting/functions/001cb0d0.c), [compiler classification](../../analysis/pstencil/caster-parity/2003-tool/functions/0044ddd0.c), [assertion strings and image provenance](../../analysis/pstencil/caster-parity/build.json).

| Literal type | Proved 2003 meaning | Proved TU1.5 handling | pStencil adaptation |

| 0 | Outside the demonstrated 1–4 predicates | Excluded by part command producer | Exclude |
| 1 | Opaque shadow-only, casts | Retained by producer; uses opaque vertex selector | Include as a 2003 caster; collect independently of visible geometry |

**The retail semantic crosswalk for types 1/2/3 is supported by structural continuity, not by a recovered TU1.5 casting predicate.** Actual TU1.5 **00041030** consumes 72-byte parts, excludes 0/5, and queues authored shader layers. **00040E20 → 0003B9C0** does not apply a demonstrated `type 1/2 → layer 10` mask. **0004CBE0** and **0004D0A0** use 4/5 for the transparent vertex selector and otherwise do not reject type 3 at layer 10. No exact retail type normalizer or named type-1/2 casting test was recovered in this audit. Therefore apply the known **2003** predicate as an adaptation to retained retail raw types, and do not advertise that host gate as exact TU1.5 projected-shadow pass behavior. The existing source often retains older-disc labels `41040/40E30/3B9D0`; the cited TU1.5 entry points are `41030/40E20/3B9C0`. [Producer](../../analysis/pstencil/caster-parity/tu15/functions/00041030.c), [enqueue caller](../../analysis/pstencil/caster-parity/tu15/disassembly/00040e20.asm), [enqueue](../../analysis/pstencil/caster-parity/tu15/functions/0003b9c0.c), [descriptor](../../analysis/pstencil/caster-parity/tu15/functions/0004cbe0.c), [draw](../../analysis/pstencil/caster-parity/tu15/functions/0004d0a0.c).

## What the 2003 ISQ actually consumes

`rasterizer_stencilshadow_shadows_model_section_draw` **0017B4D0** does not iterate current material layers and admit a triangle by shader bit 10. It consumes the section's compiled rigid plane groups, strip/cap triangles, internal edges, boundary edges, and cross-section shared edges. `rasterizer_stencilshadow_isq_object_do_skinning_work` **00179190** skins the relevant rigid point groups and constructs skinned triangle planes; **0017AF20** classifies those planes against the current light. The model routine uses those face bits when assembling caps and silhouette sides, and checks the authored cross-section compatibility predicate for shared edges. The cluster path **0017C5A0** separately submits caps, internal edges, boundary edges, and shared edges. [Model draw](../../analysis/pstencil/caster-parity/2003/functions/0017b4d0.c), [skinning](../../analysis/pstencil/caster-parity/2003/functions/00179190.c), [plane classification](../../analysis/pstencil/caster-parity/2003/functions/0017af20.c), [cluster draw](../../analysis/pstencil/caster-parity/2003/functions/0017c5a0.c), [strip winding/degenerate handling](../../analysis/pstencil/caster-parity/2003/functions/00179690.c).

Consequences:

- Recover shadow-only authored faces even when their color material or diffuse implementation is unavailable. Shader-pass residency and casting topology are separate concerns.
- A closed prism per light-facing triangle is the current host approximation. Preserving type 1/2 fixes admission, but does not reproduce original compiled ISQ adjacency, cross-section seams, or cap construction.
- Do not replace the original “manifold” predicate with a host weld/watertight test. **00160620/001606B0** read an authored section-pair incompatibility bitvector at model `+5C`, using triangular pair index `(max−1)*max/2+min`, across the selected region permutations and six LOD slots. This is an authored compatibility test. The audit does not establish a corresponding TU1.5 field. [Pair check](../../analysis/pstencil/caster-parity/2003/functions/00160620.c), [model check and disassembly](../../analysis/pstencil/caster-parity/2003/functions/001606b0.c), [001606B0 instructions](../../analysis/pstencil/caster-parity/2003/disassembly/001606b0.asm).
- The generic layered model-part path **001CD8A0** additionally checks the layer's valid-part-type table, **004A90C0**. The recovered table has mask `4` for layers 6/13, selecting type 2. Do not mistake this generic color/shader path for a complete description of the dedicated ISQ shadow-only face bank. [Generic part path](../../analysis/pstencil/caster-parity/2003/functions/001cd8a0.c), [earlier primary table extraction](../../analysis/pstencil/2003-shadow-lighting/build.json).

### Object eligibility and opacity are separate from face type

The **fake lightmap-shadow** eligibility field is model `+D0`. **001C60D0** clears it, then sets it only for object short type 0 or 1 at object `+68` when `render_model_check_shadow_manifold` succeeds. **001C5EE0** requires both `+D0` and nonzero model opacity byte `+D` when the layer is 6. This is not evidence for restricting all dynamic point-light casters to those object classes. [Eligibility producer](../../analysis/pstencil/2003-shadow-lighting/functions/001c60d0.c), [layer-6 admission](../../analysis/pstencil/2003-shadow-lighting/functions/001c5ee0.c).

The dedicated ISQ model draw **0017B4D0**, instructions **0017B520–0017B547**, computes `min(model.shadow_alpha_byte, trunc(light_opacity_007439E0 × 255))`, using the original x87 conversion. Zero skips drawing; 255 disables fractional-opacity state `0x53`; intermediate values enable it and submit the byte scaled by the primary reciprocal constant. **001C6D40** writes the visible-model alpha at byte `+C` from rendered-model-info `+8`, and the **separate shadow alpha** at `+D` from rendered-model-info `+C`. A current TU1.5 visible draw-unit opacity byte is not automatically proof of an equivalent shadow-alpha producer. [ISQ instructions](../../analysis/pstencil/caster-parity/2003/disassembly/0017b4d0.asm), [alpha-byte producer](../../analysis/pstencil/caster-parity/2003/disassembly/001c6d40.asm).

Fractional opacity is **stipple**, not alpha blending. The named `rasterizer_submit_stipple` **000959A0** calls `rasterizer_get_stipple_pattern` **000A7E00**, then original `D3DDevice_SetStipple` **0033A800**. Render-state `0x53` maps through cell **003DA69C** to pushbuffer header `0004147C`, enabling method `147C`; the pattern upload writes 32 DWORDs at method `1480`. **000A7BF0** initializes 17 patterns at **0092D940**, stride `80`, from 16 signed-short XY offsets at **003F67A0** repeated over a 32×32 tile. **000A7E00** multiplies opacity by literal 16, stores float32, uses `FISTP` with the current x87 rounding mode, clamps 0–16, and returns the matching pattern. The primary row-major rank is `[0,12,3,10,8,4,15,6,2,11,1,13,14,7,9,5]`, matching the existing source-stipple shader's rank. Preserve the original source raster phase; pattern equality alone does not prove a new resolution/crop has the correct origin. [State setter](../../analysis/pstencil/caster-parity/2003/disassembly/000956e0.asm), [stipple setter](../../analysis/pstencil/caster-parity/2003/functions/000959a0.c), [initialization](../../analysis/pstencil/caster-parity/2003/functions/000a7bf0.c), [quantizer instructions](../../analysis/pstencil/caster-parity/2003/disassembly/000a7e00.asm), [GPU upload](../../analysis/pstencil/caster-parity/2003/functions/0033a800.c), [literal tables](../../analysis/pstencil/caster-parity/build.json), [existing shader](../../shaders/source_stipple.glsl), [explicit raster phase](../../include/halo2/source_stipple.hpp).

The separate [CPU stipple oracle](../../analysis/pstencil/caster-parity/verify_stipple.py) executed unchanged **000A7BF0/000A7E00** and their original callees for 330,944 instructions with supplied x87 control `023F`. It replaced no game service and patched no instruction. All 17 complete 32-DWORD patterns equal construction from the original XY table; all 256 opacity-byte inputs select the same level as integer `(byte*16+127)/255`. [Recorded output](../../analysis/pstencil/caster-parity/stipple-oracle.json). This verifies the pattern/quantizer boundary, not GPU stencil ordering or raster origin. The separate visible/shadow-alpha producer remains material: **000CAE50** makes shadow alpha the minimum of visible alpha and an additional shadow LOD fade. [LOD alpha routine](../../analysis/pstencil/caster-parity/2003/functions/000cae50.c).

The actual **point-light object** predicate is named `render_object_should_cast_shadow`, **000DE1A0**: object flags at `+4` bit 0 must be clear; `editor_should_render_object` **000127E0** returns true in this image; the first supplied owner is rejected when light flags contain `1800`, and the second owner when they contain `2000`. `render_objects_submit_lit_object` **000DE660** calls it and additionally requires the authored section-pair manifold predicate before constructing a casting model header. Rejected/nonmanifold models get header bit 0; `render_lod_shadow_casting_models_iterate` **000CC4B0** skips that bit. This path traverses attached children/siblings, and does not impose the layer-6-only biped/vehicle test. Separately, the shadow-only visibility visitor **000C85A0** rejects object flag bit 19 (`80000`) in its shadow traversal branch. The exact cross-version meaning/producer of that bit has not been recovered; do not copy its numeric mask into TU1.5. [Point predicate](../../analysis/pstencil/caster-parity/2003/functions/000de1a0.c), [editor stub](../../analysis/pstencil/caster-parity/2003/functions/000127e0.c), [submission and manifold gate](../../analysis/pstencil/caster-parity/2003/functions/000de660.c), [casting iterator](../../analysis/pstencil/caster-parity/2003/functions/000cc4b0.c), [visibility visitor](../../analysis/pstencil/caster-parity/2003/functions/000c85a0.c).

For comparison, the TU1.5 **projected-shadow** root eligibility routine **0003D7E0** reads object no-shadow flag `0x10000`, definition mode at `+18`, object type at `+AA`, model distance fade, death fade, camouflage, and parent fallback. Mode 2 admits any object class; mode 0 admits types 0/1; other modes reject unless an eligible parent supplies the root result. Header kinds 0/1 apply a final camouflage factor. These are useful existing source-owned inputs, but this audit does not equate retail projected-shadow eligibility with 2003 point-light ISQ eligibility. ### Topology and two-sided handling

TU1.5 **0004D0A0**, instructions **0004D5D2–0004D611**, chooses a strip only when draw-unit flag `0x200` is set and raw part flag `8` is clear; otherwise it submits a list. **0004DA90** uses the part's full index range or selected eight-byte subpart ranges. Preserve this rule and alternating strip winding; do not use a section-wide heuristic when the literal part flag is available. [Original instructions](../../analysis/pstencil/caster-parity/tu15/disassembly/0004d0a0.asm), [range submission](../../analysis/pstencil/caster-parity/tu15/functions/0004da90.c), [current faithful range helper](../../src/source_effect_light_opaque.cpp).

No recovered evidence identifies any raw part flag as a two-sided-material bit. The original draw applies shader/raster state; that must be recovered from the selected source pass before claiming two-sided parity. In particular, bit 3 is a topology override, not permission to duplicate reversed caster faces. The 2003 ISQ uses authored adjacency and plane orientation; arbitrary face duplication can alter signed stencil counts.

### Main-view and light-query masks have different owners

`SourceLiveModelBaseSelectionTu15::copy` explicitly requires the completed **main prefix** and only copies those units. `source_effect_light_geometry_frame` appends secondary BSP/model queries and sphere-culls **[main_prefix, draw_count)** with their own arena. Those queries can contain objects outside the main color view. [Main handoff](../../src/source_live_model_geometry_tu15.cpp), [secondary collection](../../src/source_effect_light_geometry_frame.cpp), [sphere/subpart cull](../../src/source_draw_unit_cull.cpp), [unit arena ownership](../../src/source_draw_unit.cpp).

The current integration then applies another restriction: `models.model_available` in `multiplayer_runtime.cpp` searches only `live_vehicle_base`, `live_prop_base`, and `live_unit_base`, which originate in main-view base draws. `source_bsp_effect_lights.cpp` clears secondary model admission bits when that callback rejects a model. Consequently, using only raw diffuse receivers as the caster inventory still misses off-camera objects and parts that lack a matching base draw. Source point-light receiver pass selection further depends on shader layer 12, so it cannot be the only caster collector. [Main-base availability callback](../../src/multiplayer_runtime.cpp), [secondary rejection and diffuse completion](../../src/source_bsp_effect_lights.cpp), [layer-12 opaque selection](../../src/source_effect_light_opaque.cpp).

Collect the casting bank from actual selected source sections/LOD and current palettes **before** color/base availability and diffuse-pass selection. Retain camera masks for receivers, and retain light-query masks with their own identities; do not reinterpret a main-camera subpart bitvector as the complete shadow-casting surface. A separate caster query must also account for occluders whose shadow reaches a visible receiver; “object is in a submitted base packet” is not that test. Exact 2003 spatial/ISQ query parity remains unimplemented.

## Layered renderer branch selection

**0074455C is `render_old_rasterizer`**, not an anonymous assumed shader toggle. Its primary HS external-global registration at **004C375C** contains name **004464D0**, boolean type 5, and address **0074455C**; the matching map names the same variable. It is in the virtual `.data` tail beyond file-backed bytes, establishing an initial zero value. Zero selects `render_layer_begin/draw/end`, including the previously documented lightmap-shadow layers 6/7; nonzero selects the old **E9520/E97A0** paths. Therefore the zero branch should be called the **layered renderer**, not the old renderer. [Registration and section bounds](../../analysis/pstencil/caster-parity/build.json), [verified direct reads](../../analysis/pstencil/caster-parity/2003/legacy-switch-references.json), [render_scene](../../analysis/pstencil/2003-shadow-lighting/functions/00051160.c).

`game/init.txt` contains only `game_start ec_interior_test`. A targeted search of supplied scenario source/scripts and loose scenario tags found no `render_old_rasterizer` assignment. This supports the image-default branch, but it is not a live trace of the May 2003 scenario: indirect HS/console mutation and the loaded cache's complete script execution remain unobserved. Exported old functions alone do not prove that old branch ran.

## Next implementation and verification boundaries

1. Preserve raw type/flags through every CPU pose path. Admit known types 1/2 for the 2003 adaptation, exclude 0/3/4/5, and keep unknown metadata explicit. Do not add shader bit 10 as an additional requirement for known casting parts.
2. Populate independent shadow-only and ordinary-caster banks from current source resources, selected LOD/permutation, current pose, and full geometry owner. Start before main-base/diffuse shader admission; preserve literal list/strip rules.
3. Keep fake lightmap-shadow eligibility/direction/opacity separate from each point light. Use the prior [shadow-lighting reference](SHADOW_LIGHTING_REFERENCE.md) for its once-per-baked-mask schedule and measured original `FF989898` darkening constant.
4. Verify admission independently: same material on types 1/2/3/4, shadow-only part absent from the color mesh, list override mixed with strips, posed attached equipment, off-camera caster, noncasting receiver, and zero/fractional opacity. These cases should check source-owned part/range selections as well as GPU results.
5. Continue tracing authored ISQ equivalents, opacity raster behavior, two-sided pass state, and object-query coverage before claiming complete 1:1 face/object parity. This audit supplies no guessed material multiplier, mesh weld tolerance, replacement topology, or inferred two-sided flag.
