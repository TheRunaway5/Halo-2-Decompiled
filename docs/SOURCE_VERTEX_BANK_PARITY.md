# Actual camera banks through the production vertex interpreter

`source_vertex_bank_tests` verifies `pack_vertex_program_bank` and the ordinary
production `vpConstant` function in `shaders/vertex_program.glsl`. It uses the
actual retained original20 receiver draws7988/7993/7998/8003, their authored
world-application class0 program and all ten independently exported vertex
inputs/results from `tests/fixtures/retail_shadow_vertex.tsv`. Expected source
outputs are the captured DebugVertex words; they are never generated by native
code. Source extraction and the xemu wrapper are documented separately in
`SOURCE_SHADOW_GPU_PARITY.md`.

## Binding contract

`VertexProgramBank.camera_inputs` admits an explicit original c0..11 bank only
when first_constant is0 and at least12 vectors are supplied. The real production
packer returns the2544-byte `PackedVertexProgramBank`: range first/count,
PRT-input flag, camera-input flag, then158 vectors. Its range validation rejects
incomplete camera banks, wrong camera start registers, oversized storage,
register overflow and noncamera banks below34. Empty ordinary banks remain
valid. These tests call the production packer directly.

Each captured receiver submission packs first0/count49 with literal camera
c0..11 and literal globals c34..48. Material c18..33 and fog c12..17 are supplied
through their existing material consumers. The otherwise unconsumed c12..33
storage in the extended bank is deliberately poisoned; those values must never
override the separate material/fog consumers. An enabled legacy per-material
camera path is also supplied deliberately different values, checking that the
explicit camera bank takes priority before legacy or synthesized constants.

The compute shader includes production `vertex_program.glsl` without
`H2_VERTEX_REFERENCE_CONSTANTS`. `H2_VERTEX_REFERENCE_INPUTS` only preserves
the actual captured inline attributes; `H2_EXTENDED_VERTEX_BANK` enables the
production extended-bank path. It reads all192 resolved registers back from
the actual production constant resolver, then executes the captured program.
It does not substitute a fixture-only constant function.

## Measured coverage

Four host target sizes are deliberately unrelated to the retained scene camera:
128×128,320×240,1920×1080 and3840×2160. The host projection, eye and forward
vectors also deliberately differ from the source camera. All ten captured
vertices are submitted at every size, for40 actual source cases. The four
ordinary-global controls and four PRT controls use the same changing host
targets with camera override disabled. Their PRT c68..149 values come from
the independently retained `retail_prt_rigid_gpu.tsv`; these controls verify
constant binding and flags, not a new PRT pose or shader-output proof.

On the measured NVIDIA RTX5080 run:

- All36,864 resolved constant words match exactly across48 submissions,
  including all1,920 captured camera words.
- All1,120 consumed CPU receiver words match the captured source exactly.
- All960 nonposition GPU receiver words match exactly. Four position words
  differ by1 ULP after the literal source pixel-to-clip wrapper; the test admits
  at most4 ULP only for position, matching the separately measured shadow
  vertex contract. Every other output remains an exact-word assertion.
- Nine malformed/incomplete-bank cases are rejected by the real packer.
  Ordinary empty, c34..48 and PRT c68..149 banks retain their separate flags
  and ranges.

The wrapper uses each literal fixture B record, including its original extent
and clipRange. It snaps XY to1/16 pixel, performs the captured pixel-to-clip
conversion and multiplies XYZ by the actual W. It does not use the deliberately
different current host target dimensions for the source comparison. This
measures the retained xemu GPU translation; it is not a physical NV2A precision
claim or a complete world/shadow framebuffer comparison.

## Reproduction and boundaries

CTest names are `source_vertex_bank_cpu` and `source_vertex_bank_gpu`. The GPU
test requires the installed Khronos validation layer and synchronization
validation; CTest supplies the required environment. Private normal and
ASAN/UBSAN CPU/GPU checks retain their exact binary, shader, fixture and source
hashes in `analysis/multiplayer-shading/source-vertex-bank-final-provenance.json`.
GPU sanitizer runs disable only leak detection for the documented external
Vulkan/driver allocation boundary; CPU leak detection stays enabled.
The measured run uses the repository's `.tools/validation` SDK, selected by
`VK_LAYER_PATH=.tools/validation/usr/share/vulkan/explicit_layer.d` and
`LD_LIBRARY_PATH=.tools/validation/usr/lib` (absolute paths in the retained
command environment). Loader logs confirm the Khronos layer is loaded; the
normal and sanitizer GPU logs contain no Vulkan or synchronization errors.

This test establishes the packer/production-GLSL bridge using actual source
banks and outputs. Selection of a live camera, source owner collector history,
shadow plan submission and actual target framebuffer remain their separate
producer/integration requirements. No renderer, runtime or scene code is
changed by this test.

## Production phase declarations

The second compute build, `source_vertex_bank_production.comp.spv`, also omits
`H2_VERTEX_REFERENCE_INPUTS`. It feeds decoded world position, UV and normal
through the same production `runVertexProgram` input loading used by world
geometry. It retains the ordinary production constant resolver and packer.
It defines `H2_SOURCE_VERTEX_DECLARATION` and uses the real
`pack_source_vertex_declaration` result: Apply's literal class0 `[0,4]` and
Generate's `[0,3]`. The phase marker retains the actual submitted `flags.z=10`
and `sourceCameraControl.w=1` for Apply, or `w=0` for Generate; the typed
declaration has priority over the legacy phase fallback.

Original `1C330` reads each vertex class's literal semantic list at class+8
with its class+4 count. World-class0 shadow generation declares position/UV
(`[0,3]`); application declares position/normal (`[0,4]`). Captured receiver
event7988 independently binds float3 position and NORMPACKED3 normal, and its
authored application program consumes v1 through DPH with c41 into oD0 RGB.
The original generation-world0 program consumes v1 through c172/c18/c20 into
oT0 and does not read the normal. These phase declarations differ from the
ordinary world declaration; using the ordinary UV v1 for Apply erases the
correct receiver lighting/opacity response.
The literal all21 authored declaration census is retained in
`analysis/multiplayer-shading/world-vertex-declarations.json`; unchanged
`1C330` execution over its literal lists and stream metadata verifies34
layouts/2,176 words independently of live draw admission.

The same ten actual receiver vertices are now tested at the four host extents
with two deliberately different UV streams, for80 production-input cases.
Their decoded normals are the literal captured v1 values. Expected outputs
remain the independently captured DebugVertex words. Every active output must
also remain unchanged between the two poison-UV submissions. The80 additional
wrong-declaration controls bind `[0,3]` while keeping the correct Apply marker
and must produce a different oD0. They prevent a reference-input bypass,
phase fallback or neutral fixture from concealing the original mapping error.

Normal and ASAN/UBSAN GPU runs measure:

- All1,920 nonposition words across the80 actual Apply cases are exact.
  Eight position words differ by1 ULP after the literal source wrapper;
  only position retains the existing4 ULP bound.
- Every poison-UV pair preserves all seven active Apply outputs, and all80
  wrong-declaration controls change oD0. Independent CPU declaration controls also
  demonstrate that replacing the source v1 normal with the poisoned UV changes
  oD0 for every case.
- All135,168 resolved constant words are exact across the176 additional
  production-input submissions, including both negative and controlled cases.

Generation has a separate, explicitly controlled test. The unchanged original
14-instruction world-class0 payload is frozen as
`tests/fixtures/retail_shadow_generate_world_class0.vp`, with SHA256
`1bb03f8703d3a9f89df087333999f960684ff3e7b9a4f045d1787d2f2e74d6dd`.
It was extracted from the authored shadow-generation vertex asset; it is not
an executed class0 program in the retained capture. The controlled cases use
the independently captured generation7758 bank, explicit world positions and
two decoded UVs, with production c172 identity. The latter is the documented
decoded-world-UV contract, rather than the compressed model UV c172 retained
on generation7758's actual class1 draw.

The16 controlled generation cases combine four host extents, two UVs and two
poison normals. All448 active GPU output words match execution of the authored
payload by the CPU interpreter exactly. Normals leave every active output
unchanged, while changing UVs changes oT0 and preserves position. This checks
the generation input seam against the original payload's arithmetic. It does
not claim a new actual source generation-class0 GPU reference. Executed
generation classes1/2/4/5 and the actual target-image proof remain the separate
shadow fixture coverage.

The extension passed the two normal CTests and separate ASAN/UBSAN CPU/GPU
runs. CPU leak detection remains enabled; only the known external Vulkan
driver leak boundary disables GPU leak detection. Loader logs confirm the
Khronos validation layer was loaded, with synchronization validation enabled
and no validation errors. Its source, fixture, executable, both SPV hashes and
logs are retained in
`analysis/multiplayer-shading/source-vertex-bank-production-provenance.json`.
That report freezes the earlier phase-fallback implementation. The preferred
typed-loader revision retains the same source inputs/expected outputs and is
recorded in `source-vertex-bank-typed-provenance.json`, including the actual
packed declaration service, shared production input-loader hash and new SPVs.
Both preferred-loader GPU runs retain the same measured output bounds above.
The layer reports a settings deprecation warning because CTest supplies both
the old and new synchronization-validation settings; it reports no Vulkan or
synchronization validation errors. CPU leak checks remain enabled, and the
ASAN GPU run disables only the separately documented external driver leak check.
