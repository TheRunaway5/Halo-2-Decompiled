# Original sound-cache requests and real file completion

`source_sound_cache_request` implements the complete `21A960` CPU owner,
including `21AB20`, page-window allocation `13EAE0`, its choice/deletion
helpers, and the genuinely constructed sound-cache busy/delete callbacks.
It requires actual retained cache backing and a mandatory complete async-read
owner. It never sets the completion byte in place of a worker or invents a
successful wait, read, admission, voice, or original thread constructor.

The independent checkpoint is
`analysis/multiplayer/integration/sound-cache-request-native/final-manifest.json`.
This work edits only the new header/source/test/tools/document. The earlier
SoundCreate, cache startup, async constructor/worker, provider, release and
other chats' files remain immutable. No CMake/runtime/launcher change is made.

## Actual recorded composition

The oracle independently reexecutes the immutable SoundCreate preparation and
its three ready/reload/empty-reload requests. It captures the actual untouched
`127750` frame at `21A960`, including whole original memory and CPU context.
Those requests are the previously rejected original FP raw buffers with their
declared nonpositional association. This is explicit raw-ABI composition,
not a newly admitted `128380` packet or a live local-player/world binding.

For each frame, unchanged `1221B0` runs on a separate stack while the original
cache frame is retained. Named native XAPI adaptations create two actual
recursive mutexes and a real bounded semaphore, and the original constructor
stores their returned aliases. It stops at the absent worker/TLS/lifetime
owner `2D8606`; no thread result is returned. The constructor has written the
whole 150×64 node bank, heads and actual worker-storage descriptor. This is
a constructor-prefix adaptation, not original Xbox thread initialization.

The original cache frame is then restored without replacing queue fields.
Actual source-created physical-buffer/capacity words select the raw backing
extent. A new actual anonymous zero-filled host mapping owns that storage;
no source pointer, limit, page index or readiness is changed. The original
cache-only freeze did not retain this physical data span because it stopped
before any I/O. That absence is not treated as an existing initialized buffer.

The used shared-file bank is an explicit alias of a real read-only owned
`shared.map` stream. Original file-open/handle production is not claimed.
Only that actually used bank is bound; a current-map handle or cache index is
not synthesized. Unchanged queue CPU owners run with real exclusion and
notification, while unchanged `122360` runs synchronously on the calling host
thread. Each wait must acquire an actual permit/exclusion before source
post-wait stores. The next empty semaphore stops before supplying a wait result.
Consumed file-seek/byte outputs come from actual I/O. Unconsumed wait, release
and ReadFile EAX values are retained rather than invented BOOL/NTSTATUS values.

The original cache request publishes a read and returns **1 while completion
is still zero**. The actual original worker/file callback then reads the bytes
and writes done=1 itself. Original subsequent flags 0, 4 and 5 return 2, 6 and
6. All queue/cache/source/tag/request/physical buffers are retained before and
after all six phases; no selected source field is assigned to make this pass.

## Native contract and source order

`SoundCacheRequestState` carries the genuine entry pool, page allocator and
physical buffer roots. The existing `SoundCacheStartupConstants` carries only
the selected executable's delete/busy callback identities. These identities
are compared before the corresponding CPU callback; they are not supplied
successful callback outputs. Null callback branches remain the source branches.
Raw memory is bounded, retained, mutable, and required on every access.

`SoundCacheRequestServices::async_read` takes the exact
`SourceBitmapReadRequest`: encoded location, rounded byte size, source physical
buffer alias, optional byte-count pointer, completion-byte address, category5,
priority4. It can directly compose the frozen
`submit_source_animation_async_read` with actual file-bank tokens and real
worker services. Publication has to return through its owning CPU/service
path; a missing provider throws after the original preceding cache stores.
The source ignores its job return, so this interface deliberately returns void.

The original page allocator uses 256 local candidate windows, authored
page-shift/limits, source timestamps, busy/delete callbacks, ordered salted
pool records and source list links. Page and entry consumers retain the
original literal 24/16-byte addressing where those original instructions do;
pool primitives independently consume their actual header stride. Source
signed comparisons and 32-bit wrapping products are preserved.

`21AB20` stores the chunk's actual allocated handle and cache-entry owner/chunk
pointers before requesting the real read. It rounds the lower 30 size bits to
512 bytes for I/O. It does not set done. `21A960` refreshes the allocator stamp,
observes done, writes the first-use byte only when done is actually nonzero,
and increments its byte pin count only for flag4. Flag1 repeatedly calls the
required scheduling provider until the actual completion changes; no timeout
or ready shortcut is introduced. Result bits are pending1, ready2 and pin4.
A pending cache result is not a returned voice or source admission.

The native test composes the frozen constructor and worker modules, actual
`NativeSynchronization`, actual `NativeSoundStorage` and actual
`SourceAsyncOwnedFiles`. It compares every original interleaved CPU store and
consumed native service request, all final bytes and actual cache returns.
No fixture allocation callback supplies the backing, wait or file outcome.

## Limits and next live owners

The measured three requests start from genuine cold constructed cache state;
the eviction/ranking/full-pool/debug branches are complete static translations
but are not claimed to have executed in this three-request suite. Blocking
flag1 is measured after actual completion, not during a racing background read.
The original callback can terminate on failed/short I/O too; done is terminal
callback completion and is not universally a full-read success indicator.
These positive reads are independently verified full actual payloads.

Root/another agent owns the real native worker-thread/cancellable-wait lifetime
composition. This checkpoint does not fabricate its original constructor or
claim retail Xbox TLS/SEH execution. The old source cache clock is owned by
`21A920` and by the tail of `127290`; their aging/reset lifecycle is not replaced
with a native frame count here. Cache data-alias/temporary-use owner `21AA60`,
cache drain/teardown `21A800`, source admission/local association, completed
map/device/routing and downstream voice ownership remain separate dependencies.
The three requests are owned Lockout samples, not all-map runtime coverage.
This cache fixture executes producer/worker/consumer phases serially. Ordinary
mutable spans do not establish a safe concurrent C++ done-byte poll. A live
background worker must provide real synchronization/atomic visibility and
retained buffer lifetime; the separate actual-thread fixture only inspects raw
bytes after stop/join and cannot be cited as concurrent polling proof.
The real SDL backend is not yet connected by this module.
