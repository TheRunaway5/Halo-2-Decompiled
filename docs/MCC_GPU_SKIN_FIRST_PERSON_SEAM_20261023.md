## Finding and minimum boundary

Ordinary first-person arms and guns still deform on the CPU. The source-owned path already supplies final WORLD nodes: `multiplayer_runtime.cpp:5898–5927` prepares the original models and samples the owner/render-model/mode interpolation history, then `:6035` skins the gun and `:6041` skins primary arms. Keep that preparation, history, clip selection and source callbacks on their present CPU owner. Replace only those final deformation boundaries with an admitted `model_skin_world_pose` result; this helper performs the same palette construction/copy and falls back through the existing CPU kernel (`src/rendering/models/model_pose.cpp:291–319`). The looking-down mode0 body at runtime `:5933–5948` is a separate WORLD submission, outside this foreground change.

The smallest renderer interface is a new trailing `ModelView::deferred_foreground_skins` span, parallel to `foreground`, backed by one owned packet vector per view through `Renderer::draw`. Register `skin_plan.add_bank(view.foreground, view.deferred_foreground_skins)` beside the existing WORLD/object banks (`src/rendering/renderer/renderer.cpp:4204–4210`). Foreground already enters the same ordered grouping/upload path at `:4583–4584`; `FrameModelSkinPlan` maps its actual appended runs, disables byte dedup for GPU-containing packs and preserves independent destinations (`:4330–4356`; `src/rendering/renderer/frame_model_skin_plan.hpp:75–175`). No separate foreground GPU buffer or queue is necessary.

**A post-skin identity-placement mode is also necessary.** Both first-person append paths run `place_vertices(..., Transform{})` after shader selection (`runtime:6107–6120`). Its body at `:239–250` performs three basis MULs and left-associated ADDs for every position/normal/tangent/binormal, plus position scale MUL and translation ADD. This can change signed zero. Current `shaders/model_skin.comp:14–51` only executes the skin graph. Moving placement to the local records before skinning, or omitting it, has no established equivalence. Carry an explicit post-placement mode from immutable geometry through each GPU destination record; run the exact separately rounded identity graph after deformation. Keep it out of unrelated WORLD records. The kernel's current all-zero-weight early return (`:19–20`) must skip only skinning in this mode: original append placement still runs for those vertices.

For admitted finite normal-or-zero skin results, identity MUL/ADD cannot create a new magnitude, underflow, overflow or inexact result. Signed-zero output remains observable and must be tested, including negative coordinates, all-zero influences and mixed signed zeros. Existing host-effect/numeric qualification must remain; this source argument is not a compiled SPIR-V proof. Inspect the new shader's explicit operations/NoContraction and verify complete readbacks rather than assuming a constant identity matrix survives compilation as intended.

## Independent post-placement float/effect review

The following is a proposed contract, not an executed test result. The existing integer-only arithmetic admission in `include/halo2/model_skin_gpu_admission.hpp:35–95` proves each evaluated skin result normal-or-zero and finite, with an upper magnitude below `2^44`. It checks all 12 local attribute words before the all-zero-weight early continue. Therefore that unchanged-vertex case also has normal-or-zero attributes. No additional lower numeric bound is needed for identity placement.

For one original attribute `u`, reproduce this scalar graph independently for each axis `r`:

```text
a = basis0[r] * u.x       // positive identity constants, 1 or 0
b = basis1[r] * u.y
c = basis2[r] * u.z
ab = a + b
rotated[r] = ab + c
position only: scaled[r] = rotated[r] * 1
position only: result[r] = +0 + scaled[r]
```

All MULs have exact normal-or-zero results: multiplication by one retains the operand, multiplication by positive zero produces an exactly signed zero. Each ADD has at most one nonzero operand, so its nonzero magnitude is unchanged and exactly representable. There is no denormal operand/result, invalid operation, division, overflow, underflow or inexact rounding. DAZ/FTZ settings cannot affect this graph. Thus **the identity graph itself requires no new SSE sticky bits, and skipping its CPU execution must neither set nor clear flags**. Skin elimination still separately requires the current host check at its original kernel boundary: all SSE exceptions masked, round-nearest-even and precision sticky already set (`model_skin_gpu_host_effects_admitted`, same header `:27–33`). Preserve existing x87/errno state; the direct identity arithmetic has no library calls. Confirm the linked ordinary-x64 identity closure uses SSE rather than x87 before promoting this source-level result. Intel's [SDM Volume1, chapter11](https://cdrdv2-public.intel.com/843827/253665-sdm-vol-1-dec-24.pdf) defines the independent SIMD exception flags/masks, DAZ/FTZ and rounding state; the no-new-effect conclusion above follows from this exact restricted graph.

For GPU outputs, require explicit float32 RTE and signed-zero preservation, plus `NoContraction` on **all** contributing MUL/ADD results. Do not use an opaque `dot` or matrix operation, a normalization, reassociation, `NSZ`, or a `FPFastMath` override. GLSL `precise` needs inspection in the emitted SPIR-V; the [Vulkan SPIR-V environment, Evaluation of Expressions and Correctly Rounded](https://docs.vulkan.org/spec/latest/appendices/spirvenv.html#spirvenv-precision) explains why signed-zero preservation alone does not forbid rearrangement. A legal simplification that is genuinely bit equivalent is harmless, but the initial diagnostic should retain bounded disassembly evidence for the new graph. Current RTE/SZ property qualification remains sufficient; no DenormPreserve capability is added.

Keep registered local position/normal/tangent/binormal unchanged until compute, including their zero signs; apply only selected materials/source metadata on the CPU.
- Mode0 and post-placement mode must remain independent per record. Validate the mode on the host, copy it explicitly into the GPU word stream and include it in geometry identity; reject unknown modes and do not repurpose bone/palette extents. Update the current host record width/limit arithmetic and shader record stride together (`src/rendering/models/model_skin_gpu.cpp:94–136`). Current renderer readback oracle at `renderer.cpp:5990–6010` must apply the same post-mode CPU graph after its reference skin.
- **Rounding can change between the two original boundaries.** The effect observer at `runtime:6095`, animation observer at `:6071`, or a selected shield-layer observer at `:4353` is arbitrary user code. Initial source-FP GPU admission should exclude these observers, alongside the existing diagnostic/reference gates. The audited shader-selection functions perform arithmetic but contain no fenv setter (`source_model_shader.cpp`; `source_shader_lod.cpp`). If the original identity boundary is reached with a different rounding mode, RTE compute is not proved equivalent.
